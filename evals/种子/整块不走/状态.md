# 种子「整块不走」的状态

按出厂预设图「破产」整份起手，再摆出：

| 模块 | 节点 | 状态 |
| --- | --- | --- |
| 接受指定与报备 | 管理人承诺书及团队人员 | 已确认 |
| 自行和解 | 和解协议 | 不适用 |
| 自行和解 | 裁定认可和解协议并终结破产程序的申请 | 不适用 |

模块级不适用由引擎给「自行和解」的两个节点各记一条不适用（原话「本案不走和解，自行和解那一块整个不办」），图仍是唯一台账，没有模块级标记；视图把该模块的状态算成不适用，前方里不再有它们。前方第一个仍是「管理人工作计划」，路由该落在问 3，并且**不再提**那两个和解节点。

供 skill "ask-loo0ng" 的用例「整块不走」。

两份视图是最后一次写图后重算的。回放末尾把三份图文件的 sha256 写进工作区根的 `.基线.json`（`evals/共用/基线.py`），路由用例据此断言跑完一个字节都没变。

不含隐私检查器五类正则能命中的值：当事人与法院一律写「甲」「乙」「丙」。
