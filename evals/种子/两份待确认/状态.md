# 种子「两份待确认」的状态

按出厂预设图「破产」**整份起手**（12 模块 72 节点全部在图里），再摆出三个节点：

| 节点 | 状态 | 高亮 | 条目 |
| --- | --- | --- | --- |
| 管理人承诺书及团队人员 | 已确认 | 已清 | 一条生成（agent）、一条确认（律师，原话「承诺书这份就这样，可以了」） |
| 管理人印章备案报告 | 已生成 | **已清**（律师在 Word 里把黄都填掉了） | 一条生成，没拍板 |
| 管理人银行账户备案报告 | 已生成 | **未清**（文书里还有一处黄） | 一条生成，没拍板 |
| 其余 69 个 | 未生成 | 无文书 | 无 |

两份同时待确认，图里的顺序是印章备案在前、银行账户备案在后。印章备案在图上带时限句（自收到《刻制管理人公章函》之日起 3 日内……），银行账户备案没有。路由的待拍板行只该点印章备案（已生成、未确认、高亮已清），银行账户备案那份还有黄等律师动手。

前方第一个是同模块的「管理人工作计划」，它没有时限；排在它后面的「内部管理制度备案报告」「刻制管理人公章的申请」倒是有时限：路由若因时限改序就会挑错，这一条正是「不因时限改序」的判据。

供 skill "ask-loo0ng" 的用例「两份同时待确认」「路由第一行」与 skill "doit" 的用例「跨对话确认」。

两份视图是最后一次写图后重算的。回放末尾把 `图.json`、`图视图.md`、`图视图.json` 三份的 sha256 写进工作区根的 `.基线.json`（`evals/共用/基线.py`），路由用例据此断言跑完一个字节都没变；点开头的文件按惯例不算工作区产物。

不含隐私检查器五类正则能命中的值：当事人与法院一律写「甲」「乙」「丙」。
