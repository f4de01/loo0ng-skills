# 种子「活图多一件」的状态

律师本机的**活图**比包内的出厂种子多一件（ADR-0019、#92）。工作区是正常的六格，`AGENTS.md` 的「领域目录」那一行指着活图：

```
<工作区>/              案件工作区（六格、图.json 与两份视图、AGENTS.md 指针块指着活图）
<活图家>/领域/破产/     活图，由 sketch.py home 从 skills/productivity/loo0ng-domain/assets/破产/ 这份出厂种子拷出
<工作区>/.基线.json     跑之前三份图文件的 sha256（路由只读，跑完一个字节都不该变）
```

活图家取环境变量 `LOO0NG_HOME`：跑器每次运行另建一个临时的交给两侧 harness（`scripts/skill-eval.py`，ADR-0015 只生不存）。没设这个变量时（`--materialize`、手跑）回放自己把它指进工作区里的 `.活图家/`，**永远不碰律师真的 `~/.loo0ng/`**。

破产领域，空图起手，模块「申请确认债权」里的两件都办完了：

| 节点 | 来源 | 状态 |
| --- | --- | --- |
| 裁定确认无异议债权的申请 | 领域图带入 | 已确认 |
| 裁定补充确认债权的申请 | 领域图带入 | 已确认（确认最晚，上一完成就是它） |
| 裁定确认职工债权的申请 | **只在活图上**（id `n-queren-zhigong`，带一句时限） | 尚未进图 |

出厂种子里那个模块只有前两件，所以两条路给出两个不同的答案：

- **读活图**：那个模块还差第三件 → 命中问 3（顺着最近动过的这一块做完）→ 下一句是 `出一版 裁定确认职工债权的申请`。
- **读出厂种子**：那个模块一件不缺 → 问 3 落空、掉到问 4 → 答的是别的模块里的节点，用例红。

**活图那一改落在最后一次写案件图之后**，所以两份视图的「前方」是改之前算的，里面没有那一件（视图只在写案件图时重算，活图改了不会回头刷新它）。这一步是刻意的：不这样摆，模型光读 `图视图.md` 就能答对，这条用例就测不出它有没有真去按 `AGENTS.md` 里的路径打开领域图。律师的活图本来就会在别的案子里长出新节点、本案的视图不跟着变，这就是那个形状。断言里有一条专门守它：那个标题在工作区的三份图文件里一个字都找不到。

多出来的那一件按 ADR-0019 律师侧那条路进的活图（节点确认之后问一次归属，不给时限句），时限句 `自职工债权表公示之日起 15 日内提请法院裁定确认（活图，律师补）` 是律师后来自己在活图上补的（引擎 `set-time-limit --kind domain`）。它只在活图上有，出厂种子与两份视图里一个字都没有，所以「往下的路里原样附上它」这一条同时核了 #71 那条死顺序在活图上照样成立。

- 两个已确认的节点各有一个 `文书/<节点标题>/` 目录，一份合成的 `.md` 与同名 `-审查报告.md`，报告是五段固定的形状。
- 不含隐私检查器五类正则能命中的值：没有案号、没有手机号、没有身份证、没有统一社会信用代码、没有案件目录路径；当事人一律写「甲」「乙」「丙」。
