# 种子「回流」的状态

一个开发会话看得见的摊子（ADR-0012）：回流只在开发会话做，当前目录是本仓库、开发者一句话给出案件工作区的路径，写的是开发者本机的**活图**（ADR-0020）。跑器把 cwd 设在临时工作区，所以工作区根摆的不是六格，而是那个会话要用到的两样，外加它要写的那份活图：

```
<工作区>/
├── 案件/            案件工作区，先照种子「在办中」回放一遍，再加两个律师自加节点
└── .活图基线.json   回流之前的样子：案件图的 sha256、活图的绝对路径与逐文件 sha256、活图的模块数与节点数
<活图家>/领域/破产/   活图，由 sketch.py home 从包内 assets/破产/ 这份出厂种子整份拷出（22 件、约 540 KB）
```

活图而不是工作区根上摆一份领域图副本：真实那条路的第 1 步就是 `sketch.py home --name 破产` 取路径（`references/回流.md` 开发侧第 1 步），用例的提示词因此一个路径都不给，这一步得由模型自己走（#105）。活图家取环境变量 `LOO0NG_HOME`：跑器每次运行另建一个临时的交给两侧 harness（`scripts/skill-eval.py`，ADR-0015 只生不存）。没设这个变量时（`--materialize`、脚本层单测）回放自己把它指进工作区里的 `.活图家/`，**永远不碰开发者真的 `~/.loo0ng/`**。基线落成点开头文件，用例的「没往工作区乱写」断言按惯例忽略点开头的项。

断言拿 `.活图基线.json` 复核「回流只读案件图，案件图字节不变」「活图只多出一个节点」「包内出厂种子一个字节没动」（活图是种子的逐字副本，那条指纹直接拿来比种子），节点数从基线里读、不硬写：下一次入库让出厂种子长大时，这份种子跟着长，用例不用改。

`案件/` 这一层的状态见种子「在办中」的 `状态.md`（真实破产领域目录整份起手、六格、`管理人承诺书及团队人员` 已确认、`管理人印章备案报告` 已生成未确认、两条律师陈述）。那一层的 `AGENTS.md` 指针块仍指着包内出厂种子：本种子不改它，模型照它去写会撞上引擎那条无条件拒（拒绝消息里写着活图怎么取）。本种子在它之上加两个律师自加节点，都挂在领域图已有的模块「接管与调查」下：

| 节点 | 状态 | 是不是回流候选 |
| --- | --- | --- |
| 乙公司甲年乙月丙日厂区接管现场情况说明 | 已确认（一条生成、一条确认，原话「现场情况说明这份可以了，就这样定」） | 是 |
| 乙公司食堂承包合同解除请示 | 已生成（一条生成，没拍板） | 否，判据 (a) 要至少一版已确认 |

- 两个标题都带着本案的当事人与日期，去案件化才用得上：`乙公司`、`甲年乙月丙日` 都要去掉；`厂区` 去不去归模型判（实测两侧都判成本案特有、一并去掉），用例的断言只认核心词「接管现场情况说明」加「当事人和日期不在标题里」。
- 两个节点各有一个 `文书/<节点标题>/` 目录，里面一份合成的 `.md` 与同名 `-审查报告.md`，报告都是五段固定的形状。
- 活图里已有的 72 个节点都在案件图里（整份起手），按 id 减法它们都不是候选；模块「接管与调查」也已在活图里，回流时按活图的标题指认。
- `python skills/productivity/loo0ng-domain/scripts/sketch.py from-case --case 案件/图.json --domain <活图>` 恰好提出一个候选，`tests/loo0ng-domain/test_seeds.py` 机械复核这一条。
- `案件/` 那一层由跑器自己的 `replay_seed` 摊出来（`scripts/skill-eval.py`），元文件名单只有那一份。
- 不含隐私检查器五类正则能命中的值：没有案号、没有手机号、没有身份证、没有统一社会信用代码、没有案件目录路径；当事人与法院一律写「甲」「乙」「丙」。

供用例「回流」：开发者一句话给案件工作区的路径、不给领域图的路径，断言回显清单与拍板后的活图。
