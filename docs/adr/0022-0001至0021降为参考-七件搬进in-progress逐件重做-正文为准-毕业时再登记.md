# 0001 至 0021 降为参考，七件 skill 搬进 in-progress 逐件重做，与正文冲突时以正文为准，毕业时再登记

3.0 从 9 月 4 日开工到 9 月 13 日发出 0.4.0，写了 21 份 ADR，其中 16 份写在 9 月 4 日与 5 日两天内；律师第一次装上是 9 月 9 日。也就是四分之三的裁定先于任何真实使用。`docs/3.0-handoff.md` §2.4 给 3.0 定的元规则是「一条规则只在真实使用里被违反过一次之后才写进 AGENTS.md」，实际没有做到；对 2.0 的诊断「规则集已经成为修改的阻力而不是助力」在 3.0 上第二次成立。

阻力的形状具体是：工程走向加固边界与添加门禁，由此长出随包分发的脚本 4,174 行、配套测试 10,428 行，测试是脚本的两倍半；五份 `test_isolation.py` 断言的是「某 skill 正文不许提某词」，与功能无关；合入门槛要求脚本层单测、两侧 eval、三条校验全绿，eval 用例是历次抖动的封条，剪一句正文就红一片；新的想法在 grilling 里被既有 ADR 否掉。律师 0.1.0 试用带回的三件需求（出一版慢、可视化、泛化）在 0.3.0 与 0.4.0 两版里一张票都没开，两版全花在回归上游与去前缀上。

我们决定：

- **0001 至 0021 降为参考。** 文件不删、不改，`status` 字段照旧；读法变了：它们记的是「当时为什么这么定」，不再是「现在必须这么做」。与某件 skill 正文冲突时，正文对、ADR 错。引用其中任何一条不构成反对一个改动的理由；要复活某条裁定，在改到那件 skill 时把理由重写进它的正文，或另写一份新 ADR。`docs/agents/domain.md`「Flag ADR conflicts」那条对 0001 至 0021 不再适用。

- **三样不在封存之列。** 硬边界两条（案件材料永不入仓库、办案会话对仓库只读）是数据安全，不是设计，隐私钩子跟着留；平台事实（`docs/agents/skills.md`「命名与编码」：python 3.9、BOM、description 引号、`display_name` 等于 `name`、安装源须公开）是撞过的坑，不是谁的裁定；结构不变量 1 至 5 是上游 Matt 的打包形状，正是这一轮要照的东西。`CONTEXT.md` 留作词汇表，词条的 Avoid 列表随各件改造时清理。

- **七件 skill 全部搬进 `skills/in-progress/`，按上游对这个桶的定义处理。** 不进 `.claude-plugin/plugin.json`、不进根 `README.md`、没有 `docs/<bucket>/<name>.md` 页；桶 `README.md` 逐件列出。`plugin.json` 的 `skills` 数组在改造期间为空：Claude Code 插件路线装到的是空包，`claude plugin update` 不会把半成品推到任何人的机器上；要试用走 skills.sh 单件装（`npx skills@latest add f4de01/loo0ng-skills --skill=<name>`），律师那台 mac 走的本来就是这条路。桶 README 原先那句「草稿放分支不放目录」对这一轮不适用：这一轮改的是全部七件、跨多次发布，分支装不下。

- **逐件改造，逐件毕业。** 每件按同一张单子：先写下律师在 0.1.0 里对它实际做了什么、卡在哪；列它调的每个脚本，问「模型不用它能不能做对」，能就删脚本连同它的 `tests/<名>/`，留下的只应是守不可逆的那几个；正文按 `writing-for-agents` 重写成步骤加完成判据加拍板点，命令行不进正文；被旧 ADR 否掉的想法在改到那件时直接试。改完一件就从 `in-progress/` 搬回 `engineering/` 或 `productivity/`，走 `docs/agents/skills.md` 的登记步骤，docs 页那时重写。顺序从 `doit` 起（最厚、最慢、律师碰得最多，它决定三件参考 skill 还需要提供什么），`ask-loo0ng` 最后（路由是二手来源，入口定了再画一次）。

- **合入门槛在改造期按件收。** `docs/agents/skills.md`「合入门槛 = 脚本层全绿 + 两侧 eval 全绿 + 三条校验」只对已毕业的件成立；`in-progress/` 里的件提交前只跑 `check-skill.sh`、`check-wiring.sh` 与 `claude plugin validate`（`AGENTS.md` 结构不变量 6 本来就只列这三条）。一件毕业时，它的单测与 eval 用例随它的脚本与正文一起重定：脚本删了测试就删，正文重写了封条就作废，留下的那些才重新成为它的门槛。

## 考虑过的方案

- **删掉 21 份 ADR**：丢的是「当时为什么这么定」，2.0 那次整体换掉的教训是回头查一条理由要翻 git 历史。
- **逐条附注推翻**：21 份逐条写附注，附注本身就是沉积；且这一轮的问题不是哪一条错了，是整层的地位错了。
- **不搬桶，原地改**：`engineering/` 与 `productivity/` 里的件进插件清单，改到一半 push 到 `main` 就会经 `claude plugin update` 推到装了插件的机器上；`in-progress/` 正是上游给「故意公开、随时可能改或消失」定的位置。
- **只封存 ADR、机械层照旧**：挡改动的从来不是 ADR 文字，是它们长出来的测试与门槛。封文字不拆机械层，第一件 skill 改到一半就会撞上同一堵墙。

## 后果

- 七件从 `skills/engineering/` 与 `skills/productivity/` 搬进 `skills/in-progress/`；两个 promoted 桶暂时只有 README。`plugin.json` 的 `skills` 为空数组。根 `README.md` 的 Skill 清单段改为指向桶 README；七页 `docs/engineering/*.md` 与 `docs/productivity/to-docx.md` 删除，v0.4.0 的 tag 上还在，毕业时重写。
- 仓库里写死 `skills/engineering/…` 与 `skills/productivity/…` 的地方（`scripts/privacy-check.py` 的领域图前缀、eval 回放与断言、`tests/` 下各处、`references/回流.md`、`graph` 正文、`docs/交付/现场清单.md`、`docs/agents/skills.md`）改指 `skills/in-progress/…`；毕业时再改回。`LICENSE` 与 `AGENTS.md` 结构不变量 5 改为不带桶名的写法。
- 隐私钩子守的路径前缀跟着搬（`scripts/privacy-check.py`），硬边界 1 的机械守门在改造期不断档。
- 开发机 Claude Code 侧的插件路线在改造期装不到七件，改用 `scripts/link-skills.ps1` 挂 junction（它照上游把 `in-progress/` 一并挂上）；`skill-eval.py --harness claude` 要带 `--claude-plugin ""` 退回裸名。
- 一张 minor 的 changeset，正文以 **Breaking:** 开头：装了插件的机器更新后是空包，改造期请走 skills.sh 或留在 0.4.0。
- ADR-0009 附注「草稿放分支不放目录」与 ADR-0015「合入门槛」两处按本文读。
