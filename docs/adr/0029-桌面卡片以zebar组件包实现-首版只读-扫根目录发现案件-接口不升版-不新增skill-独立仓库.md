# 桌面卡片以 Zebar 组件包实现，首版只读，扫根目录发现案件，接口不升版，不新增 skill，独立仓库

0.3.0 地图的 B 股把可视化拆成四题：宿主与呈现形态、插件读什么、接通的 skill 存不存在、本体。本票依一份仓库外的选型讨论稿（《独立桌面组件选型提案》，自述"讨论稿，未实施"，其中的历史仓库事实未经核验）把前三题一次裁掉，并给第四题定形。

本会话核实过的事实：`图视图.json` 已实现到格式版本 2，字段齐，引擎 `graph.py` 是唯一写者，状态在引擎里算一次；Zebar 的 macOS 侧有签名 dmg 与 brew cask，菜单栏停靠、多显示器定位、`top_most` z-order 都在活跃维护（律师主力机是 mac + WPS）；Zebar 的组件包就是 `~/.glzr/zebar/<包名>/` 下一个带 `zpack.json` 的目录，一个包可含多个组件，且提供 shell 执行 API，所以读本机文件不必 fork 上游。讨论稿第 3、5 节仍以自建 Tauri 工程为首选，与第 1、6 节的 Zebar 路线没有收口，本票收口。开发者在本会话逐轮确认下列各条，状态据此为 accepted。

我们决定：

- **宿主是原版 Zebar，我们交付的只是一个自有组件包。** 无边框窗口、拖动、置顶、多显示器、托盘与菜单栏常驻、安装包签名、自动更新，这些是上游已解决且在维护的；我们写的是 HTML/JS 加一个 `zpack.json`，靠宿主的 shell 执行 API 读工作区里的文件。不 fork 上游，不为退出行为维护定制分支。
- **首版只读，一个字节都不写；提醒整块后移。** 进度所需的一切 `图视图.json` 里已经有；提醒需要四样全新的东西（图里没有的可调度时间戳、本机数据库、单实例调度器、agent 写入通道），一样都还没裁。只读还有一条结构上的好处：它不新开任何写入面，天然不触硬边界。
- **案件由扫根目录发现。** 律师在一份设置文件里填一到几个根目录，卡片扫下面一层，**目录里有 `图视图.json` 就算一个案件**。一次设置，之后新起手的案件自动出现。这规定的是卡片自己的设置，不是工作区之上的摆法，ADR-0007「工作区之上怎么摆不作规定」不受影响。
- **只读一个文件。** 桌面卡片只许读每个工作区里的 `图视图.json`，`材料/`、`文书/`、`待归档/`、`参考/` 一律不读、不列、不显示。它在律师本机列出案件目录是本职，不需要任何豁免条款；代价就是这一条，而这一条可被检查：卡片的代码里只该出现一个工作区文件名。
- **不新增 skill，也不并进 `ask-loo0ng`。** ADR-0011 关掉「图存档」槽时给的理由是"它没有律师一句话就该被模型够到的场景"。这条理由今天不但成立，而且被宿主选型加强了：卡片常驻桌面，律师要看图是转头看一眼，不是打一句话；他真要说的那些话（改图、办节点、归档）各有归属。卡片与 agent 之间没有调用关系，引擎写、卡片读，两边不认识对方，唯一的接口是那个文件加 `格式版本`。首版因此不动结构不变量 2、3，不走登记八步。
- **接口原样，不加字段不升版；卡片只做聚合，不做判定。** ADR-0011 禁的是第二份状态推算规则，不是禁算术。把引擎给的状态计数、排序、取 `前方` 的第一个，输入全是引擎的结论，走样不了；任何需要看条目才能得出的结论，必须由引擎先算好再交给卡片。遇到不认识的 `格式版本` 照 ADR-0011 明确报错，不猜、不降级。
- **接口先于呈现。** 本票只定卡片消费什么、不消费什么；显示哪几格、长什么样、点击展开成什么，由原型与后续设计回答。桌面可见性记为已知取舍：派生视图里没有案号与当事人（ADR-0003），但工作区目录名是律师自己取的，可能含当事人名而常驻在桌面上；打码开关后移，不进首版。
- **住独立的 public 仓库 `loo0ng-widget`。** 本仓库分发的是 skill，桌面卡片不是 skill，进来只会把结构不变量 1 那五个登记点逼出例外。public 是硬要求而非偏好：ADR-0026 记着现场事实，私有仓库下律师 mac 上三次装不上，转 public 才成。安装形状照 ADR-0026，一条命令把包拷进 `~/.glzr/zebar/loo0ng/`。
- **原型即新仓库的第一个分支。** 不回本仓库开 `prototype/` 分支；原型答完题不删，留在那个仓库里当 primary source，实现在它上面长。验三项，全用 `evals/种子/` 下的 `回放.py` 造出来的工作区喂，不碰真实案件：装得上并出一张可拖动的卡片；扫根目录能认出两个以上案件且 `图视图.json` 变了卡片跟着变（"轮询还是文件监听"在这一步量出来，不先猜）；关掉一张卡片不影响宿主里其他组件与其他案件的卡片。
- **在 Windows 上验收，通过即交一版，律师 mac 试用并进交付票。** Zebar 的双平台兼容由上游负责，我们验的是自己的组件包。
- **术语分家。** 「桌面卡片」取代「可视化插件」；「插件」一词今后只指 Claude Code 插件。

## 2026-09-16 附注：原型实测改两处

原型（新仓库 `prototype/卡片` 分支）跑通之后，有两条本票原先写岔或没写到的，按实测改：

- **根目录填在哪。** 原文写的是"律师在组件设置里填"。宿主没有给组件自定义设置的格子，
  `zpack.json` 的字段是固定的一套。所以根目录落在包外的一份设置文件里：`~/.loo0ng/卡片设置.json`，
  与个人预设图同一个家（ADR-0023 已经开了这个口）。这不动本票其余任何一条：卡片仍然只读，
  仍然只读每个工作区的 `图视图.json` 一个文件。
- **卡片出现在任务栏与程序坞里。** 宿主的 ACL 不放行给窗口装系统窗框，也不放行 Tauri 自己的拖动
  与"取消最小化"。放行的是挪位置、最小化、关闭。于是拖动由卡片自己按位移实现，最小化用系统的、
  **还原只能交给系统**，因此窗口必须出现在任务栏/程序坞里。这是"最小化与关闭按各平台常规逻辑"
  这条要求能落到的形态，也意味着这张卡片不是一个藏在桌面层里的挂件。窗口控件的位置与样子仍归
  呈现那一轮，本附注只定"进任务栏"这一条。

## 考虑过的方案

- **自建 Tauri 2 独立工程**（讨论稿第 3、5 节的首选，含 `crates/core`、`crates/cli`、双平台 CI 与签名）：首版没有一样东西非它不可，而它要我们自己扛的恰恰是最贵、最容易在律师那台 mac 上翻车的那一层。保留为后路，触发条件写明：提醒需要一个不依赖 Zebar 进程的后台调度器时重新评估。
- **首版同时做节点可视化与提醒**（讨论稿第 1 节的并列）：提醒的四样前置一样都没裁，并且它要新开写入面，会把一个天然安全的只读件变成要单独立案的东西。
- **手工维护一份案件清单 `~/.loo0ng/案件.json`**：比扫根目录多一份要维护的状态，新案件起手后还得记得去补一行。
- **由 `setup-case` 起手时自动登记一行**：要改 skill、要新开写入面，换来的只是省律师一次设置。格式若将来真需要，再单开一票。
- **扫父目录以外再发明一套案件登记约定**：等于把 ADR-0007 有意不回答的问题偷偷回答了。
- **引擎补聚合字段、格式版本升到 3**：为一个还没定形的呈现去动接口。
- **首版连聚合都不做、卡片只摆逐节点状态**：卡片退化成一张长列表，"哪个案子该动了"这件最该横着比的事反而看不出来。
- **新增一件「看图」skill，或把它并进 `ask-loo0ng`**：需要正面推翻 ADR-0011 那句话，而那句话今天更成立。
- **组件包放进本仓库**（或先放进来、能跑了再拆）：见上，五个登记点一个都不该挂。
- **先在本仓库开 `prototype/` 分支**：原型的产物直接就是那个新仓库的起点，搬一次没有收益。
- **写一条"豁免列出案件目录"的条款**：豁免是一句话，谁也检查不了；换成"只读 `图视图.json` 一个文件"这条配套限制，可被检查。

## 后果

- `CONTEXT.md`：「可视化插件」词条改名为「桌面卡片」并整条改写（宿主、只读、扫根目录、只读一个文件、只聚合不判定）；「派生视图」与 Relationships 里提到它的两处随之改口径；Flagged ambiguities 新增一条记「插件」一词的分家。
- `docs/0.3.0-wayfinder起手.md` 的 B 股：#4、#5、#6 由本 ADR 答掉，#7 变形为新仓库的第一个分支。该文件另有一处陈旧事实顺带更正：它写的喂料目录 `evals/领域/菜园/` 并不存在。合成小领域「菜园」（4 模块 9 节点）仍在，但它住在 `evals/共用/回放助手.py` 里由 `造菜园()` 现造，不是一个目录；skill 层端到端的喂料是 `evals/种子/` 下 16 个种子各自的 `回放.py`，用 `scripts/skill-eval.py --materialize <种子名>` 现生一个工作区（ADR-0015 定 skill 层端到端用真实领域）。
- 本仓库这一轮零代码改动：没有新 skill，没有登记，没有 relink，没有 changeset。
- `GRAPH-FORMAT.md` 事实上成了桌面卡片的公开接口，但它在 skill 包里，受结构不变量 7（随包自足）约束，**不许**出现 `loo0ng-widget` 的名字或链接。接口与消费方的关系只记在本 ADR 与 `CONTEXT.md`；`格式版本` 升级时通知桌面卡片，是本 ADR 记下的义务，不是 skill 正文里的一句话。
- 旧文里的「可视化插件」不回头改：ADR-0022 已把 0001 至 0021 降为参考，与现行正文冲突时以正文为准。
- 提醒那一版重开时要正面回答的三件：可调度时间戳从哪来（图里没有，`时限` 是自由文本句）；写入通道归谁（那时才重开"接通的 skill 存不存在"）；调度器是否还能寄居在 Zebar 进程里（答否即触发 Tauri 后路）。
