# 包外的家与 agent 沙箱冲突，起手对卡片设置由写入维护降为只读校验

ADR-0030 把"新案件自动出现在桌面卡片上"这件事落成一段写入：`setup-case` 收尾把新工作区的上级目录加进 `~/.loo0ng/卡片设置.json` 的 `根目录` 列表，并规定「读不出、形状不对、写不进都只回一句，起手照样算完成」。

2026-09-19 律师机上第一次真跑，那句话出现了：**「桌面卡片设置因当前权限无法写入」**。代码路径对得上，是 `maintain_card_roots` 写临时文件再 `os.replace` 的那一支 `except OSError`。

同一天同一台机器上，装卡片的那个会话**成功创建了**这份文件。两件事放在一起看，暴露出一个比"写失败"更要紧的问题：装卡片那次，写是由 agent 自己发起的，被挡住时它向律师弹出批准请求，律师批了，于是写成了；而起手这次，写发生在 `python3 setup.py init` 这个**子进程**里，被挡住 → Python 抛 `OSError` → **脚本自己把它吞掉，换成一句友好提示** → 外层的 agent 从头到尾没看见任何失败，也就没机会弹那个批准框。

**ADR-0030 设计的那个优雅降级，把唯一能解决问题的机制一起屏蔽了。** 那条规则当初是为"那台机器没有卡片"写的，它同时吞掉了"挡了一下，问一句就能过"。

根因没有坐实，而且**有意不查**：判别它要在律师机上跑两次对照命令，律师不做终端操作，开发者本人不在那台机器前。两种可能（agent 沙箱只许写工作目录；那个目录的属主或权限不对）指向的结论是同一个，所以查不查不改变任何决定：**那份文件住在包外，起手不能依赖对它的写入成功。**

这条冲突不止一个出口。ADR-0023 把个人预设图安在 `~/.loo0ng/预设图/`，理由与 ADR-0030 相同（包外的家，不破硬边界 2）。本会话核查 `domain` 的 `preset.py` 发现：`cmd_save` 里建那个家的 `target.parent.mkdir(...)` 漏在 `try` **外面**，所以律师哪天说一句「把这个案子的图存成预设图叫 X」，他拿到的不是一句中文提示，是一串未捕获的 `PermissionError` traceback。ADR-0023 与 ADR-0030 都是在开发机（Windows，无沙箱）上论证的，**没有一个字考虑过律师那台机器上的 agent 跑在沙箱里**。

## 我们决定

- **起手对 `~/.loo0ng/卡片设置.json` 降为只读校验，本脚本从此不写它。** 读 `根目录` 列表，比对新工作区的上级目录：在里面就说一句卡片看得见，不在就说一句该把哪个目录加进哪个键。加根目录这个动作交还给律师和他的 agent，那条路上 agent 自己发起写入，挡住了会弹批准框。
- **ADR-0030 的核心决定就此反转，反转的理由记在这里：开发机没有沙箱，律师机有。** ADR-0030 想要的效果（律师不用记得去配）只保住一半：他偶尔要自己补一行。这是值得的，因为原来那一半是**假的**：写失败被吞成一句他看不懂也做不了的话，比一句"该怎么加"更坏。
- **文件不在、读不出、形状不对，一律整步跳过、回显里不提。** 原来对后两种各回一句，现在不回了：读不出的那份设置该由卡片自己去报（它有专门的设置错误一格），起手在这里多说一句，只是在一个跟它无关的地方制造噪音。文件不在仍然意味着"那台机器没有卡片"。
- **`--no-card` 保留，语义从"不维护"变成"不查"。**
- **这个只读判据与 ADR-0031 的位置闸是同一段代码。** `card_roots()` 一处读取，位置闸拿它判"当前目录是不是根目录本身"（拒绝），收尾拿它判"上级目录在不在列表里"（提醒）。一个判据同时解决两件事，而且它只读，不受本票所记的那堵墙影响。
- **`preset.py` 的 `mkdir` 挪进 `try`。** 无论根因是沙箱还是权限，一行 `mkdir` 漏在 `try` 外面导致 traceback 都是 bug。另存失败要落成那句已经写好的「另存没落成 X：…。案件图一字未动。」
- **硬边界 2 的射程不变，ADR-0023 的"包外的家"不推翻。** 个人预设图仍然住在 `~/.loo0ng/预设图/`：另存是律师主动说的一句话，那条路上写失败会冒泡成一句拒绝，他看得见、agent 也能据此去要批准。本票否的不是"写包外的家"，是"在一个收尾步骤里**静默地**写包外的家"。
- **`CONTEXT.md` 记一条 Flagged ambiguity：包外的家与 agent 沙箱的结构冲突。** 它今天只露了两个口子，以后凡是要写 `~/.loo0ng/` 的东西都会撞上，新写这类代码的人应当先看见这条。

## 考虑过的方案

- **保留写入，失败时让它冒泡成拒绝**：起手就会因为一件跟案件无关的事整件失败，而那台机器上可能根本没有卡片。代价与收益完全不成比例。
- **保留写入，失败时让 agent 去要批准**：脚本是子进程，它没有办法要求外层 agent 弹框；能做的只有把失败往上抛，那就回到上一条。
- **把卡片设置搬进工作区之内**（沙箱允许写的地方）：那份设置是**跨案件**的，一份一台机器；放进某一个案件的工作区里，语义就错了，而且卡片要先发现案件才能读到它，循环。
- **先查清根因再决定**：查不动（律师不做终端操作），而且两种根因的结论相同。为一个不改变决定的事实去挡一个方案，是把不确定性当借口。
- **连 `--no-card` 一起退场**：那一步现在只读、极便宜，但在完全没有卡片的机器上仍会多读一次文件；留着开关不要钱。
- **`maintain_card_roots` 整步退场，一句都不说**：律师就再也不会知道"这一案不会出现在卡片上"。只读校验的全部价值就在这句话上。
- **把个人预设图也搬出 `~/.loo0ng/`**：为一个还没爆的问题改一条已经稳定的约定，而另存那条路的失败本来就是可见的。

## 后果

- `skills/engineering/setup-case/scripts/setup.py`：`maintain_card_roots` 换成只读的 `check_card_roots`，新增 `card_roots()` 与 `norm()`；不再有临时文件、不再有 `os.replace`、不再有写入的 `except OSError`；文件头说明改写。
- `skills/engineering/setup-case/SKILL.md`：卡片那一段改口径，并明写模型不要自己去改那份设置；「与邻居的边界」里那一条跟着改。
- `skills/engineering/domain/scripts/preset.py`：`cmd_save` 的 `target.parent.mkdir` 与 `shutil.rmtree(staging)` 一并挪进 `try`。
- `tests/setup-case/test_setup.py`：`卡片根目录` 整个测试类按只读契约重写，8 条；其中两条专门守"一个字都不该动"与"不留 .tmp"。
- `CONTEXT.md`：「桌面卡片」词条改口径；Flagged ambiguities 新增"包外的家与 agent 沙箱"。
- ADR-0030 的「配置自动化落在起手的 CLI 收尾」与「接口义务机械化」两条中，前者由本票反转，后者（`check-release.sh` 比对格式版本）不受影响。
- 桌面卡片仓库那边有一条配套改动另走它自己的票：扫描把权限失败与路径失败分开报，权限那一支给出系统设置里该开哪个开关。本仓库不记那个仓库的名字。
