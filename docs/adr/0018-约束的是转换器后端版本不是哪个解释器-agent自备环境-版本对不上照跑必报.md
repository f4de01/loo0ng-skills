# 约束的是转换器的后端版本，不是哪个解释器：agent 自备环境，版本对不上照跑必报

ADR-0017 立了一条原则，但只用它管了渲染器：**缺 Word / WPS / 其他软件，不得阻断文书生成**。本 ADR 把同一条原则用到上游的一层，管解释器与转换器的后端。理由比那次更硬：没有渲染器只是少一层加信，没有能跑转换器的环境是整个工作台一步都走不动。

直接起因是律师 2026-09-08 的裁定：「各用户机环境各不相同，甚至有很多完全没有 python 环境，写死限定会导致无法正常运作。**agent 有能力自己完成初始化的配置。**」`loo0ng-to-docx` 的正文当时写死「两个都用系统的 `python`；`uv run python` 是另一套没有这些库的解释器，不用」。这句话在开发机上没问题，在**没配过 python 的律师机上就是「工作台永远出不了件」**。

**agent 自备环境已经成过一次。** 2026-09-08 在合成工作区里做 [#62](https://github.com/f4de01/lawyer-workbench-v3/issues/62) 的关票触发（Codex 侧，Full access），沙箱里 `python` 敲不动，agent 自己走完了 `uv python find` → `uv pip install --python <它> --target <临时目录>` → `PYTHONPATH` 指过去这一串。产物核过：表形与官方模板同形、无占位残留、门禁通过、三件齐全，图上那条生成条目三条路径都指着真文件。装的东西落在临时目录，**没进工作区、没进仓库**。

**顺带挖出一个真洞：`python-docx 1.2.0` 没有任何可执行的钉。** 这个数只活在散文里（ADR-0017 与两份 changeset 提过），仓库里没有依赖声明文件、没有任何机械检查。查过 PyPI，1.2.0 今天仍是最新版，所以**漂移还没发生**；但 1.3 一发布，自备环境的 agent 就会静默换掉「冻结转换器」的后端，而 `SKILL.md` 与 ADR-0006 都把它称作冻结的。这个风险与谁来装无关，只是今天被「开发机正好装着 1.2.0」盖住了。转换器扎得不浅：除公共 API 外还用着 `docx.oxml.OxmlElement` 与 `docx.oxml.ns.qn` 十余处，另有一处私有属性 `cp._element`（删 `lastPrinted` 用，python-docx 不接受 `None`），吃的正是上游最不承诺稳定的那一层。

我们决定：

- **约束的对象是后端版本，不是解释器。** 怎么拿到能跑转换器的环境（系统的、uv 管的、现装的）归 agent，正文不写死。要守的只有四条：能 `import docx`；装在**临时位置**，不进案件工作区、不进仓库；**不静默**；门禁本体零依赖照旧（ADR-0017），所以哪怕转换器怎么都起不来，已有的 DOCX 照样检得动。

- **钉子是一份随 skill 包分发的依赖清单**，落在 `loo0ng-to-docx` 的 skill 目录顶层，文件名 `requirements.txt`，精确钉 `python-docx==1.2.0`。仓库根上放的清单到不了律师机：两个 `plugin.json` 与 skills.sh 都只带 skill 目录。python **3.9 底线**由同一个数派生（`Requires-Python >=3.9`），写进同一份文件的注释，机械守门仍在 `tests/python-floor/`，不靠这份文件生效。

- **精确钉，另记「已知可跑范围」。** 今天这个范围只有 1.2.0 一个数；将来谁在别的版本上真跑过全套测试，才往里加一个。不用 `>=1.2.0,<2.0.0`：上游对 `docx.oxml` 那一层不作 SemVer 承诺，那个上界是空头支票。

- **版本对不上照跑，但必报。** 转换器把实测到的解释器与后端版本写进 stdout 回显，模型抄进审查报告的「生成依据」段，**恒常写，不只在对不上时写**；对不上时报文里明写这不是钉住的那个版本。这是 ADR-0017 那句话的正确移植：**缺能力不阻断，但不把没量过的说成量过了。**

- **机械检查不许 skip。** 四条断言：清单的形状是精确钉；这台机器上装的版本等于清单里的数；转换器回显里的版本取自运行时而不是照抄清单常量；清单里的数与正文、ADR 里的那个数一致。

- **正文给一条已验证的示例路径**（上面那三步），并明说它只是走通过的一条路、不是唯一路，uv 不在时另想办法。

## 考虑过的方案

- **版本对不上硬拒（退出码非零）**：把本 ADR 要消灭的阻断换个原因重演一遍。律师那台 mac 上哪天装了 1.3.0，工作台从「起不来」变成「拒绝跑」，对律师没有区别。
- **版本对不上把整件降为「需人眼」**：`CONTEXT.md` 给这个词的定义是「某项判据的推算区间横跨其阈值」，且明写「只可能由页数、空白页、行高三项产生」。塞一个依赖版本进去会当场破坏这个词的定义；何况需人眼件照常落盘，等于什么也没拦住。
- **区间钉 `>=1.2.0,<2.0.0`**：见上，上界无依据。
- **清单用 `pyproject.toml`**：`requires-python` 只在有人 `pip install` 这个目录时才生效，而 skill 目录不是包、没有 build backend、没人会装它，那份「机器可读」是假的；代价是让 skill 目录长得像 python 包。
- **清单放 `scripts/` 下一份自造 JSON**：agent 扫目录找依赖时不会认它，正好把「装依赖时读得到」这条要求丢掉。
- **正文只写约束、一个命令都不给**：把「agent 有能力自己完成初始化」当成了前提。没配过环境的机器上 agent 第一反应多半是 `pip install`，在系统 python 上会被 PEP 668 拒（本机即如此），而且会装进用户全局环境，直接违反「装在临时位置」。
- **依赖检查许 skip**：ADR-0015 的口径是本体测试在任何机器上全绿、不许 skip，只有渲染层许 skip。依赖钉不是渲染层；而且它红的那一刻，正是它唯一有价值的时刻。
- **「不静默」那一行新开审查报告第六段**：破坏「五段固定，顺序固定」这条格式契约，而这些段名被五个 eval 用例的断言引着。

## 后果

- `CONTEXT.md` 新增「冻结转换器」词条，`_Avoid_` 里点名「渲染器」：门禁那条渲染是另一回事，两个词混起来会把 ADR-0017 与本 ADR 搅成一团。「依赖清单」是实现细节，不进词汇表。
- `loo0ng-to-docx` 的 `SKILL.md` 那段环境正文重写；`references/审查报告.md` 的「生成依据」段加一行出件环境。
- `.agents/registration.md` 的目录布局表加一行：skill 目录下许有 `requirements.txt`。那张表此前是封闭的五项。
- 转换器要改（读清单、报环境）。ADR-0017 立的「门禁本体零第三方依赖、且不新增任何依赖」一个字不动，本 ADR 只碰转换器那一侧。
- **两处没验过，另开票，不作本 ADR 的前提**：受限沙箱（Codex `workspace-write`）下能不能自备环境（[#78](https://github.com/f4de01/lawyer-workbench-v3/issues/78)）；律师那台 mac 上能不能（[#79](https://github.com/f4de01/lawyer-workbench-v3/issues/79)）。`evals` 里为绕开前者而标着 `danger-full-access` 的用例本次不动，留给那张票。
- 本 ADR 满足三条件：照跑必报、精确钉、清单随包走，三条没有上下文都会让人奇怪；每条都在两三个方案间选过；钉子一旦立起，后来者要改它得重走一遍这里的取舍。

## 附注（2026-09-08，#78）

「两处没验过」的第一处销掉了：**受限沙箱（Codex `workspace-write`）下 agent 自备环境实测成立**，`uv python find` → `uv pip install --target <临时目录>` → `PYTHONPATH` → `import docx` → 转换器出件 → 门禁给结论，退出码与沙箱外逐条相同。结论是**有条件成立**，三个条件：uv 得在那个模式读得到的地方；至少已有一个 uv 管的解释器（沙箱里 `uv python install` 写不了 uv 的锁文件，装不了新的）；uv 的缓存要指到能写的地方。第二处（律师那台 mac，#79）仍未验，本 ADR 的裁定一条不动。

上面那句「`evals` 里……用例本次不动，留给那张票」已被 #78 兑现：11 个用例的 `Codex沙箱` 全部改回默认的 `workspace-write` 并实跑全绿，`danger-full-access` 留在跑器里只作能力、不再是任何用例的前提。顺带把 #28 与 #62 那条「PATH 上有 python 却敲不动」的老观察挖到根：不是 PATH 里没有它们，是那两个目录的 ACL 不继承、沙箱账户读不到。逐条实测表与处置在 #78 的 resolution 评论里，本文正文照 ADR 惯例不改。

## 附注（2026-09-09，#79）

第二处空白不再作为「未验」挂着，**改的是口径不是裁定**：律师那台 mac 不单独验，由本 ADR 立的「照跑必报」持续自报。

理由是这条机制把「先验一次」变成了「每次都验」。转换器恒常回显出件环境，模型原样抄进审查报告的「生成依据」段，所以那台机器上每出一份文书就自报一次实测到的解释器与后端版本；将来 1.3 发布、或那台机器换了环境，漂移会自己浮到审查报告里，不需要今天预先测一遍。自备环境这套动作本身的可行性已由 #78 在受限沙箱里坐实，不欠一次 mac 上的重复。

局限照实记，别把这条附注读成「验过了」：

- 0.1.0 已交付并试用，**出件成立**，所以那台机器上转换器跑得动：这是真实使用给的证据，不是探针给的。
- **走的是系统自带的 `python-docx` 1.2.0（`docs/research/mac-实测-20260907.md` 记着它在），还是 agent 自备了一次，仓库里没有证据。**答案其实就在那台机器上任何一份审查报告的「出件环境」行里，只是这一轮没有取回来。#79 第 1 项（现装的够不够用）只到「真实使用中出件成立」这一级。
- #79 的第 2 项（假装没装、从零自备一次）与第 3 项（核装出来的落在哪）在那台机器上一步没做。机制那一半由 #78 覆盖，**那台机器上的那一半没有覆盖**。

本 ADR 的裁定一条不动。
