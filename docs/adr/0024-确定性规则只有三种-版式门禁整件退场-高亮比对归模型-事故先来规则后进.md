# 确定性规则只有三种：字节原样、被检查的是模型自己、对律师文件的写入可重放；版式门禁整件退场，高亮比对归模型，事故先来规则后进

ADR-0023 把出件改成填模板差量之后，to-docx 剩下两个脚本：`fill.py` 555 行施加差量，`gate.py` 1193 行做门禁，其中约 400 行无渲染的版面推算、约 150 行 Word COM 渲染加信、三条从 Markdown 路线留下的结构判据加「模板表缺失」。下一张票 #14 又要写一条比对命令：段落模糊匹配、段内多重集合消一个，判律师填没填。2.0 交接件 §2.3 的诊断是「语义归模型、确定性归代码」这条分界画得太靠代码侧；ADR-0022 的诊断是工程走向加固边界与添加门禁。两次都没写下代码到底该留什么。2026-09-14 一轮 grilling 把它写成一条判据，再拿它复审 `gate.py` 与 #14。

## 判据

**确定性规则只有三种**，其余都是判断，归模型加 skill 正文里的方法与律师的眼睛：

1. **字节必须原样保住的**：在 docx 上施加差量，拷贝与搬运不改名不覆盖。
2. **被检查的一方是模型自己的**：差量本身不合法即拒改（编号越界、原文不唯一、区间重叠、run 含脚注图片域），雏形的同名判重。
3. **对律师文件的写入必须确定性可重放的**：图的唯一写入口。

**没有例外。** grilling 里试过给「律师在 WPS 里看不见的东西」（模板自带的第三方作者姓名）开一条例外，律师裁定那本质不是事故，能处理是好事、不处理也没问题：`apply` 收尾无条件清元数据是第一类（施加本身的构造），不需要一条检查。

**事故先来，规则后进。** 「一次事故 → 一条规则加一对 fixture」这条口子不关，加一道过滤：事故的教训先问落不落进三种之一，落进的才成代码规则加 fixture；落不进的写进它所属 skill 的正文（AGENTS.md「本文件写什么」）或 eval 用例。to-docx 正文里那句引的「通用裁定台账」是 2.0 的东西，随这条改。

## 复审 `gate.py`：整件退场

按这条尺子逐层查，`gate.py` 里没有一层落进三种：

- **版面推算与「需人眼」一档**（ADR-0017）：从没在真实出件里触发过，仓库里唯一触发它的是 eval 种子「带内」把 `trHeight` 钉成恰好 200 磅造出来的；现场记录表 D4a 那一行从没填过。律师办案机（mac + WPS）恒定没有渲染通道，而律师出件后本来就在 WPS 里打开看：撑列、页数这类由填进去的字多长决定的几何，是律师一眼看见的东西，一句「写短点重出」就修了，重出不动他填过的。几何门禁的全部价值只剩「模型自动重试两次不烦律师」，代价是 550 行、一个从没触发过的第三档、与「测不准算不算通过」整套话术。
- **渲染层**：律师机上永远不跑，唯一价值是开发机上「推算区间不含实测值」这条给开发者看的探测器。三件回归件的真值已冻在 `tests/to-docx/test_layout_estimate.py`，推算器再改时手动量一次就够。
- **四条结构判据**：页脚 PAGE 域写死是旧仓 #28 预写的故障构造，没有任何事故，且 `list` 只枚举正文 `w:p`、模型碰不到页脚；模板表缺失来自旧仓 #107，`delete` 只删段落、单元格末段改清空，表删不掉；元数据残留是 2.0 真实事故，但 `apply` 收尾已无条件清掉；表格直接接 sectPr 在 2.0 是推断的风险（本机 Word 打开正常，从没真出过修复提示），差量路线下模型 `delete` 表格后那个空段仍能复现它，守法搬进 `fill.py`（改清空不删，与单元格末段、带 sectPr 的段同款），落进第一类。
- **第一样「改动段残留占位且不在高亮里」**：`apply` 收尾的留黄扫的是全篇，模型误去黄一个占位当场被重新标黄；这一条能拦的只剩「模型把 XX 当值填进槽」一种，律师在 WPS 里看得见，与所有其他判断同一档。留它会让「门禁」以另一个名字活着。

于是 **`gate.py` 整件退场**：推算、渲染、三档结论、退出码 3、阈值旗、`--no-render`、`--template`、`--deliver`、`--overwrite` 全部不再有。`fill.py` 改三处：表格后末段的 `delete` 改清空；`fill` 空串按「没填」处理、槽留原占位由收尾留黄（`replace_range` 收到空串就删 run 那一段只对 `replace` 成立，`replace` 空串是条件块取舍的正当用法）；`--out` 可直接写 `文书/` 下的路径，拒改一个字不写，fail-closed 由构造成立。「律师说把这份 docx 检一下」这个用法随之消失，「这份模板有哪些槽」（`list`）留。

**数据泄露与渲染格式两样机制没有缺**，它们在施加本身里：元数据每次施加无条件清；差量只落在槽的字符区间上，`tblPr`、`tblGrid`、`trPr`、`tcPr` 与槽外每个 run 的格式逐字节不动，原型在 19 件官方模板上验过，`tests/to-docx` 逐件回归守着。这份保证从运行时的门禁挪进了测试：每次改 `fill.py` 都要过 19 件。

## 复审 #14：比对代码不写

判「律师填没填」是判断。`fill.py list` 已把当前文书的高亮标成 `⟪⟫`，模型读清单加上一次审查报告里的高亮清单自己就能判，只对仍高亮处与律师点名处写差量。误去黄的后果：占位形状的槽由 `apply` 全篇留黄自动纠回；差量的 `unhighlight` 结构上不碰文字，律师的字不会被改到；兜不住的只剩没把握的句子与不带标记的提示文字上的高亮，去黄后律师少一处「看这里」，写进正文作已知行为，真出一次事故再按尺子进代码（那时它恰好是第二类）。这与 #141 形状不同：#141 是模型改正文、门禁看不见正文；这里模型的判断只能落成一个只改格式的算子。

审查报告仍四段，第三段「门禁原话」改成「施加原话」：`apply` 回显整段照抄（出件环境、逐条改动、留黄、若有拒改则拒改原文与重来次数），它本来就是这一版「代码做了什么」的唯一留痕。

## 考虑过的方案

- **第二类照字面收推算**（撑列的字是模型填的，所以几何门禁算「被检查的一方是模型」）：会把 550 行整个收回来。第二类收的是精确检查（读 XML 得二值、集合成员），不收区间与阈值。
- **留一个只查第一样加 `--deliver` 的 60 行 `gate.py`**：留一个只能查一件事、而那件事施加时就能拒的 CLI，是为了保住「门禁」这个词，不是为了保住律师。
- **`fill` 空串拒改**（它是 #141「删槽」的差量写法）：拒改是内容检查，#141 的机理正是「检查占位 → 模型删槽过检」。改成按没填处理，槽留着由收尾留黄，不拒。
- **#14 补一小段代码兜没把握句子那一类**（`apply` 加一个输入：去黄处的当前文字若与记录的原文相同即拒，一行集合查找）：代价是审查报告里的高亮清单要有代码能读的形状。事故还没来，不预写。
- **兜底件保留元数据一条披露项作尺子的唯一例外**：律师裁定不是事故。
