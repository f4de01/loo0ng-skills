# 案件工作区就是客户端建的项目目录，起手加位置闸与件数闸

律师那台 mac 2026-09-19 装完桌面卡片、起了第一个案子，两段回显暴露出同一件事：**没有人规定过案件工作区该建在哪里，于是它建在了客户端的默认工作目录里。**

本会话核实过的事实。律师机是 MacBook Air（M1）、装卡片当天由 macOS 13.2.1 升到 macOS 27；Zebar 3.3.1 的 brew cask 写着 `depends_on macos: :sonoma`，上游 `tauri.conf.json` 的 `minimumSystemVersion` 是 `14.6`，来自 2025-02-08 的 commit `6bedfbef`（标题自述是为了让 rust-analyzer 与 cargo 用同一个 deployment target、避免 `*-sys` crate 重编），仓库里没有任何 macOS 14 独占 API，唯一的原生调用是 `NSWindow.setLevel_`（macOS 10.0 时代），同作者的 GlazeWM cask 写的是 `:ventura`。也就是说那个门槛是打包卫生的副产物，不是技术要求；律师升级之后它不再挡路，本票不为它做任何代码改动。

真正的问题出在升级之后。同一天出现了**三个互不相干的案件根目录**：律师原本放案子的 `~/Desktop/破产事务/案件`（里面是已经起过手的工作区）；装卡片的 agent 自行新建、并覆盖了既有设置的 `~/案件`（空的，案件数 0）；以及 `setup-case` 实际落脚的 `~/Documents/ChatGPT`，那是客户端的默认工作目录。三者交集为零：卡片盯着一个空文件夹，真案子在桌面上，新案子在客户端的文件夹里。

`docs/交付/律师上手指南.md` 对这一步的全部要求是一句话：「让 Codex 到那个文件夹里工作……这一步很重要，起手认的就是『当前目录』」。这是整条交付路上唯一一个无法自动化、又完全没有护栏的步骤，它翻车时没有任何提示。而 `setup.py` 的 `sweep_to_pending` 会把当前目录里所有非点开头、非保留名的条目搬进 `待归档/`，**没有件数上限、没有确认、没有干跑**，所以落错目录的代价不是"位置不好看"，是把律师放在那儿的东西整批搬走。

ADR-0007 有意不回答"工作区之上怎么摆"，ADR-0029 与 ADR-0030 各有一处否决理由是"那等于把 ADR-0007 偷偷回答了"。本票公开地回答它。

## 我们决定

- **案件工作区就是客户端建的项目目录。** 律师在客户端里新建一个项目，客户端确定目录，那个目录就是这一案的工作区；`setup-case` 认的"当前目录"因此天然就是对的位置，不需要他再记得切一次。这条同时解掉一个副作用：工作区落在客户端的工作目录之内，起手对工作区自己的写入就在沙箱允许的范围里（沙箱本身见 ADR-0032）。
- **客户端只认自己建的项目，所以迁移是"新建再搬进去"，不是"搬过去再打开"。** 已经起过手的老工作区要进来，先在客户端里新建一个项目，再把老工作区的内容整体移进那个新目录。本会话核实过搬动是无损的：`图.json` 与 `图视图.json` 的 `文书`、`审查报告` 一律是相对工作区根的正斜杠路径，绝对路径引擎直接拒（`GRAPH-FORMAT.md`）；`源图` 只是个文件名；指针块"一条路径都不记"；`归档索引.md` 的第一列也是相对路径。整个目录 `mv` 过去，一个字都不用改。这是"案件图自足"设计好的性质。
- **不设第二个案件根。** 卡片支持多根，但两个根会立刻把"案件工作区 = 客户端项目目录"这条等式打回"老案一套规矩、新案另一套规矩"，而桌面与文稿一样吃 macOS 的目录隐私授权，双根一分麻烦都省不掉，只是把要授权的地方从一个变成两个。
- **起手加位置闸：几个目录绝不许起手，`--force` 也不放行。** 家目录本身、它下面的 `Desktop` / `Documents` / `Downloads` / `Library` / `Movies` / `Music` / `Pictures` / `Public`、文件系统根与 `Users` / `home` / `Applications`，以及**桌面卡片的根目录本身**。前一组拦的是"把律师的整个数字生活搬进待归档"；后一组拦的是另一种无声失败：在根目录上起手，建出来的案件卡片永远扫不到（它扫的是根的下一层），而起手仍然报成功。盘符按被检查的工作区自己的取，免得在 Windows 上拿无盘符的路径去比一个有盘符的。
- **起手加件数闸：要挪走的东西超过 20 件就拒绝，`--force` 放行。** 位置闸拦得住叫得出名字的那几个，拦不住律师随手堆东西的某个目录。件数是本地就拿得到的旁证：一个新建的案件目录该是空的，或者只有客户端放的那两份说明（`AGENTS.md`、`CLAUDE.md` 本来就在 `KEEP_AT_ROOT` 里，不计入）。这一闸给 `--force`，因为"这些东西本来就该进本案的待归档"是一个真实且正当的场景。
- **拦的件数与搬的件数共用一套规则。** 新增 `sweepable()`，件数闸与 `sweep_to_pending` 都从它取名单：两处各写一遍迟早走样，拦的数和搬的数就对不上了。
- **新增 `--dry-run`：只打印会建什么格、会挪走哪几件、卡片看不看得见，一个字不写。** 它给模型一个在真正动手前把计划摊给律师看的办法。位置闸对干跑同样拒绝：干跑不该把一个拒绝说成一份计划。
- **一个确认点都没加。** 三样全是拒绝或只读预览，不是问句。ADR-0023 定下的"起手清单是那条路上唯一的确认点"形状不破。
- **不碰 ADR-0007 的射程。** 本票不规定工作区之上怎么摆，只规定几个地方不许起手，以及"客户端项目目录是我们推荐并据以设计的那一种摆法"。律师要把项目建在哪，仍是客户端和他自己的事。

## 考虑过的方案

- **继续只靠上手指南那句话**：已经证明会翻车，而且翻车时完全无声。律师照着走，走完还以为成功了。
- **护栏判据用"当前目录在不在卡片设置的某个根之下"**（本会话一度推荐过）：被 ADR-0032 否掉。那份设置**写不进**，用一个写不进的文件当护栏判据，护栏本身就是坏的；而且它拦不住真正的灾难（在一个装满东西的目录里起手）。只读地拿它判"当前目录是不是根目录本身"是另一回事，那一条留下了。
- **起手不再认"当前目录"，改成显式传路径**：会改掉律师上手指南整条动线，而且路径由谁来给、给错了怎么办，只是把同一个问题挪了个位置。
- **在起手清单里多问一句"这个目录对吗"**：破坏"唯一确认点"这条形状，换来的是一次本可以机械判定的确认。判得出来的事不该问。
- **把桌面那批老工作区留在原地当材料库**（本会话一度推荐过）：被事实推翻，那里面是已经起过手的工作区，不是散材料。
- **卡片设置里留两个根，谁都不搬**：见上，把一次事故固化成长期状态，而且省不掉授权那一层。
- **件数闸不给 `--force`**：把一个正当场景（这些东西确实该进本案待归档）变成死路。
- **件数闸的上限设得更小（比如 5）**：客户端项目目录里除了两份说明通常是空的，5 和 20 拦到的是同一批灾难；上限定高一点，误伤少。

## 后果

- `skills/engineering/setup-case/scripts/setup.py`：新增 `sweepable()`、`forbidden_dirs()`、`guard_location()`、`guard_sweep()` 与常量 `SWEEP_LIMIT`、`SYSTEM_SUBDIRS`；`sweep_to_pending` 改从 `sweepable()` 取名单；`cmd_init` 在任何写入之前过两道闸；新增 `--force` 与 `--dry-run`；文件头说明改写。
- `skills/engineering/setup-case/SKILL.md`：「一条命令」一节多一段两道闸与干跑的说明，并明写拿到位置闸的拒绝时该怎么做（去客户端新建项目，不要找别的目录绕过去）。
- `docs/engineering/setup-case.md`：「When to reach for it」多一段面向律师的"起错地方它也会拒绝"。
- `tests/setup-case/test_setup.py`：新增 `位置闸` 与 `件数闸与干跑` 两个测试类共 12 条。位置闸的测试把 `HOME` / `USERPROFILE` 指到临时目录，碰不到开发机真的家目录。
- 迁移动作留给交付：律师那三个目录的收拾（设置改指客户端项目目录、删掉空的 `~/案件`、桌面那批老工作区逐个新建项目再搬进去）在律师机上做，本仓库不记它们的路径。桌面那批的**格式版本**还没查过；引擎只认当前版本、遇到更早的明确拒绝且没有升级路径，若有旧版本的，那几案是重新起手而不是搬。
- 「案件根目录」进 `CONTEXT.md`。
