# 工作流按律师用法重做：预设图两处两归属、案件图自足、文书覆盖不迭代、填模板差量出件、审查报告降为留痕、陈述与回流退场

ADR-0022 之后 `doit` 重做了一轮正文，律师带回的反馈不是措辞：材料堆积自己归档不动；起手问领域、问起手图、问雏形，问得比办的多；审查报告没人读，律师要的是文书里标黄「你来填这里」；对话里给过的材料与出过的文书，下一个节点还得再给一遍；文书版本律师从不追溯。2026-09-14 一轮 grilling 把这些定成一条新工作流，需求单在 `docs/research/工作流-重做.md`，本文只记其中难改回、没上下文会觉得奇怪、且有真实取舍的几条。

我们决定：

- **预设图两处两归属，出厂原位读、不拷出包。** 出厂预设图住 skill 包内，升级整个换掉；个人预设图住律师本机 `~/.loo0ng/预设图/`，由律师从案件图另存而来，升级碰不到。两者不合并，同名拒。案件工作区只记名与归属，不记路径，路径按名当场解析。取舍：ADR-0019 那套「活图从种子拷出、之后只认活图」要维护两份同名图的一致性，0.1.0 又把包内绝对路径写进了工作区、升级即死；两处两归属靠目录物理隔开，更新即删旧装新，包外没有残留，律师的图在另一个目录。

- **案件图自足，起手整份拷入。** 预设图起手把模块、节点、时限句、整个模板目录一次拷进工作区，之后前方只从案件图的条目算，惰性带入、`--domain`、按 id 查预设图全部退场。取舍：整份之后惰性带入没有东西可带；律师看视图要看整个流程有哪些节点、办到哪，整份在图上才看得见；「预设图后来新增的节点按名带入」为少见的升级情形保留一条运行时依赖，不值得。代价：律师加节点只走一句话新增，想带回预设图就整份另存。

- **文书覆盖不迭代。** 一节点一份 docx 加一份审查报告，重出覆盖同一路径；图的生成条目仍只追加，留痕第几次、何时。律师的改动默认正确：重出以当前那份为底，代码比对上一次记下的高亮清单，文字变了的去黄不碰，没变的 agent 填，律师点名处照改；律师改过的位置不经门禁。取舍：律师不追溯版本，`-v{n}` 只让目录变长；覆盖的风险是吃掉手改，用「agent 只写高亮处与点名处」堵住，不用「判断哪些是律师改的」。

- **出件走填模板差量，不重写整篇。** 代码把模板或当前文书的段落与单元格打成带编号清单，agent 提交编号处的改动（填、删段、加或去高亮），代码原地施加；Markdown 最小集与冻结转换器退场。缺的槽保留模板原占位加黄色高亮，没把握的句子也高亮。门禁缩成两样：改动处无残留占位且不在高亮里、几何不超阈值。取舍：ADR-0006 的「模型写 Markdown、转换器以模板为载体」在十轮样本里十中都把模板重写了一遍（#141），门禁只量几何、全报通过；差量输出把「删句、抹法院名、编事实」变成结构上不可能，也去掉七段长文本写作里最大的那一段。

- **审查报告降为机器留痕，名字不改。** 四段：生成依据逐值记来源、高亮清单、门禁原话、时限推算；不再要求律师读它，收尾改为直接说高亮了哪几处。确认仍是律师在对话里一句话，永不从「高亮已清」推断：黄色没了可能只是删了一段，不等于认可全篇。出件与确认可跨对话，一个对话一个节点保留为默认。

- **整读范围收到同模块在前的已确认文书。** 后节点依赖前节点，但只读同模块里排在前面且已确认的；其他模块不读，未确认不读，律师点名的加读。取舍：读全部已确认文书随案子累积越来越慢；只读律师点名的把工作量推回律师。代价：前面的节点被跳过时后节点缺值留黄，由律师补。

- **律师陈述机制退场，换成一份追加文件。** 律师在对话里说的每一句本案事实或选择，agent 追加一行到 `材料/律师说过的.md`（日期、原话），不判它落没落进文书、不回显；性质三档、取代链、`--reply`、拟标题整套退场（ADR-0013）。改口是再追加一行，后说覆盖先说由整读时判。理由：原则是「律师给过一次的东西不给也能出」，零判断零往返的落法才不会被跳过。

- **回流与入库退场，换成另存与导入。** 律师侧逐节点回流那一问删掉，律师要复用整案的图就一句话另存为个人预设图；开发侧改为导入：agent 整读来源（目录树、指引手册、别的案件图）写雏形、判重、拍板进个人预设图，再经 PR 进仓库成为出厂预设图，第二双眼审那次 diff。律师不可导入。`intake`、`home`、`references/回流.md` 删（ADR-0012、ADR-0019、ADR-0020）。

- **目录改形。** 收件箱改待归档；指南与模板并入 `参考/` 下两格；文书按 `文书/<模块>/<节点>/`；派生视图仍两份（律师读的 md 与可视化插件读的机器可读一份），状态只在引擎里算一次；`材料/律师陈述/` 不再有；工作区根加 `归档索引.md`。归档能力加强：输入可指工作区外任意目录（复制、原件不动），按内容去重，维护索引；律师发起的与起手末尾那次先出清单再搬。不做解压、识图、OCR、PDF 转文本，后两样留位。

## 考虑过的方案

- **保留活图与逐节点回流，只加个人预设图**：两套机制回答同一个问题（律师长出的东西怎么复用），逐节点那一问在每次确认后出现，律师没有一手记录说它有用。
- **预设图起手空图加惰性带入（现在 `init --empty --domain-name` 的形状）**：空图与预设图的区别只剩「有没有前方」，律师感知不到。
- **版本迭代保留，加「律师改过就停下问」**：多一个判断、多一次往返，律师仍不追溯版本。
- **文书里高亮清零即视为确认**：把律师专权交给文件状态推断，是 ADR-0002、ADR-0010 那条「确认永不由 agent 代做」的反面。
- **整读全部已确认文书**：正确性最好，但一次生成的读取量随案子单调增长；破产案 72 个节点办到后半段每次都要读几十份。
- **陈述文件只在事实没落进文书时才写**：多一个判断，多数时候判错的代价是下一个对话看不见这句话。

## 后果

- ADR-0006、0012、0013、0016（案件图不存时限那一半）、0019、0020 描述的机制退场；文件不动，与 0001 至 0021 一样按 ADR-0022 读。
- `AGENTS.md` 结构不变量 5「领域目录三样」改为预设图的形状（包内 `assets/预设图/<名>/` 只有图、模板、指引手册；个人预设图在包外），在 domain 重做那张票里改，改时引用本文。
- `CONTEXT.md` 同日整体改写：新增预设图、归属、空图、待归档、参考、律师说过的、高亮、差量、归档索引、另存、导入；退场领域图、领域目录、回流、入库、律师陈述、收件箱、冻结转换器；「图存档」并回「派生视图」的机器可读形态。可视化插件定为独立于 Codex 与 Claude Code 的应用，只读那份机器可读视图，不自己算状态。
- 七件 skill 逐件按需求单第 3 节改，顺序 graph → to-docx → filing → domain → setup-case → doit → ask-loo0ng；to-docx 的差量路线先以原型验证 python-docx 能否按编号原地改写并保住表格几何，不行则回到 grilling 只补那一支。
- 出厂种子里的指引手册留在包内给开发者导入用，不拷进工作区。
- 硬边界两条不动：个人预设图在仓库外，办案会话对仓库仍只读；导入的预设图进仓库那次 diff 仍经隐私钩子与第二双眼。
