# skill 正文随包自足：与 ADR、issue 与仓库文件剥离

七件 skill 的第一轮重做（ADR-0022 的改造期）写正文时，习惯把裁定的出处随手括在句尾：一条规矩后面跟一个 ADR 号，一句实测后面跟一个 issue 号，一处定义指向 `CONTEXT.md`，一条测试要求指向 `tests/`。清洗前的盘点：七件 `SKILL.md` 与八份 `references/*.md` 里有 25 处以上 ADR 号、若干 issue 号与实测出处，另有三处直接指向不随包分发的仓库文件（词汇表的归属定义、`AGENTS.md` 的结构不变量、仓库测试目录）。

这些指针在开发机上读得通，在律师机上读不通：`npx skills add` 与 `claude plugin install` 装过去的只有 `skills/<bucket>/<name>/` 这一个目录，`docs/adr/`、`CONTEXT.md`、`AGENTS.md`、`tests/` 一个都不在。

真正推动这条裁定的是一次实机事故：**skill 未加载时，模型靠读仓库里的 ADR 找到了实现路径，自己模拟了一遍流程**。它之所以拼得出来，正是因为正文把实现细节的指针撒在了仓库里。出处标注不只是读不到的死链，它还是一条邀请，请模型绕过正文去别处重建一套流程。

## 裁定

**skill 正文随包自足。** `SKILL.md` 与 `references/*.md` 自己说完该说的，不指向它在用户机上读不到的任何东西：

1. **ADR 号、issue 号、版本号一律不写。**
2. **历史对比句一律不写**（「以前 X 现在 Y」「随某裁定退场」「0.1.0 曾经如何」）：正文描述的是现在这一版的打法，不是它怎么变成这样的。
3. **出处与实测标注删出处、留内容。** 「这条打法只在 Codex 客户端实测过、别照搬到另一侧」是会改变模型判断的内容，留；「（旧仓库 #40）」是出处，删。
4. **理由段按两档处理**：不改变模型判断的删；会改变判断的改写成判据本身，即写「不许 X」，不写「因为当年 Y 所以不许 X」。后者是在请模型评估那个理由今天还成不成立。
5. **包外引用就地补成一句话**，不留指针。开发者的规矩（例如「改任一件 skill 都要同步路由那两张表」）不是运行时的规矩，直接从正文里删掉：它写在 `AGENTS.md` 的结构不变量里，读它的是开发者，不是装了包的模型。

**一条常驻的机械检查守着不回潮**：`scripts/check-skill.sh` 逐件扫 `SKILL.md` 与 `references/*.md`，命中即红。白名单放行三样：清单坐标（`p2#1` 这类不是 issue 号）、指向本 skill 目录内的链接与 `references/` 路径、钉住的后端版本号（`python-docx==1.2.0`、`python 3.9.6` 是模型要照抄的内容，不是仓库的发布版本）。

## 为什么不

- **人工读一遍就够**：挡不住下一次顺手写。出处标注是写作时最自然的动作，只有机械检查拦得住。
- **改成「装包时剥掉」**：正文在仓库里与在用户机上就成了两份，开发会话读到的与模型实际拿到的不是同一份，比留着指针更坏。
- **把 ADR 一起装进包**：ADR 是决策记录，写给开发者；把它送到律师机上，正是这次事故里模型读的那一份。
- **连「只在某一侧实测过」这类话也删干净**：那会丢掉会改变判断的内容。删的是出处，不是判据。

## 后果

- 七件 `SKILL.md` 与八份 `references/*.md` 按上面五条清洗。`frontmatter` 的 `description` 与 `agents/openai.yaml` 的 `short_description` 是元数据，顺手核一遍，不是清洗对象。
- `AGENTS.md` 结构不变量加一条（第 7 条）。
- `scripts/check-skill.sh` 加一条常驻检查。已知代价：`check-skill.sh` 自身没有单测，这条规则写错了没有第二道拦。
- 与被删句子绑定的「正文必须含某字符串」类断言随正文走：断被删句子的跟着删，断行为的改写成断新句子。不为保住测试在正文里留句子。
- 本文与 ADR-0022「正文为准」同向：正文是唯一的实现依据，ADR 只解释当时为什么这么定。

## 2026-09-16 附注：随包脚本的说明也自足（#54）

开发者裁定扩展约束到 `scripts/` 的说明，包括实现注释、文档字符串与回显。脚本和正文一起安装，模型排障时会读脚本，运行时还会直接读到回显；以「给维护者读」为由豁免会留下同一条包外依赖。理由就地写成现行规则，开发出处留在仓库记录里。

范围承接 #53 摊平后的根目录全部 `*.md`，另加 `scripts/` 文件；检查器同步扫描两处。此次实际盘点为六个脚本、48 行中的 56 处 ADR 引用，并有 issue、CONTEXT 与 docs 引用，一并清理。运行所需的格式版本、依赖版本、包内路径与工作区文件名保留，`assets/` 中的官方模板与指南原件不动。通过 CLI 回归测试守住脚本引用拒绝、合法运行信息放行与原始数据豁免。
