# 验证分三层，测试工作区只生不存，测试放 skills 之外，一个跑器两个后端，Codex 侧编排 skill 用替身提示词，全部本地不做 CI

ADR-0009 把每张 skill 票的完成定义落为「在 Codex 案件会话与 Claude Code 各真实触发一次」，并留下一句「开发迭代可在测试工作区做」。本票展开这一句：没有真实案件时 skill 怎么验证，测试工作区放哪、怎么建、含什么，两平台的验证方式是否相同，迭代与关票之间怎么衔接。制票时的前提事实：本机 `claude plugin eval` 处于 early access（服务端旗标，本地开不了），且其确定性判定只看文件存在与回复文本、读不了文件内容；Codex 没有 eval 跑器，`codex exec` 的提示词里 `$名` 不解析，显式触发的 skill 在 AFK 下触不到；Matt 体系本身没有 skill 级测试；隐私钩子（ADR-0014）会扫进仓库的每一行。

我们决定：

- **验证分三层，判据各异。** 脚本层：四个参考 skill 的零依赖脚本，用 `/tdd` 红绿循环 + 标准库 `unittest`，判据是断言。skill 层：模型读了 SKILL.md 之后有没有做对，判据是测试工作区里的文件状态（`图.json` 的条目、`文书/` 下的文件、律师陈述目录）。真实案件层：ADR-0009 的完成定义，只记结果类别。
- **测试工作区只生不存。** 仓库里不存任何案件工作区（包括合成的）；存的是种子：`收件箱/` 的合成文件、一段按顺序调用图引擎 CLI 与归档脚本建状态的 Python、一份状态说明。每次测试在临时目录用 `loo0ng-setup-case` 起手、回放种子生出工作区，跑完即弃。不另定回放格式：种子走的就是 skill 会走的命令，引擎一改测试立刻红。
- **种子里不出现能被隐私钩子五类正则命中的字符串。** 案号、当事人、法院等字段的值由种子里的律师陈述给出、取「不像真的」的值（如「测试案号甲」「甲公司」），文书按正常路径填入，不留占位符；不给钩子开豁免。
- **领域两用。** 脚本层用一个合成小领域（`evals/领域/`），证明引擎与模型不认破产语义；skill 层端到端用真实的破产领域目录，因为 skill 正文、路由决策树、雏形机制只有读真的指引手册与模板才测得出写坏。
- **起手两个场景**：空目录（起手三选一、机制 B）；在办中（领域图起手 + 一个已确认节点 + 一个已生成未确认节点 + 两条律师陈述）。收件箱含既有成品的场景等起手清单实现票再加。场景只随实现票与事故进入，不预铺。
- **一个跑器两个后端**：`scripts/skill-eval.py --harness claude|codex`，标准库零依赖，与 `link-skills.ps1`、`privacy-check.py` 同层。Claude Code 侧走 `claude -p`（Git Bash 下 `MSYS_NO_PATHCONV=1`），Codex 侧走 `codex exec`。用例是一个目录：提示词、指向种子的名字、一段读工作区文件判真伪的 Python 断言，两侧共用；不用 LLM 评判，回复形状用正则。每用例默认跑一次，`--runs N` 供怀疑抖动时用；抖动是正文问题，不用多数决盖住。每次调用带回合上限与超时，超限记失败。不采用官方 `claude plugin eval`：旗标本地开不了，开了也读不了文件内容。
- **Codex 侧编排 skill 用替身提示词**：「读 `~/.agents/skills/<名>/SKILL.md` 并照做：<律师原本会打的一句>」，测的是正文不是触发；触发由「两平台补全与 $ 提及的人工实测」与完成定义那一次覆盖，用例说明里写明这个局限。参考 skill 靠律师一句话隐式触发，`codex exec` 能直接测。
- **测试放 `skills/` 之外**：脚本层单测在 `tests/<skill 名>/`，skill 层用例与种子在 `evals/`（`evals/种子/<场景>/`、`evals/领域/`）。`skills/<name>/` 里只装律师机器要用的东西，skills.sh 拷贝时不带测试。目录名保持 ASCII 给工具用，内部按仓库习惯用中文。
- **两道门分开**：合入门槛 = 脚本层测试全绿 + 两侧 eval 全绿（+「两平台注册、补全与拉取实测」定下的登记校验）；关票门槛 = 真实触发一次（ADR-0009）。eval 结果不进仓库，只进用例。
- **事故先红后绿**：真实案件层的事故由处理它的那次开发会话写成用例（脚本层一对 fixture 或 skill 层一个用例），先红再修，随修复 PR 同来；用例说明只留「什么形态的输入导致什么错」，不留工作区路径与案件事实。ADR-0006 那条「一次事故 + 一对 fixture」由此推广到全部 skill。
- **门禁测试缺 Word 即 fail 不 skip**：门禁「没有渲染能力时明确报错、不降级」（ADR-0006），测试 skip 就是在测试里降级。
- **全部本地、不做 CI**：门禁要 Word COM，eval 要两个 harness 的本机登录态，钩子已定不做 CI；GitHub 上的 PR 检查只剩第二双眼。等第二台机器出现再议。

## 考虑过的方案

- 仓库里存一份完整 fixture 案件目录：`图.json` 格式还会变，快照随格式漂移失效；ADR-0003「状态只算不存」对测试同样适用。
- 钩子对 `tests/`、`evals/` 豁免：在守门上开洞，ADR-0014 刚定钩子零维护。
- fixture 留 `〔案号〕` 占位符出件：门禁日后加「未填占位符」规则会拦自家 fixture。
- 只用真实破产领域：测不出引擎写死破产语义；只用合成小领域：测不出提示词写坏。
- 采用官方 `claude plugin eval`：early access 本地开不了；确定性判定只有 `file_exists` / `regex`（回复或轨迹）/ `tool_used` / `tool_order`，断言 `图.json` 内容仍得自己写。按官方 `case.yaml` 格式写用例给自家跑器读：等于养两套。
- Codex 侧完全人工、只在完成定义那次验：把迭代全押在 Claude Code 上，两平台系统提示不同，正文一边好用一边不好用是常事。Codex 侧只冒烟不断言：没有判据。
- 测试放 `skills/<name>/scripts/tests/` 随 skill 分发：律师机器上没用，拷贝体积翻倍。
- 每用例固定跑 3 次全绿才过：三倍花钱，抖动藏进平均分。
- CI 跑脚本层的一部分：三样依赖都只在本机，为它单独维护一套环境不值。

## 后果

- `CONTEXT.md` 新增「测试工作区」；「确认」条「测试案件」改为「测试工作区」。种子、用例、跑器是实现细节，不进词汇表。
- ADR-0006 附注：门禁 fixture 的落点是 `tests/loo0ng-to-docx/`，缺 Word 即 fail。ADR-0009 附注：「开发迭代可在测试工作区做」展开见本 ADR。
- `tests/`、`evals/`、`scripts/skill-eval.py` 随 `/to-spec` 之后的建仓工作落地；两个起手场景的种子随 `loo0ng-setup-case` 与 `loo0ng-doit` 的实现票写。测试命令进 `.agents/testing.md` 的维护段。
- 地图 Out of scope 加一行：CI 与第二台机器上的测试。

## 附注（2026-09-07，ADR-0017）

「缺 Word 即 fail 不 skip」改口径：降级的定义随门禁本体走。门禁本体已改为零依赖推算层，所以**推算层测试在任何机器上都必须全绿、不许 skip**；只有渲染层那几件许 skip，且须打印说明。「测试工作区只生不存」与其余各条不变。

## 附注（2026-09-07，#66）

「测试工作区只生不存」的适用范围从合入门槛（脚本层测试与两侧 eval）**延伸到关票触发**：关票前 `python scripts/skill-eval.py --materialize <种子>` 生一个临时工作区，两侧各触发一次，用完删。它打印工作区路径就停，不跑 harness、不删，因为生出来是给人接着用的。「像办到一半的真案子」这层真实性由种子给（`在办中` 就是这一个），代价是每次关票多一次回放，认了。

由此，Cases 根下那几个常驻合成目录**不再承担任何门槛**：它们只是手工探索的现成起点，可以留着，但关票不在它们上面做，也就不必再为它们写「什么时候重建」的规矩。ADR-0009 的完成定义随之改口径，见其同日附注。


## 附注（2026-09-08，#68）

**合入门槛仍是「两侧 eval 全绿」，例外只有一件：Codex 侧的「出雏形」列为已知抖动，单件红放行。** 律师 2026-09-08 就 #68 裁定：全量 19/20 可以通过。这件抖动与任何一次改动都无关：`fix/65-codex-三件红` 上 4 次红 2 次，stash 掉全部改动回到 main（`8e29df3`）同样跑 3 次仍红 2 次，两种漏法（回显漏空白模板名、漏时限）都出现过；同一份正文在 Claude Code 侧稳定给全。

豁免的边界写死三条：只对 `出雏形` 这一个用例，只在 Codex 侧，且只在其余 19 件全绿时成立。其余任何一件红仍是阻塞，这条不读作「19/20 就行」。PR 里照 #65 的做法点名这件红、写明与本票无关。

这条不改正文那句「抖动是正文问题，不用多数决盖住」：那句禁的是复跑取多数把红盖成绿，而这里是把一件已知红原样记在门槛旁边，不复跑也不改判。`loo0ng-domain` 的回显段下次被改动时，这条一并复核。

## 附注（2026-09-12，#96）：「不做 CI」的射程只到测试与门禁，不含发布

标题里那句「全部本地不做 CI」写得太满。正文给的理由只有一条：**门禁要 Word COM，eval 要两个 harness 的本机登录态，为它单独维护一套环境不值**。这条理由框住的是**测试与门禁**那一层，它一个字不改：脚本层单测、两侧 eval、版式门禁仍然全部本地跑，合入门槛与关票门槛都不搬上 GitHub。

**发布不在这条理由的射程里**：结算 changeset 只要 node，版本对齐与 `agents/openai.yaml` 同步只要标准库 python，三样本机依赖一样都不沾。所以 `.github/workflows/release.yml`（#96）不与本 ADR 冲突，它只做发布：两道闸门（`agents/openai.yaml` 同步、版本三处对齐、有待结算的 changeset、工作树干净；结算后再验版本真的变了、changeset 都被吃掉、CHANGELOG 有这一节、tag 还没有）、`npm run version` 结算、提交打 tag、发 Release 并附离线兜底包。它不跑一个单测、不跑一件 eval、不跑门禁。

唯一一处越出「手动发版」的触发是：**那个 workflow 自己（或它调的两个脚本、`scripts/sync-plugin-version.py`、`package.json`）被改动的 PR 上干跑一次**，跑的仍然只是发布路径，不是测试。发布机器坏了只有在真发版那天才发现，代价比一次一分钟的干跑高。

ADR-0014 标题里也有「不做 CI」，那一条说的是**隐私守门**，理由是 CI 在 push 之后才跑、只能报警不能阻止（`:16`）。发布 workflow 不做守门，也不在它的射程里；隐私仍由本地两只钩子守。

「等第二台机器出现再议」那句仍然只对测试与门禁有效。
