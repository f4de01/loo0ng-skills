# 现场交付清单：在律师那台 mac 上装好 3.0 并初步跑通

**执行的人是开发者本人，在律师那台机器前现场做。** 不是交给律师自助的向导，也不是 agent 能替的：那台机器不在这里。律师只做三件事：点授权、念他在客户端里看见的东西、在拍板那一句里说话。

**这份清单没法预先跑通一遍。** 开发者手边没有 mac，凡是拿不准的步骤在正文里标成 `⚠️`，并在末尾的「拿不准的八处」里汇总。**现场照实记，别在这里猜一个答案写进去，也别就地想办法绕。**

## 怎么用

- **断网可用。** 要打的每一条命令、每一条预期回显都写在这份文件里，现场不用去翻 issue、翻仓库、翻网页。
- **每做完一步，把结果记进 `记录表.md` 的同号那一行**：命令、退出码、报错原文、当场怎么处置的。填不出来的写「未跑到（卡在 X.y：…）」，不要留空、也不要编。
- **失败本身就是结果。** 三条路的第 1 条不成就降第 2 条，不要去找 GitHub 令牌、不要让律师去登录、不要装什么把缺的东西补上。
- **不改任何 skill 正文。** 现场发现该改的，逐条记进记录表末尾的「带回去的票」，回来另开票。
- **这一版里没有票号。** 3.0 迁过一次仓库（ADR-0021），旧仓库的票号在这个仓库里指到的是别的东西，所以一概不引；要溯源就看正文里点到的 ADR 与 `docs/实测/`。
- **案件内容不进记录表、不进 issue、不进 commit message**（硬边界 1）。段 3 与段 4 用的是真案子，所以记录表里只记「第几步、退出码、卡在哪」，节点标题、当事人、文件名、路径一概不抄；要举例就写成 `<节点标题>`。

## 段 1　装

律师用的是 Codex 客户端。装法三条路，**从 A 往下降，成一条就停**，把走通的那条记进记录表 I6。

仓库名是 **`f4de01/loo0ng-skills`**（迁仓之后的名，ADR-0021），不是旧的 `lawyer-workbench-v3`。

### 1.1　路 A（首选，要网）

```bash
npx skills@latest add f4de01/loo0ng-skills -a codex
```

安装器会让你挑 skill 与目标 agent：**七件全选**，agent 选 codex。**安装源必须是公开仓库**：2026-09-09 那趟私有仓库没走通，最后是把仓库转成 public 才装成的（`docs/实测/mac-20260909/结论.md`），本仓库至今是 public，照上面这条直接装。

⚠️ **这一步在仓库还是私有的时候失败过三次**：一次报 `Error in the HTTP2 framing layer`（网络），一次报 `Authentication failed for https://github.com/...`（凭据），2026-09-09 那次没留回显。失败就照记退出码与报错原文，降到路 B，**不要去弄令牌、不要让律师登录**。

⚠️ 还有一个坑：上一轮的判据是「`~/.agents/skills/doit` 这个目录在不在」，而上上轮拷进去的还在，于是**明明失败却判成了成功，用的还是旧文件**。这一轮的判据改成看时间戳：

```bash
ls -la ~/.agents/skills/ | head -20
stat -f '%Sm %N' ~/.agents/skills/*/SKILL.md
```

装之前先看一眼这两条的输出，装之后再看一眼，**时间戳没动就是没装上**，不管安装器说了什么。

磁盘上有不等于模型看得见。三个来源对账，**不一致就三个都记，不要挑一个**：

## 段 3　起手一个案子

在一个**空目录**里走完一问二选、目录形状、清待归档、起手清单、拍板。这一轮是**真使用，不是 eval**，不承担任何门槛。

### 3.1　挑目录

跟律师一起挑一个空目录作案件工作区，**在这台机器上、不在任何仓库里**。⚠️ 别放 iCloud 同步的位置（「文稿」「桌面」多半是同步的），中途同步会把半截产物搬走。路径**不抄进记录表**（硬边界 1），记录表 S1 只写「已选定；不在仓库内：是 / 否；不在 iCloud 同步目录内：是 / 否」。

**目录里已经堆着律师手头的文件也行**，起手不因此停：它们一律视为待归档，由起手挪进 `待归档/`。要看清待归档那一步，反而该让它非空。

### 3.2　把这个目录在 Codex 客户端里打开成项目

⚠️ **客户端有时会把任务放进它自己的临时副本或 git worktree**，那个目录和律师看到的文件夹不是同一个。开工第一句先让它自报位置：

```
先跑一句 pwd && ls -a && git rev-parse --show-toplevel 2>/dev/null，把输出念给我，别做别的。
```

`pwd` 不是那个目录就停下来，换个开法（把文件夹拖进窗口、或用项目选择器重开），**不要在副本目录里起手**。记录表 S2 记它实际在哪（写成相对形状，不抄绝对路径）。

⚠️ 它要是问「这个文件夹不是 Git 仓库、要不要初始化」：**不要**。案件工作区不是仓库。

### 3.3　律师打起手那一句

由**律师本人**在客户端里打（这是他日后每天要做的动作，得让他打一次）：

```
$setup-case 这个案子归我了，在这个目录里起手，用破产那份预设图。目录里堆着的东西你一并归了。
```

⚠️ 先打 `$set` 让补全筛出来再选，别只打 `$`（列表太长，这七件不在首屏）。

后面那句自由文本是律师自己的话，**不用照抄**；要点只有一个：**要不要在这一句里就把「空图还是哪份预设图」说了**。说了它就不问，没说它会只问这一件（下一步）。**不必说领域名**：这一版起手不问领域，预设图自带名字。

⚠️ **`$名` 显式提及能不能触发隐式关闭的 skill，在 Codex 客户端上没测过。** 上一轮在 Codex **TUI** 上测成了（`allow_implicit_invocation: false` 的 skill 用 `$名` 照样触发），客户端是另一个壳。不触发就记原样反应，然后退到 3.3'。

3.3'（现场兜底）：把 `~/.agents/skills/setup-case/SKILL.md` 直接拖进对话或让它读一遍，再说「按这份起手」。**这是现场兜底，不是设计**，照实记成「显式提及未触发，用了兜底」，并开一张票带回去。

### 3.4　一问二选：空图还是哪份预设图

模型**只问这一件**。它先跑一条命令把两组列给律师看：

```bash
python3 ~/.agents/skills/domain/scripts/preset.py list
```

期望回显两组（开发机上 2026-09-15 实跑的形状）：

```
出厂（<domain 的 assets/预设图>）：
- 破产：12 个模块、72 个节点，模板 19 件
个人（<个人预设图根的绝对路径>）：
- （无）
```

两行括号里打的都是**展开后的绝对路径**（出厂那一行指进 skill 包，个人那一行是 `~/.loo0ng/预设图` 展开后的样子），上面写成占位是因为它随装法与用户名变，逐字对不上不是毛病。

**这是人的决定，让律师选。** 别替他选，也别因为只有一份出厂预设图就默认用它。他在 3.3 那句里已经说了名字（「破产那份」）就不该再问一遍。

⚠️ 这一版才有的三条事实，看它做得对不对：

- **旧版那个「三个选项：整份领域图／空图／定制图」没有了**，现在是二选：空图，还是哪份预设图（带归属）。
- **出厂预设图原位读、不拷出包**：整份拷进工作区的只有它的 `模板/`（19 件），`指引手册/` 留在包里给开发者导入用，**不进工作区**。旧版那种「把种子整份拷进 `~/.loo0ng/领域/<名>/`」的动作**已经没有了**：段 3 跑完 `~/.loo0ng/` 应当还是空的，那一处只住个人预设图，律师一句话另存时才会写它。
- **起手不跑雏形**：旧版起手会对 `指南/` 跑一次 `check`，这一版不跑。它真跑了就是走了旧路，记一张票。

工作区**不记预设图的路径**，只记名与归属（见 3.5 的 `AGENTS.md`）：路径每次按名与归属当场解析，包一升级绝对路径就死。

## 段 4　初步跑通一个节点

至少一个节点走完出一版加拍板。**这一段要看的是：黄色标在哪几处、审查报告四段齐不齐、落盘两件加图上一条条目。**

### 4.1　出一版

还是律师本人打：

```
$doit 出一版 <他要办的那个节点>。材料里没有的先照出，标黄留给我。
```

后半句同样是律师自己的话，不用照抄。**它写在这里是因为「生成不问缺事实」是设计**：材料里没有的槽留黄，模型不停下来问；律师读了黄色在对话里答一句，那句先填进新的一版、再追加一行到 `材料/律师说过的.md`。现场看它是不是真这么走。

⚠️ 挑节点时优先挑**有空白模板、材料齐**的那种：节点在图上的空白模板属性得指着 `参考/模板/` 里真在的一件，否则这一版出不了文书（它只回缺什么，不出件、图一字不动，**这不算生成失败**，下一句仍在这个对话里继续办这个节点）。`图视图.md` 里每个节点行都写着它的空白模板是哪一件或者「无」，照着挑。

⚠️ **一个对话一个节点**。律师一句话里连点两个节点时，第二个应当被挡下来，回显只有两行（「这个对话在办…」加「新对话的第一句：`doit 出一版 …`」）。要看这一条就让他故意连点两个。

### 4.2　这一段要看的四样（**最要紧的**）

一版出完，把下面四样**逐字抄进记录表**（只抄这四样的形状，不抄案件内容）：

1. **施加回显第二行**：`出件环境：解释器 …（python 3.9.6）；python-docx 1.2.0（与依赖清单钉的一致）`。它有没有被模型抄进审查报告「生成依据」段的末条？
2. **`代码留黄 N 处` 与 `高亮清单 N 处` 两行**：没填也没被高亮的槽由代码统一加黄，模型不逐个写；`高亮清单` 那一行起到末尾是下次重出认律师填没填的键。两个 N 都记下来。
3. **回显里有没有结论行**：**应当一行都没有**。看见「版式门禁」「通过 / 需人眼 / 不通过」「披露项」「须目验清单」中的任何一个字样，就是装了旧版本，或者是模型自己编了一段，当场停下来记票。
4. **收尾三段在不在**：`doit` 每次回答固定三段（落了什么 / 高亮了哪几处 / 下一句该打什么）。第二段要把这一版的高亮逐处报给律师，一处一行（段落号，单元格里的段带表格坐标），并说一句他有两条路：在 Word 里直接填（去不去黄都行），或者在对话里把事实给它、让它重出一版。

### 4.3　落盘两件与图上那条

```bash
ls -la <案件工作区>/文书/<模块>/<节点>/
```

期望**两件**同目录：`<节点标题>.docx` 与 `<节点标题>-审查报告.md`。

⚠️ **这一版没有 `-v{n}` 版本号，也没有同名的 `.md` 稿子**：一节点一份文书、不留版本，重出覆盖同一份。看见 `-v1`、`-v2` 或一份同名 `.md` 就是旧版本。

审查报告**四段固定、顺序固定**：**生成依据、高亮清单、施加原话、时限**。

⚠️ 旧清单里那五段（生成依据、存疑点、待律师裁定、版式门禁、时限）**已经不是了**：`存疑点` 与 `待律师裁定` 并进了黄色（黄色的意思只有一个「这里要律师动手」），`版式门禁` 整段退场，新增 `高亮清单` 与 `施加原话` 两段。**没有任何东西插在四段之前，也没有第五段**；看见「须目验清单」插在标题之后就是旧版本。

图上应当多一条生成条目，**两条**相对路径分别指着文书与审查报告，都真在：

```bash
python3 -c "import json,sys
g=json.load(open(sys.argv[1],encoding='utf-8'))
n=[x for m in g['模块'] for x in m['节点']]
print('模块', len(g['模块']), '节点', len(n), '条目', sum(len(x['条目']) for x in n))" <案件工作区>/图.json
```

要看那条条目本身的形状（不抄内容）就 `python3 -m json.tool <案件工作区>/图.json | tail -40`。

**一次生成 = 两件加这一条条目，缺一即生成失败。**

### 4.4　拍板

律师在**同一个对话**里说确认（「确认 X」）。图上再多一条确认条目，**原样存着他那句话**。下一个节点开新对话。

拍板也可以隔几天新开对话说，不要求那个对话先出过件；这一趟在同一个对话里说，省事。⚠️ 「看起来没问题」「这份行吗」**不是**确认，模型该问一句再落；它直接落了就记一张票。

### 4.5　整段走不通时的兜底

「出一版」整个走不通（模型不触发、填模板脚本起不来、客户端撞上限），**退到只打一份清单**：`fill.py list` 对任意 DOCX 都跑得动，律师手上现成的文书就能打一份。

```bash
python3 ~/.agents/skills/to-docx/scripts/fill.py list <律师现成的某份.docx> | head -20
```

这不是一次生成（不落 `文书/`、不写审查报告、不动图），但它能证明填模板脚本在这台机器上跑得动，也能让律师一眼看见「这份模板有哪些槽要填」。记录表 D5 记退出码与前几行的形状。

## 收尾

1. `记录表.md` 逐行填完，**每条命令的退出码、卡住的地方、当场的处置**都在。
2. **段 2 那部分誊进 `docs/实测/mac-<日期>/`**，结论的体例照 `docs/实测/mac-20260909/结论.md`（`mac-20260907/` 是那次的探针包，不是结论体例），作为 **ADR-0018 那一处空白的答案**，并给 ADR-0018 补一条附注。
3. **带回去的票**：现场发现要改 skill 正文或实现的，逐条开票，票里带上现场证据的原文。**不在现场改。**
4. 段 3 与段 4 产出的那份真案件图，**这一轮先别动它，也别拷进本仓库**。律师想把这一案的构成留给下一案，路是他一句话另存成个人预设图（住 `~/.loo0ng/预设图/<名>/`，在本仓库之外）；要把它变成出厂预设图是开发者回来走 PR 的事，那次 diff 须经第二双眼。
5. 案件内容一律不进记录表、不进 issue、不进 commit message（硬边界 1）。

## 交互脚本：现在没做，要不要做留给现场

那台机器方不方便跑 bash，现在答不了，所以**这一版只出清单，脚本的取舍留在现场**。

现场若判定要脚本，两条现成的：段 2 那十几条互不依赖、只读、失败不影响后面，是唯一值得当场拼成一个 `.sh` 的；段 1 与段 3、段 4 不要脚本化，那几步每一步都要开发者当场判断（哪条路降到哪条、报错原文意味着什么、要不要停下来记票），判断脚本化了就丢了。**现场做了哪个决定，连同理由记进记录表**，那是这一问的答案。
