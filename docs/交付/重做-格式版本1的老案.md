# 重做一个格式版本 1 的老案

2026-09-20 定（#97），对应 skills `0.7.0`。**一次性的转发件，那一案做完就作废。**

## 这一节不转：决定与理由

引擎只认格式版本 2，对更早的明写「没有升级路径，从预设图重新起手」。那句话仍然成立，**本件不推翻它**：这里做的不是升级，是在原地换一张新图。四条决定：

1. **不改代码。** v1 是存量而非增量：格式版本是在「领域离开图、时限进节点」那次升的（ADR-0016），今天的工作台只写 2。2026-09-20 在律师机上盘点，v1 只有 1 件。为 1 件不再产生的存量往 `setup-case` 的三条前置里加永久分支，不值当。
2. **原地重建，不搬工作区。** 真正会扫根目录的是 `setup.py init`，不是引擎；`graph.py init` 只写图与两份视图，`材料/`、`参考/`、`文书/` 一个都不碰。所以旧图改名之后直接调引擎，既有的归档成果原封不动。
3. **只补「已确认」。** 生成历史（出过几版、哪一版何时）留在改名保存的旧图里，不往新图搬：条目里的路径与时间要逐条对，工量成倍且易错，而律师要的只是「办没办完」这件事立刻准。
4. **对不上就建同名节点。** 旧图的模块与节点是当初自编的，未必对得上破产预设图；找不到同名的就在新图上 `add-node` 一个同名节点再补登记，宁可图上多出几个预设之外的节点，也不让模型去猜「哪个预设节点跟它等价」：确认是不可撤的记账，判错了得人工收拾。

**红线**：旧图只改名不删；除 `register` 挪那一份文书之外不搬动任何文件；找不到对应文书的确认节点一律跳过并列出来，不编。

做完要回收三样：新图的 `图视图.md` 头几行、卡片上那一行从红底报错变成正常一行、`$ask-loo0ng` 在这一案里问得出路。

**下面分隔线以后整段转给律师。**

跑完之后看一眼桌面卡片：这一案应当从红色那一行变成正常的一行，显示当前模块与下一个要办的节点。**没变就等 5 秒再看，还不变就告诉我。**
