# 试运行：卡片到底能不能读到一个案件

2026-09-19 拟。一次性的实机脚本，跑完就有结论，不是一份长期维护的文档。

**要转给律师的是下面「给律师的话」那一整节，到分隔线为止。** 分隔线之后是给开发者看的，不要一起转过去。

## 这一趟要答什么

律师那台 mac 上，卡片装好了、宿主起来了、扫描脚本在命令行下也跑通过，但**卡片从来没有在宿主里读到过任何一个真实案件**。这一段在 mac 上一次都没跑通过。一趟实机答四件：

1. 那几个更早起手的老工作区，图的**格式版本**各是几。引擎只认当前版本、遇到更早的明确拒绝且没有升级路径，所以这一条决定那几案是搬过来还是重新起手。
2. 宿主的 shell 执行在 mac 上找不找得到 `python3`。
3. 案件落在系统的隐私保护目录下面时，读取会不会被拦；被拦时的**真实报错文案**是什么。卡片仓库有一票在等这个文案，拿到之前不要照想象写。
4. 卡片能不能在宿主里真的列出一个案件。

顺带还有一件不花额外力气就能问出来的，见分隔线之后。

## 以下不转给律师

### 为什么这样写

- **「不要新建、不要删、不要搬」放在指令最前面**，是因为之前装卡片那次，agent 自作主张新建了一个案件文件夹又覆盖了既有设置，三个对不上的根目录就是这么来的。禁令写在头上，比写在末尾管用。
- **第 4 步第 4 问（有没有弹过允许框）是冲着「包外的家写不进」那条去的。** ADR-0032 是在「根因没坐实、也有意不查」的前提下写的；这一问不花律师任何额外力气，却可能顺手把沙箱那条推断坐实：**如果第 2 步第 4 小步弹了框、而第 5 小步的起手没弹**，就等于当场验证了「失败发生在子进程里、被脚本吞掉、外层 agent 看不见、所以没机会弹框」。
  - 弹了 + 起手没弹 → 沙箱那条推断成立，ADR-0032 的理由从推断升为事实。
  - 两处都没弹、第 4 小步也写成功了 → 那面墙是目录属主或权限，一次性修掉即可，ADR-0032 的决定不变（它本来就不依赖根因）。
- **没让他删那个误建的空文件夹。** 删除不可逆，放在一次找毛病的试运行里不值当；第 4 小步把它从设置里挪出去就够了。空文件夹留着不碍事，等实机通了再收拾。
- **用试运行而不是真案子**：起手会把当前目录里的东西全挪进 `待归档/`。新项目虽然是空的，但第一次跑没必要拿真案子冒险。通了他可以直接把这个项目删掉。
- **文案里不出现宿主与卡片仓库的名字**，按交付文档一贯的写法，只说「宿主」；具体名字在那边的 README 里。

### 拿回来之后做什么

| 拿到的 | 喂给 |
| --- | --- |
| 老工作区的格式版本 | 定那几案是搬还是重新起手（ADR-0031 的「后果」里挂着这一条） |
| 权限被拒的真实文案与 errno | 卡片仓库那张「权限失败与路径失败分开报」的票，它明写了在拿到真实回显之前不要实现 |
| 起手回显最后那一行 | 核对只读校验说的是「桌面卡片在看…」还是「没在看…」 |
| 卡片的照片 | 这一趟唯一真正要答的那件：卡片能不能在宿主里列出一个案件 |
| 弹框的有无与时机 | 沙箱那条推断，见上 |

**四样缺一样就别急着改代码。** 之前有一趟实机是「照做不是照记」，回来只剩口述结论，没有退出码也没有报错原文，那份记录自己把这条局限写在了正文里。
