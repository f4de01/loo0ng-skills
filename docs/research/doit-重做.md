# doit 重做记录（ADR-0022 的单子，第一件）

> 写于 2026-09-14。ADR-0022 给每件 skill 定了同一张单子：先写下律师在 0.1.0 里对它实际做了什么、卡在哪；列它调的每个脚本问「模型不用它能不能做对」；正文按 `writing-for-agents` 重写成步骤加完成判据加拍板点，命令行不进正文；被旧 ADR 否掉的想法直接试；改完毕业。`doit` 排第一，因为它最厚、最慢、律师碰得最多，且它决定三件参考 skill 还需要提供什么。本文按这张单子逐条记，证据全指旧仓库 `f4de01/lawyer-workbench-v3` 的 issue 与本仓库的文档，不含任何案件内容。

## 1. 律师在 0.1.0 里对它实际做了什么、卡在哪

**装与环境**（#83、`docs/实测/mac-20260909/结论.md`）：2026-09-09 开发者在律师那台 mac 前照现场清单装 0.1.0，仓库转 public 之后经 skills.sh 装上；四段走通，「整体功能没问题，律师已经在试用」。那台机是 mac + WPS + Codex 桌面应用，没有渲染通道。0.1.0 交出去时不含 PR #71 那三处正文加固。现场记录表没有逐条填，退出码与卡点只有口述。

**律师带回的三件需求**（#83、#84）：`doit` 出一版偏慢；可视化插件；泛化到所有领域。没有一件是图的形态问题；拍板与兜底登记两条路律师没报过问题（它们只有 eval 覆盖，没有律师侧的一手记录）。

**卡在哪，事后查出来是三处**：

1. **律师从来没真跑过 `doit`**（#142）。Codex 上 `policy.allow_implicit_invocation: false` 把编排 skill 整个剔出 skill 目录，`$doit` 因此不解析；律师那种「自称 skill 未加载、但对话实际调用了」两句都是真的：机制没加载，模型有时自己把 `SKILL.md` 读进来。所以律师跑的是「模型自拼四件参考 skill」那条路，也就是 #140 的 B 腿：三条腿里最慢、最不稳的一条（均 375.9 秒、同腿相差 1.8 倍、撞过重试环路）。「出一版慢」这句反馈多半来自这里。完整编排那条腿反而最快（206.8 秒），因为死顺序省掉了模型自己找路的往返。
2. **稿子是照模板重写的，不是照模板填的**（#141）。十轮样本十中：官方模板核心那一句（两个案号、申请人、负责人）整段消失，法院全称抹成「人民法院」，一轮自己编了日期；门禁十轮全报通过，它只量几何。grilling 查到唯一合格的一轮是唯一把模板文本留在眼前的一轮；病因重读是旧正文出了一道自相矛盾的题：「文书本体直接可提交、`XX` 一个不留」加「缺的事实照出、不停下来问」，手上没有事实时唯一的共同解就是把槽连句子一起删掉。
3. **慢在模型写长文本**（#123）：五轮计时模型占 94% 至 97%，其中七段写长文本占 55%（稿子、两份审查报告、收尾），开场整读占 24% 且贵在往返次数（14 次）不在字节数；四段 CLI 合计不到 7 秒。「正文最厚所以慢」量下来是反的：46 KB 正文只付一次 prefill，缓存命中 92% 至 97%。

**另两条与 0.1.0 之后的版本有关，一并记**：`doit` 20 KB 里 4 KB 是律师侧逐节点回流，机制的主人是 `domain`，归属错位（#124）；一个从空图长出来的新领域每个节点都没有空白模板，转换器却硬要一份，旧正文只有「三样全无」那一支、没有「只缺模板」（#137）。

## 2. 它调的每个脚本，模型不用它能不能做对

`doit` 自己没有脚本。它调的六样，按「模型不用它能不能做对」逐个问：

| 调的 | 用来做什么 | 模型不用它能做对吗 | 结论（doit 这一侧） |
| --- | --- | --- | --- |
| `graph.py`：`confirm`、`not-applicable`、`generate`、`add-node` | 往 `图.json` 追加条目、惰性建节点、重算视图 | 不能。条目只追加、状态只算不存、引擎守的几条规则（已确认不能不适用、只有已生成能确认、模块级不适用带入再逐个记）与视图重算，模型手改 JSON 做不对，改坏了也撤不回 | 留，守不可逆 |
| `md2docx.py` | 最小集 Markdown 以官方模板为载体转 DOCX | 不能。照抄模板表格的 `tblPr`、列宽、行高、合并单元格是 python-docx 的活 | 留 |
| `gate.py` | 版式门禁三档，通过与需人眼才 `--deliver` 落盘 | 不能。推算层与「不通过不落盘」正是要防模型自己拍板落盘 | 留，守不可逆 |
| `sketch.py docx-text` | 把 docx 打成文本 | 不能。harness 读不了 docx，而模板的文本正是稿子的骨架（第 1 节第 2 条） | 留；#134 说它该搬去 `to-docx`，doit 只说「调用 skill "domain"」，搬了改一个词 |
| `archive.py list` / `move` | 收件箱搬到四格 | 能。一次搬运，不改名、不覆盖、子目录相对路径原样，模型用文件操作做得对；它守的不是不可逆的东西 | doit 不要求经它；去留归 `filing` 重做时定 |
| `statement.py` | 律师一句话落成 `材料/律师陈述/` 下一个文件 | 能。六字段一个文件，落盘后只读是次要的；doit 要的只是「一条一文件、按文件引用」这个约定 | 同上，归 `filing` 重做时定 |

`tests/doit/test_seeds.py` 验的是种子「兜底」的状态，不是脚本，留。

## 3. 正文怎么重写的

从 20,248 字节到 10,986 字节。按 `writing-for-agents` 的杠杆逐条说：

- **三个分支各是一段步骤，每步一句完成判据。** 出一版九步（归档、一个对话一个节点、建节点、模板在不在、整读、骨架成稿、转换与门禁、三件、条目）；兜底登记四步；拍板两条。判据写成可数的：「律师点了几个节点，回复里就有几段」「稿子与模板逐段对得上、骨架段一段不少」「三件齐全、版本号一致」。
- **命令行全部出正文。** 图、归档、陈述、转换、门禁、打文本各一句「调用 skill "xxx"」，`--help` 与各自正文是命令的权威。旧正文里六段命令行原样抄的是邻居的接口，邻居一改就陈旧。
- **归属那一问搬回主人那里**（#124 裁定 a）：4 KB 一个字不剪，搬进 `domain/references/回流.md` 律师侧那一节；doit 只留「确认落盘后看来源，是『案件』就调用 skill "domain"」这一句加一行指针。`tests/domain/test_isolation.py` 里对 doit 正文那四个词的断言随之改成断触发条件与 `回流.md`。
- **封条作废**（ADR-0022）。旧正文里三处「什么样的回复算没走这一步」「发出去之前数一遍」是 #65、f19b0cd 两次 eval 抖动的封条，删掉，换成那一步的完成判据；「三条留痕规则」并进拍板一节；「什么算一次生成」并进第 9 步。用例一个不动，它们断的是终态（文件、条目、活图字节），不是措辞；重写后的正文以它们为门槛（第 6 节）。
- **正向表述。** 「不删句、不抹法院名、不编事实」改成「骨架段保持原句；槽要么是值要么是空位」；硬护栏（确认永不由模型推断、阈值不调、临时件不手拷）保留，每条都配着要做的那件事。
- **领导词**：回合、整读、骨架、槽、三件、拍板、留痕、兜底。

## 4. 这次直接试的、被旧裁定挡过的想法

1. **模板文本就是稿子的骨架，写稿是改骨架**（#141 的减法修法，当时未验证）。第 6 步「骨架成稿」把稿子定义成对模板文本做四件事：填槽、条件段取舍、删说明段、落律师的要求。缺的事实**留空位**，句子原样保留：这一条同时消掉了旧正文那道自相矛盾的题。`to-docx` 正文里「`XX` 一个都不能留」照旧，空位不是 `XX`，门禁的「模板占位残留」不拦全角空格。验收口径照 #141：同节点同模板跑六轮，骨架段的句式在、缺的事实留空或进待裁定。
2. **合并读取**（#133 查明 ADR-0008 没禁）：第 5 步写明「几份能一次读的就一次读进来」，冲的是开场整读那 24%。
3. **只缺模板单独一支**（#137 的第一个候选）：第 4 步「模板在不在」，没有空白模板就只报缺什么与模板可从哪来，不出件、图一字不动；有模板缺材料照出。旧的「三样全无」取消：有模板就有骨架，材料空着照样能出一版留空位的稿。ADR-0019 那句「入场费降到零」在这一版照实成了「每个要出件的节点各供一份空白 DOCX」；转换器要不要自带素载体归 `to-docx` 重做时定（第 5 节）。
4. **没有再加约束**。#141 方向重置写明「凡提议加约束，先说明它去掉了模型的哪一个改写理由」：这一版加的每一条都是减法或给路（骨架、空位、合并读取、缺模板那一支），一条门禁判据没加。

**没动的**：`disable-model-invocation` 双旗（#142 是三件编排 skill 共同的事，改它要动 `AGENTS.md` 结构不变量 3，另立 ADR，不在一件 skill 的重做里）；一个对话一个节点（ADR-0008、ADR-0010 的理由仍成立，律师没在这条上卡过）；生成不问缺事实（律师裁定「尽量出一个律师可改的版本」）；收尾三段（ADR-0008 入口收尾同形；#133 倾向不动）。

## 5. 给三件参考 skill 的需求单

`doit` 重写后对邻居的要求，轮到它们重做时对着这张单子改：

- **to-docx**：(a) 给「模板打成最小集骨架」一条路（#141 grilling 提的 `--show-template`，输出段落、`:left:` / `:right:`、管道表，占位与 `【…】` 原样带出），今天 doit 用的是 `domain` 的 `docx-text`，输出是纯文本、不带最小集标记，模型要自己加；(b) `docx-text` 搬过来（#134）；(c) 无模板时的载体要不要自带（#137），doit 这一版按「没有就出不了件」写，若 `to-docx` 决定自带素载体，doit 第 4 步改成「没有就用素载体」一句；(d) 正文里「`XX` 一个都不能留」旁边写上「槽留空位」的口径，与 doit 第 6 步同一套。
- **domain**：律师侧逐节点回流的全部规矩现在住 `references/回流.md`，`SKILL.md` 只留指针；`docx-text` 搬走后 doit 第 5 步「调用 skill "domain"」改成 `to-docx`。
- **graph**：doit 用到的只有 `add-node`、`generate`、`confirm`、`not-applicable` 四个子命令与视图里的「来源」一列；接口不动。
- **filing**：doit 要的只是两个约定：归档的四格去向与「不覆盖」；陈述一条一文件、按文件引用、`--reply` 指向审查报告。两个脚本留不留由它自己按「模型不用能不能做对」定（第 2 节的判断是都能）。

## 6. 门槛与毕业

按 ADR-0022，`in-progress/` 里的件提交前只跑 `check-skill.sh`、`check-wiring.sh` 与 `claude plugin validate`；毕业时它的单测与 eval 重定。这一件的 eval 重定结果：十二个带 `skill: doit` 的用例（办节点出一版、兜底登记、拍板、换节点被拒、不通过收尾、需人眼落盘、模块不适用、逐节点回流四件、指针指着种子被拒）全部保留，它们断的都是终态；用例说明里引旧正文步号的句子是描述，不改。

2026-09-14 在新正文上跑了一遍 Claude Code 侧（junction 路线，`--claude-plugin ""`）：十二件全绿，其中办节点出一版 33 回合 187 秒、不通过收尾 31 回合、需人眼落盘 28 回合，其余六件 5 到 20 回合。第一轮里六件撞上 API 层瞬时错误（一回合、几秒即退、`is_error` 而 subtype 仍为 success），重跑即过。Codex 侧没跑：开发机 `~/.agents/skills/` 改造期不挂 junction，替身提示词读不到 `doit/SKILL.md`；毕业前要在 Codex 侧补一遍。

**这一件暂不搬回 `engineering/`**，理由只有一条：`doit` 自己没有脚本，每一步都经 `graph`、`filing`、`domain`、`to-docx` 落盘，而那四件还在 `in-progress/`。毕业即进 `plugin.json`，插件路线的机器 `claude plugin update` 之后装到的会是一件调不到任何邻居的 `doit`，比空包更坏。所以搬回、进插件清单、根 README、`docs/engineering/doit.md` 这四步等四件参考 skill 也毕业时一起做；那时 doit 的正文按第 5 节的落实情况改几个词就够。
