# 工作流重做需求单（从接案到第一份文书）

> 写于 2026-09-14。起因：`doit` 按 ADR-0022 的单子重做过一轮（`docs/research/doit-重做.md`），但律师反馈的不是某一件 skill 的措辞，而是整条工作流不合他的用法：材料堆积归档不动、起手问得太多、审查报告没人读、对话里给过的东西下一个节点还得再给。本文是一轮 grilling 的产物，记的是设计裁定与理由，覆盖七件 skill；逐件重做时对着它改，改完回头核这份单子。不含任何案件内容。

## 1. 律师的新工作流

1. **接案**。Codex 创建项目，项目目录就是案件工作区，一项目一案。律师把手头文件丢进目录根或 `待归档/`。
2. **起手** `setup-case`。只问一件事：空图，还是哪份预设图（列表分出厂、个人两组）。不问领域名。落目录结构；预设图整份拷入（模块、节点、时限句、整个模板目录）。目录里已有的文件走归档清单：有文件要归才有确认点，没有就直接收尾。不跑雏形。环境配置这一轮不做，正文留一节的位置。
3. **出件** `doit 出一版 X`（新对话）。先清待归档，不问。整读：`归档索引.md`、`材料/` 全部（含 `律师说过的.md`）、`参考/指南/` 全部、本节点的模板、本节点当前那份文书、**同模块里排在它前面且已确认**的文书；其他模块不读，未确认的不读，律师点名的加读。以模板为底填差量：填槽、条件段取舍、删说明段、落律师的要求；材料里没有的槽保留模板原占位并加黄色高亮，没把握的句子也高亮。过门禁后覆盖落盘：一节点一份 docx 加一份审查报告，图上追加一条生成条目。收尾说高亮了哪几处、下一句打什么。
4. **律师处理高亮**，两条路任选。(a) 在 Word 里直接填，去不去黄都行。(b) 在对话里给事实或补材料，让模型重出。重出以当前 docx 为底：脚本逐个比对上一次的高亮清单，文字变了的是律师填的，去黄、不碰；没变的模型填；律师点名的位置照改、改完不加黄。律师的改动默认正确，不跑门禁。对话里说的事实先填进文书，再顺手追加一行到 `材料/律师说过的.md`。补材料走归档再重出。
5. **拍板**。「确认 X」或「X 不适用」一句话落条目，原话进条目。可以在几天后的新对话里说：默认一个对话一个节点，但同一节点的出件与确认可跨对话。确认之后不再问回流。
6. **兜底**。「X 我自己写好了」：文件覆盖到节点目录，追加一条来源记律师的生成条目，审查报告一行「律师自写、未跑门禁」。
7. **复用**。案子办完说一句「存成预设图叫 Y」：图剥掉全部条目与不适用记录，只留构成；标题里的当事人、案号由模型列出改法回显，律师一句话后落；模板整份拷走；落到本机个人预设图目录。

### 律师给过一次的东西

原则不是「不许再给」，是**不给也能出**：材料落过盘、文书出过件、对话里说过的话，下一个节点一句 `doit 出一版` 就够。为此补三样：整读加入同模块在前的已确认文书；对话里的事实一律落盘；审查报告逐值记来源。律师愿意再给一遍也行，那只是冗余。

**接受的代价**：同模块排在前面的节点若律师跳过没办，后节点读不到它，相关的槽留黄色，由律师补。靠一个对话一个节点尽量让文书按图序完成。

## 2. 目录与分发

### 工作区

```
<工作区>/
├── 图.json  图视图.md  图视图.json  归档索引.md  AGENTS.md  CLAUDE.md
├── 待归档/               律师随手丢；归档 skill 清
├── 材料/                 本案事实原件；归档可建主题子目录
│   └── 律师说过的.md     对话里给出的事实与选择，一句一行（日期、原话）
├── 参考/模板/            空白模板；起手时从预设图整份拷入，律师自加的也放这里
├── 参考/指南/            法院要求文件、指引
└── 文书/<模块>/<节点>/
    ├── <节点>.docx
    └── <节点>-审查报告.md
```

- **版本不迭代**：重出覆盖同一路径。律师不追溯版本。图的生成条目仍只追加（ADR-0003），留痕第几次、何时生成，路径不变；视图显示最近一次。
- **材料不按模块分**：一份原件常服务多个节点。归档 skill 只允许建主题子目录。
- **模板与指南两层**，不平铺。图上「空白模板」属性只记文件名，文件在 `参考/模板/` 下。
- 派生视图仍两份：律师读的 `图视图.md` 与可视化插件读的 `图视图.json`，状态只在引擎里算一次，插件不自己算（可视化插件定为独立于 Codex 与 Claude Code 的应用，便签页面形态，第一项内容是节点状态与进度）。`材料/律师陈述/` 不再有。
- 目录名用节点标题；标题里的斜杠、冒号由引擎换成全角。
- `AGENTS.md` 指针块只记「预设图：<名>，<出厂|个人>」两个字段与入口名、「本工作区对 skill 仓库只读」；**不记路径**。0.1.0 记包内绝对路径的教训：包一升级路径就死。需要路径时由 domain 按名与归属当场解析。

### 预设图两处两归属

| 归属 | 位置 | 谁写 | 升级时 |
| --- | --- | --- | --- |
| 出厂 | 包内 `assets/预设图/<名>/`（`领域图.json`、`模板/`、`指引手册/`） | 开发者经 PR | 整个被换掉，原位读，不拷出包 |
| 个人 | `~/.loo0ng/预设图/<名>/`（`领域图.json`、`模板/`） | 律师经「存成预设图」 | 碰不到 |

- 出厂预设图**不拷到本机目录**：更新即删旧装新，包外没有残留；个人预设图在另一个目录，物理上碰不到。
- 个人预设图与出厂重名拒，让律师换名（起手列表两组同名会混）。
- 出厂种子里的指引手册留在包内给开发者导入用，不拷进工作区。
- 起手时整份拷入工作区之后，案件图**自足**：前方只从案件图的条目算（没生成的在前方，已确认与不适用的不在）；惰性带入、活图、种子、`home`、入库、逐节点回流整套退场。律师加节点走 graph 的 `add-node`，想带回预设图就整份另存。
- 时限句随起手拷进案件图的节点；案件图仍拒律师写时限（ADR-0016 的理由不变，只是来源从运行时查预设图改为起手拷入）。

### 受影响的既有裁定

ADR-0012、0013、0019、0020 描述的机制退场，与 ADR-0001 至 0021 一样降为参考（ADR-0022 已定）。`AGENTS.md` 结构不变量 5「领域目录三样」要改成预设图的形状，另立一条 ADR 记这次重做的裁定。硬边界两条不动：预设图的个人目录在仓库外，办案会话对仓库仍只读。

## 3. 逐 skill 改动

### setup-case

- 前置改为「当前目录没有 `图.json`」，不再要求空目录；目录里已有的文件一律视为待归档。
- 一问二选：空图或哪份预设图，列表分出厂、个人两组。不问领域名。
- 预设图整份拷入：图、时限句、整个模板目录到 `参考/模板/`。
- 指针块只记预设图名与归属。
- 起手清单并成一张：归档去向、既有成品登记、同名冲突三张表一次回显、一句话拍板。有文件要归才有这个确认点。
- 删「指南非空跑雏形」那一步。
- 正文留「环境」一节的位置，本轮不填（自检、安装都不做）。
- 收尾三段形状不变。

### filing

名字沿用，正文重写，能力加强。

- **输入**：`待归档/`，或律师指的任意目录（含工作区外）。待归档内移动，外部目录复制、原件不动。外部目录不经待归档中转，直接判去向。
- **去向三格**：`材料/`（本案事实原件）、`参考/模板/`（空白件）、`参考/指南/`（要求文件）。拿不准的留在待归档并说一句为什么。
- **确认点**：律师一句话发起的整理与起手末尾那次，先回显「文件、去向、一句理由」清单，律师拍板再搬；`doit` 开场清待归档不问。没有文件要归就不出清单。
- **去重**：按内容哈希，已有的报「已有」不搬。同名不同内容留原处，清单里单列「同名冲突」让律师定。不改名，不覆盖。
- **索引**：维护工作区根 `归档索引.md`，一行一件：相对路径、一句话是什么、归档日期、「文本」列（现在全是「原件」，将来 OCR 或 PDF 转出的 md 放原件旁同名加 `.md`，这一列指向它）。出件整读先读索引。
- **不做**：解压、识图、OCR、PDF 转文本（后两样是后续版本，正文留位）。
- **陈述 CLI 删**。对话里的事实由 `doit` 追加到 `材料/律师说过的.md`，不经 filing。
- 归档脚本留不留，按「模型不用它能不能做对」定；去重与索引的哈希与写表是脚本做得更稳的部分。

### domain

改成**预设图的家**。

- 按名与归属解析路径；列出厂、个人两组供起手用。
- **另存预设图**：从案件图剥条目与不适用，只留模块、节点、空白模板、时限；模板从 `参考/模板/` 整份拷；标题去案件化由模型回显、律师拍板后落；与出厂重名拒。
- **开发者导入**：模型整读一个来源（目录树、指引手册、别的案件图），按现有雏形 JSON 格式写雏形，`check` 判重回显、拍板后 `apply` 写进一份新的个人预设图，模板拷到它的 `模板/`；再手动拷进仓库 `assets/预设图/<名>/` 走 PR，第二双眼审 diff。来源那一步不写死规则，正文给来源示例。目录树里没有时限句，导入后对指引手册再跑一次雏形补。**律师不可导入。**
- 律师从空图建图时可用「从这份指南里提节点」，雏形机制保留，只是不再挂在起手里。
- 删：`references/回流.md`、`intake`、`home`、活图与种子那套；`docx-text` 搬去 to-docx。

### graph

- `init --empty` 与 `init --preset <名> --owner 出厂|个人`，`--full`、`--from`、`--domain` 删。
- 空白模板属性只记文件名。
- 时限随 `init --preset` 拷进案件图；案件图对律师写时限仍拒。
- 前方只从案件图算。
- 加 `export-preset`：剥条目与不适用，只留构成。
- 生成条目两条相对路径（docx、审查报告）；条目只追加不变。
- 目录名转义规则由引擎定。
- 其余子命令与规矩不动：节点永不删、不适用是终态、已确认要改就重出、模块里有已确认的节点整个模块不能不适用。

### doit

- 一个对话一个节点保留为默认；出件与确认可跨对话，新对话里说「确认 X」直接落。
- 出件步骤：清待归档（不问）→ 一句话两个节点停第二个 → 建节点（不在图里则 `add-node`）→ 模板在不在（`参考/模板/` 里挂到它的；没有就只报缺什么，不出件）→ 整读（范围见第 1 节第 3 条）→ 读清单、写差量（填、按原文换、删段、加高亮、去高亮；不重写整篇；没填的槽由代码留黄，模型不写；模板自带的高亮解决了要显式去黄）→ 门禁 → 覆盖落盘两件 → 追加条目 → 收尾。
- 重出以当前 docx 为底；高亮比对由脚本做，模型只写仍高亮处与律师点名处。
- 对话里的事实先填、再追加一行到 `材料/律师说过的.md`，不回显、不中断。
- 兜底登记缩成三步：覆盖到节点目录、追加来源记律师的条目、审查报告一行。
- 拍板只剩落条目，删回流那一问。
- 收尾三段保留，「你现在该拍板什么」改为列高亮了哪几处。
- 命令行仍不进正文，各步一句「调用 skill "xxx"」。

### to-docx

大改或重做，方向是**填模板**（模型只出差量，不重写整篇，结构上消掉「删句、抹法院名、编事实」）。这条路 2026-09-14 已在 python-docx 1.2.0 上以原型验证，结论「行，两处有条件」，六条答案、最小代码形状与已知行为都在 `docs/research/to-docx-差量原型.md`，原语从分支 `prototype/fill-template` 的 `fill.py` 搬，不重写。下面只写需求，细节指向那份。

- **打清单**：脚本把模板或当前 docx 的正文打成带编号的清单。编号是全文 `w:p` 的序号，单元格里的段落带表、行、格标签；一段里的槽按占位正则从左到右编号；模板自带的黄色高亮（19 件官方模板里有 24 处，标的是条件块与提示句）与「（注：…）」说明段都在清单里标出来。占位正则的形状随模板走，律师自己的空白模板用别的占位习惯要能加。指南整读用同一条不带标记的输出，`docx-text` 并进这里。
- **差量五种**：填（`fill`，可带 `highlight: true` 表示填了但没把握）、按原文换（`replace`，给不带任何标记的提示文字与条件段用，原文在段里须唯一）、删段、加高亮、去高亮。差量落在段落字符区间上，不落在 run 序号上（占位在 16 件模板里横跨 run）。模型解决了的模板自带高亮要显式去黄。
- **代码统一留黄**：施加完后没被填也没高亮的槽由代码一律加黄，模型不逐个写。
- **原地施加保几何**：表格的 `tblPr`、列宽、行高、合并单元格逐字节不变，槽外每个字符的 run 格式不变。槽所在 run 含脚注引用、图片、域代码时拒绝改动。元数据照现有 `clear_metadata` 清。
- **门禁两样**：改动段没有残留占位且不在高亮里（只查改动段，排除高亮里的）；几何不超阈值（直接复用现有 `gate.py` 的推算层，渲染层照旧机会性加信）。现有 `static_checks` 里全篇查占位与模板说明段残留两条删，元数据、页脚 PAGE 域、表格接 sectPr 三条留。律师改过的位置不查。
- **高亮清单**：出件时一处一行记进审查报告：段落号（只作提示）、记录时整段文字、高亮处原文；不记偏移。重出时脚本比对：段落按整段文字模糊匹配，段内按原文在记过的多重集合里消一个；文字变了的去黄不碰，没变的仍待填。**已知行为**：律师在记过高亮的段落里自己新加的黄，重出时会被去掉；律师把整段重写到认不出时，该段的高亮一律不动。这两条写进 to-docx 正文。
- **审查报告四段**，全是机器留痕、不要求律师读：生成依据逐值记来源（「案号 ← 文书/…/….docx」，一槽一行）、高亮清单、门禁原话、时限。
- Markdown 最小集与转换器退场。审查报告与差量格式的 references 归它。
- 随包脚本要跑得动 python 3.9（原型只按 3.9 语法解析过，没在 3.9 解释器上真跑），后端仍钉 python-docx 1.2.0。

### ask-loo0ng

- 入口表同步（增删改名照结构不变量 2）。
- 「下一步做什么」只读案件图。
- 扫 `文书/` 下的 docx，发现高亮已清、节点未确认的列在第一行，提醒律师说一句确认。

## 4. 裁定与理由（按 grilling 的顺序）

| # | 裁定 | 理由 |
| --- | --- | --- |
| 1 | 起手仍是独立一步，建在当前目录 | 身份标记与目录结构只落一次；并进 doit 会拉长第一次出件的对话 |
| 2 | 不问领域名 | 案件图自足后领域名只是标签；预设图自带名字 |
| 3 | 律师自建的图可存成个人预设图 | 一个概念覆盖两种来源，替代活图与逐节点回流 |
| 4 | 出厂原位读、个人另一目录 | 更新即删旧装新，物理上碰不到律师的图 |
| 5 | 模板与指南在 `参考/` 下两层 | 律师的裁定；平铺会让归档判断丢一个维度 |
| 6 | 版本不迭代，覆盖 | 律师不追溯版本；条目只追加保留留痕 |
| 7 | 预设图整份拷入，案件图自足 | 律师看视图要看整个流程；惰性带入在整份之后没有东西可带 |
| 8 | 指针只记名与归属 | 0.1.0 绝对路径升级即死 |
| 9 | 归档输入可指任意目录，外部复制 | 堆积物不在工作区里；原件不动 |
| 10 | 律师发起的归档走清单，组内不问 | 上百件判错的代价是找不到文件；开场几件新件不值得停 |
| 11 | 去重与索引做，解压与识图不做 | 索引是压开场整读往返的入口；OCR 与 PDF 转文本是后续版本 |
| 12 | filing 名字沿用 | 换名要改四处登记，换不出价值 |
| 13 | 雏形从起手里删，弱化到开发者与从零建图 | 多数案子起手就没有确认点 |
| 14 | 导入由 agent 能力完成、律师不可用 | 来源形状定不下来，写死规则会错；产物经 PR 进仓库 |
| 15 | 高亮只标律师要动手的两类 | 高亮的意义是「你要改这里」，混进只读信息就失去意义 |
| 16 | 审查报告降为机器留痕、名字不改 | 对话下一回合看不见，依据与门禁原话得有文件；不再要求律师读 |
| 17 | 律师的改动默认正确，模型只写高亮处 | 不必判断哪些是律师改的；律师件不跑门禁 |
| 18 | to-docx 走填模板 | 差量输出结构上消掉重写病，也去掉最大的一段长文本写作 |
| 19 | 确认仍是对话里一句话 | 律师专权、留痕；黄色没了不等于认可全篇 |
| 20 | 整读同模块在前的已确认文书 | 读全部会随案子累积越来越慢；只读点名的又把工作量推回律师 |
| 21 | 对话里的事实一律追加一行落盘 | 零判断零往返；陈述机制那套性质、取代链、标题整个退场 |
| 22 | 审查报告逐值记来源 | 与高亮清单是同一份东西的两半：填了的记来源，没填的记位置 |

## 5. 明确不做的

环境自检与安装、解压、OCR、PDF 转文本、版本追溯、雏形起手、律师侧导入、回流、陈述机制、图上的依赖边、门禁对律师改动、出厂与个人预设图的合并。

## 6. 门槛

按 ADR-0022：七件都在 `in-progress/`，逐件重做，提交前跑 `check-skill.sh`、`check-wiring.sh`、`claude plugin validate`；毕业时单测与 eval 对着本文第 1 节重定。改动顺序建议：graph（接口是别人的地基）→ to-docx（doit 的第 6、7 步等它）→ filing → domain → setup-case → doit → ask-loo0ng。
