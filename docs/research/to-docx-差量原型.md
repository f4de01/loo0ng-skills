# to-docx 差量路线原型：六条结论

> 写于 2026-09-14。验证 ADR-0023 第四条「出件走填模板差量」在 python-docx 1.2.0 上走不走得通。原型代码在分支 `prototype/fill-template` 的 `prototype/fill-template/`（`fill.py` 是可搬走的逻辑，`demo.py` 对包内 19 件模板把六个问题跑一遍，`demo-output.txt` 是跑出来的原话），不进 main。测试内容全部合成。回到主线后按本文改需求单第 3 节 to-docx 那段，再打 `to-spec`。

**总结论：行，两处有条件。** 19 件模板逐件打清单、逐件全填与留黄，表格几何逐字节不变、槽外每个字符的 run 格式不变；Word 打开并渲染无修复；重出比对在律师增删段落后仍认得出哪处填过。有条件的是第 5 条（高亮清单的键）与第 1 条里占位正则的覆盖面。

## 1 打清单：行

- 编号：正文里全部 `w:p` 按文档顺序编 `p0、p1…`，单元格里的段落也在序列里，清单行前标 `[表1 行2 格1]`。同一份 docx 编号稳定；表格结构是 `body.iter(w:p)` 的自然顺序，不另立坐标系。
- 槽：一段里按占位正则从左到右编 `#1、#2…`，清单里写成 `⟦1 XX年X月X日⟧`；已高亮的区间写成 `⟪…⟫`；「（注：…）」开头的段前标 `[说明]`。19 件共 754 个槽。
- 清单一行的样子：

```
p2 苏州工业园区人民法院于⟦1 XX年X月X日⟧作出⟦2 （20XX）⟧苏0591破⟦3 XX⟧号裁定书，裁定受理⟦4 XX⟧公司（债权人名称）申请…
p9 [表1 行3 格2] ⟦1 XX年X月X日⟧
p0 [说明] ⟪（注：无未结诉讼，以财产不足以支付破产费用而终结时，适用本模板）⟫
```

- **条件（占位正则的覆盖面）**：模板里的槽形状比预想多。除 `XX`、`（20XX）`、`XX年X月X日`、`【…】`、下划线串外，还有带量词的单个 X（`X家`、`X元`、`X名`）、整段的条件块 `【若有异议：…】`（长于 40 字）、以及不带任何标记的提示文字（`（债务人名称）`、`（如有）`、`律师事务所/会计师事务所`）。前两类原型已收进正则；第三类正则收不了，靠模型用 `replace` 按原文改，这是 doit 正文要写的事。正则的形状随模板走，将来律师自己的空白模板用别的占位习惯要能加。
- **一个意外**：19 件官方模板里有 24 处自带黄色高亮（3-1、3-2、4-1、4-2、4-3、5、7-1、7-2、9-1），标的正是条件块与提示句（`【写明未结诉讼情况】`、`（若有诉讼）`、`综上`）。这与「高亮 = 这里要律师动手」的语义恰好一致：模型解决了的要显式 `unhighlight`，没解决的自然留给律师。清单里 `⟪⟫` 让模型看得见它们。

最小代码形状：

```python
def paragraphs(doc): return list(doc.element.body.iter(qn("w:p")))          # 编号 = 下标
def text_of(p): return "".join(Run(r, None).text for r in p.iter(qn("w:r")))
def slots(p): return [(m.start(), m.end(), m.group()) for m in PLACEHOLDER.finditer(text_of(p))]
```

## 2 原地施加：行

- 关键事实：**占位在模板里大多横跨 run**（`X` + `X年X月X日`、`（20` + `XX` + `）苏0591破`），19 件里 16 件有这种情形。所以差量不能落到 run 序号上，只能落到「段落字符区间」上。
- 原语只有一个：`replace_range(p, start, end, new_text, highlight)`。先把 run 在区间两端切开（深拷贝 run、各留一份 rPr），再只动区间里的 run：填字时第一个 run 的文字换成新文字、其余删掉，格式取自第一个 run；加去高亮时逐个 run 设 `w:highlight`。区间外的 run 一个不碰。
- 填、按原文换、删段、加高亮、去高亮全是这个原语的调用；删段是 `p.getparent().remove(p)`，单元格里最后一段与带 `sectPr` 的段改成清空文字。
- 验证：19 件各跑两遍（只留黄；754 槽全填「某某」），施加前后比 `tblPr`、`tblGrid`、每行 `trPr`、每格 `tcPr` 的 XML 逐字节相同，槽外每个字符的 rPr（去掉 highlight 后）相同。「苏州工业园区人民法院于XX年X月X日作出…」这种固定文字与槽混在一段的，填后每个 run 仍是仿宋 sz=32。Word 经现有 gate 的渲染层打开 1-2 与 1-1（五张表）均无修复，实测行高与模板一致。
- **条件**：被切开或换字的 run 若含 tab、换行以外的子元素（脚注引用、图片、域代码），拷贝时会跟着复制或丢失。19 件模板的槽所在 run 里没有这些；实现时对这种 run 拒绝改动即可。
- 元数据（作者、最后修改者、上次打印时间）原型没清，现有 `clear_metadata` 照搬即可，否则门禁静态项会报。

最小代码形状：

```python
def _cut(p, k):                       # 把落在字符 k 处的 run 切成两个
    for r, s, e in _runs(p):
        if s < k < e:
            t = Run(r, None).text; left = copy.deepcopy(r); r.addprevious(left)
            Run(left, None).text = t[:k - s]; Run(r, None).text = t[k - s:]; return

def replace_range(p, start, end, new_text=None, highlight=None):
    _cut(p, end); _cut(p, start)
    covered = [r for r, s, e in _runs(p) if s >= start and e <= end and e > s]
    if new_text is not None:
        Run(covered[0], None).text = new_text
        for r in covered[1:]: r.getparent().remove(r)
        covered = covered[:1]
    if highlight is not None:
        for r in covered: Run(r, None).font.highlight_color = WD_COLOR_INDEX.YELLOW if highlight else None
```

差量的形状（模型写的）：

```json
[{"op":"fill","at":"p2#1","text":"2026年1月1日"},
 {"op":"fill","at":"p2#8","text":"2025","highlight":true},
 {"op":"replace","at":"p2","old":"XX公司（债权人名称）","new":"某甲公司"},
 {"op":"delete","at":"p14"},
 {"op":"highlight","at":"p3","text":"没把握的那句"},
 {"op":"unhighlight","at":"p7"}]
```

同一段的改动按区间从后往前施加，偏移互不影响；`replace` 的 `old` 在段里须唯一；施加完后没被填也没高亮的槽由代码一律加黄（`highlight_rest`），模型不必逐个写。

## 3 重出的比对：行

- 模拟：出件留黄 17 处 → 律师在 Word 里一处填了字并去黄、一处填了字没去黄、最前面插一段并在里面自己标黄两个字、删了一段「特此报告」→ 比对。结果：填了没去黄的那处「去黄」；填了也去黄的报「律师已填并去黄」；其余 15 处「仍待填」不动；律师自己标的黄报「不在记过的段落里，不动」。清单编号整体飘了一位，比对不受影响。
- 律师改动不经门禁：`compare` 只做去黄，不碰文字。

## 4 门禁两样：行

- 第一样「改动处没有残留占位且不在高亮里」：对 `apply` 回的改动段落号逐段查槽是否都落在高亮区间里，十几行。只填一槽不留黄时报 10 处残留，留黄后通过。
- 第二样「几何不超阈值」：现有 `gate.py` 的推算层可以直接复用，`gate.estimate_ranges(gate.Docx(path))` 加 `gate.judge(...)` 两个调用，渲染层照旧机会性加信。原型就是这样 import 的，没改一行。
- 现有 `static_checks` 要缩：它对全篇查占位（留黄件必报「模板占位残留」）与模板说明段残留，这两条与差量路线冲突，改成只查改动处且排除高亮里的；元数据、页脚 PAGE 域、表格接 sectPr 三条与差量路线无关，留着不碍事。

## 5 高亮清单怎么记：行但有条件

- **不能用字符偏移或 run 序号**：律师填字就让同段其他高亮的偏移飘，增删段落让段落号飘。
- **也不能用「整段固定文字」当锚点**：原型第一版这么做，律师去掉同段里任一处黄，其余几处的锚点就全变了，比对全部落空。
- **能用的键是两层**：段落用「记录时的整段文字」模糊匹配（`difflib.SequenceMatcher` 比率 ≥ 0.6），段内每处高亮用「原文」在该段记过的原文多重集合里消一个。律师填字改的是高亮区间的文字，整段相似度仍高；填了字就不等于任何原文，判为「律师已填」。段落号只作提示写进审查报告。
- **条件一**：律师在一个记过高亮的段落里自己新加的黄会被当成「填过的」去掉（原文不在记过的集合里）。在没记过的段落里加的黄不动。要完全避免得给代码的高亮打自己的记号（如同时写 `w:shd` 或书签），但律师用荧光笔去黄时记号会留下，得另擦；本轮判为不值得，写进 to-docx 正文作为已知行为。
- **条件二**：同一段里两处原文相同（两个 `XX`），律师只填了其中一处，代码只知道「消掉一个、剩一个」，报出的位置以当前文书为准，不会错判，但审查报告里那行「原 p3 XX」对不上是哪一个。可接受。
- **条件三**：律师把整段重写到相似度低于 0.6，该段的高亮全部报「律师自己加的黄，不动」，段里记过的那些报「已填并去黄」。这是保守方向（不动律师的东西），可接受。
- 审查报告里一行的形状：`{"p": 2, "n": 0, "para": "<记录时整段文字>", "text": "（20XX）"}`。

## 6 python 3.9 与 python-docx 1.2.0：行

- `fill.py` 按 3.9 的 `feature_version` 解析通过；类型注解用 `typing.List/Dict/Tuple`，没有 `match`、没有 `X | Y`、没有 `Path.write_text(newline=)`。
- 用到的 python-docx 公共 API 只有 `Document`、`Run.text`（getter 把 tab/br 折成 `\t`/`\n`，setter 反向）、`Run.font.highlight_color`、`BaseOxmlElement.xpath`；`w:highlight` 元素的插入顺序由 python-docx 的 `CT_RPr` 处理，不用自己排 rPr 子元素顺序。其余是 lxml 与 re。1.2.0 上跑全套无异常。
- 没有在 3.9 解释器上真跑（开发机只有 3.14）；`tests/python-floor/` 那条机械守门按现有规则会扫到它搬进 `skills/*/*/scripts/` 之后的位置。

## 对需求单第 3 节 to-docx 那段的改法

- 「脚本把模板或当前 docx 的段落与单元格打成带编号的清单」：编号是全文 `w:p` 序号，单元格段落带表/行/格标签；槽在段内编号；清单要把模板自带的高亮也标出来。
- 「模型提交编号处的改动：填、删段、加高亮、去高亮」：加一种「按原文换」（`replace`），因为不带标记的提示文字与条件段只能按原文指认；填了但没把握的用 `fill` 加 `highlight: true`。
- 「缺的槽保留模板原占位加黄色高亮」：由代码在施加完后统一做，模型不写。
- 「门禁缩成两样」：第一样查改动段、排除高亮里的；第二样直接复用推算层；`static_checks` 的全篇占位与说明段两条删。
- 「审查报告记高亮清单」：一处一行，记段落号、记录时整段文字、高亮处原文；不记偏移。
- 新增一条已知行为：律师在记过高亮的段落里自己新加的黄，重出时会被去掉。
- `docx-text` 并进「打清单」：清单本身就是 `docx-text` 加编号与标记，指南整读可以用同一条不带标记的输出。
