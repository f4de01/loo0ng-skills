## What it does

`ask-loo0ng` 是一张**只读的地图**：你说一句话，它告诉你这个案件走到哪一步、接下来该做什么、下一句该打什么，然后停。它不触发任何 skill、不写图、不替你按下去；用不用它，案件都走得一样。

回复的**第一行就是待拍板行**：黄色已清、还没确认的文书逐个列出来，后面直接跟上「下一句：`/doit 确认 X`」。一份都没有时那一行写「待拍板：无」，它永远在。那是你最容易漏的一句话，现在是回复里第一眼看见的东西。

往下是固定五段，段序不变：**你在哪**、**三问**（当前节点、上一完成、下一任务）、**往下的路**、**相近入口分界线**、**下一句该打什么**。

## When to reach for it

随时，也可以一直不问。它只读，不必开新对话。

典型的三种：办完一个节点不知道接下来办哪个；隔了几天回到一个案子想知道停在哪；想确认某一份是不是还等你确认。

## Prerequisites

会话当前目录是案件工作区（有 `图.json`）。没有它就直说没有，并请你在案件目录里开会话。

## Common questions

**它怎么决定「下一任务」？**
一棵四问有序决策树，按顺序问、第一个 yes 胜出，回复里标出命中哪一问：①有黄色已清、等你确认的吗 → 先确认它们；②有黄色没清、等你动手的吗 → 去填，或把事实给 `doit` 重出；③前方里还有没生成的节点吗 → 出第一个模块里的第一个；④都没有 → 无事可做。你不同意就点名一个节点，它不拦。

**顺序是谁定的？**
你自己。「前方」按图序排，图序就是起手拷进来那份预设图的顺序加上你后来调过的。路由不重排。

**带期限的节点它会提前排吗？**
不会。它读不到材料，算不出本案真正的基准日与截止日，任何「临近」都是猜。带时限的节点，它把那句话原样附在「往下的路」里，判断留给你；顺序不因它改变。

**它会不会自己去数文书里还有几处黄？**
不会。黄色清没清是图引擎每次写图时算好的一列，它照读。它不打开任何 docx。

**我问的事图上没有怎么办？**
它直说「对不上」，并给你 `doit 出一版 <你说的标题>` 这一串（那一条会按你说的标题把节点建进图再出件）。**它绝不发明一个不存在的入口名。**

## It's working if

- 回复第一行是待拍板行，往下五个二级标题一字不差、按序、末段之后就停。
- 跑完之后 `图.json`、`图视图.md`、`图视图.json` 一个字节都没变。
- 「下一句该打什么」给的是可以直接粘贴的整串，Claude Code 与 Codex 各一行。
- 指到那四件说一句话就到的 skill 时，给的是你要说的那句话，不是一个 `/名`。

## Where it fits

路由是可选的：三个入口（[setup-case](https://github.com/f4de01/loo0ng-skills/blob/main/docs/engineering/setup-case.md)、[doit](https://github.com/f4de01/loo0ng-skills/blob/main/docs/engineering/doit.md)、它自己）你都可以直接打，不必先问它。它只读图引擎（[graph](https://github.com/f4de01/loo0ng-skills/blob/main/docs/engineering/graph.md)）算好的 `图视图.json`，不自己推。凡是对某件 skill 行为的说法，以那件 skill 的 `SKILL.md` 为准：不一致时它对、这张地图错。
