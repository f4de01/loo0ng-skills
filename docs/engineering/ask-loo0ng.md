## What it does

`ask-loo0ng` 是一张**只读的地图**：你说一句话，它告诉你这个案件走到哪一步、接下来该做什么、下一句该打什么，然后停。它不触发任何 skill、不写图、不替你按下去；用不用它，案件都走得一样。

回复先给待拍板行，往下是固定五段，段序不变：**你在哪**、**三问**（当前节点、上一完成、下一任务）、**往下的路**、**相近入口分界线**、**下一句该打什么**。

## When to reach for it

随时，也可以一直不问。它只读，不必开新对话。

典型的三种：办完一个节点不知道接下来办哪个；隔了几天回到一个案子想知道停在哪；想确认某一份是不是还等你确认。

## Prerequisites

会话当前目录是案件工作区（有 `图.json`）。没有它就直说没有，并请你在案件目录里开会话。

## 待拍板行，把差你一句话的文书放在最前面

文书已经生成、黄色也清了，图上仍可能没有你的确认。隔几天回来，最容易漏的就是这一步。**待拍板行**先把这些节点按「标题（模块）」逐个点名，再给出第一份的确认话，让你第一眼看见哪几份只差拍板。

| 视图里的情况 | 回复第一行告诉你什么 |
| --- | --- |
| 有已生成、未确认且黄色已清的节点 | 逐份列出，附上第一份的「下一句：`/doit 确认 X`」 |
| 没有这样的节点 | 「待拍板：无」，不省略这一行 |
| `图视图.json` 不在 | 「待拍板：无法判断」，说明缺少视图，并指向让引擎重算的改图动作 |

「待拍板：无」也可能是文书还有黄色要填，不能据此认定本案办完。后面的「当前节点」会把已生成待确认的文书都列出来，逐份写清黄色清没清。下一任务先提醒处理这些文书，再列出图序里下一件可以生成的节点，方便你安排自己的时间。

## 只读的地图，读的是图里已有的状态

问路照读 `图视图.json`，那里已经有节点状态、高亮和前方。它把这些信息变成你能直接打的下一句话；是否执行、何时执行，由你决定。反复问路不会生成文书，也不会替任何节点落确认。

这张地图的边界也在这里：它不读材料、不打开文书，黄色清没清取自引擎上一次写图时算好的那一列。你刚在 Word 里改完、视图还没重算时，问路并不会刷新这项判断。图里的时限句也只原样附上，真正的基准日与截止日要靠本案材料判断，不能用问路的排列代替期限判断。

所以「下一句该打什么」是一条交给你的话。你可以照着打，也可以直接点名另一个节点去办；问路始终是可选的入口。

## Common questions

**为什么第一行总是「待拍板」，下一任务又按什么排？**
先提醒黄色已清、仍没确认的文书，避免漏掉你最后那句话。四问按顺序取第一个命中：先确认黄色已清的，再处理仍黄的，再出「前方」第一个模块的第一个节点，最后才是无事可做。「待拍板：无」不等于办完，仍黄的文书还要处理。出处：[CHANGELOG 0.6.0，路由改成四问与待拍板行](https://github.com/f4de01/loo0ng-skills/blob/main/CHANGELOG.md#060)。

**以前还去活图找下一件，现在为什么只看案件图？**
起手已把预设图整份拷进本案，之后案件图自足。路由只读 `图视图.json` 算好的状态、高亮与前方，不再开第二张图，也不打开 DOCX 数黄色；顺序按本案图序。出处：[CHANGELOG 0.6.0，路由与图引擎重写](https://github.com/f4de01/loo0ng-skills/blob/main/CHANGELOG.md#060)。

**归档、改图这些事，为什么给一句话而不给 `/名`？**
入口表分两组：`setup-case`、`doit`、`ask-loo0ng` 按名字调用；`filing`、`graph`、`domain`、`to-docx` 说一句话就到。问路指向后一组时给你要说的原话，本身不替你执行。出处：[CHANGELOG 0.6.0，路由新增第二张入口表](https://github.com/f4de01/loo0ng-skills/blob/main/CHANGELOG.md#060)。

## It's working if

- 回复第一行是待拍板行，往下五个二级标题一字不差、按序、末段之后就停。
- 跑完之后 `图.json`、`图视图.md`、`图视图.json` 一个字节都没变。
- 「下一句该打什么」给的是可以直接粘贴的整串，Claude Code 与 Codex 各一行。
- 指到那四件说一句话就到的 skill 时，给的是你要说的那句话，不是一个 `/名`。

## Where it fits

路由是可选的：三个入口（[setup-case](https://github.com/f4de01/loo0ng-skills/blob/main/docs/engineering/setup-case.md)、[doit](https://github.com/f4de01/loo0ng-skills/blob/main/docs/engineering/doit.md)、它自己）你都可以直接打，不必先问它。它只读图引擎（[graph](https://github.com/f4de01/loo0ng-skills/blob/main/docs/engineering/graph.md)）算好的 `图视图.json`，不自己推。凡是对某件 skill 行为的说法，以那件 skill 的 `SKILL.md` 为准：不一致时它对、这张地图错。
