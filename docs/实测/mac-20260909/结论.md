2026-09-09，开发者本人在律师那台 Mac 前照 `docs/交付/现场清单.md` 段 1 做的。机器本身的事实（系统、芯片、`python3`、`node` / `npx`、`codex`、办公套件）与 2026-09-07 那次是同一台，已记在 `docs/research/mac-实测-20260907.md`，本文不重复。

**证据等级先说清。** 这一趟是照做不是照记，`docs/交付/记录表.md` 的格子没有当场填，回来只留下口述结论（#83 收口那条评论已经照实记过这条局限）。所以下面**没有本轮的退出码，也没有本轮的报错原文**，凡标「口述」的只有一句话为据。上一轮那两条报错原文照抄自 `docs/research/mac-实测-20260907.md`，那一份是有原始回显的（回显本身在律师回传的 zip 里，不入库，硬边界 1）。

- **本轮没有原文。** 不补一份看起来很像真的：那份文件将来是下一次交付的唯一依据，编出来的比空着更坏。

## 最后怎么成的

把 `f4de01/lawyer-workbench-v3` 从 private 改成 public，再跑一次路 A 的原命令，装成了。安装命令一个字没改，路 B / 路 C 两条降级路线一条都没用上。

**没有相反记录**说现场去找过 GitHub 令牌或让律师登录过（段 0 的 P7 与 1.1 的 ⚠️ 都写着不要那么干）。这一条同样只是口述加禁令倒推，不是有回显的事实。

## 由此定下的约束

**安装源必须是公开仓库。** 它是一条约束不是一处笔误，正文落点在 `.agents/release.md` 的分发段，连同「真要把主仓库转私有得付的三样代价」一起写在那里。

现场清单与 README 里两处「私有仓库吃本机凭据 / 凭本机凭据克隆」的措辞照这一条改过了（#94）：那句话只在开发机上验过（`.agents/release.md` 分发事实，#18），拿到律师那台机器上是误导。

## 清单 U1 销掉

`docs/交付/现场清单.md` 的 U1 是「`npx skills add` 这一次成不成」，本轮答掉：**私有仓库装不上，公开之后装得上。** 清单与 `docs/交付/记录表.md` 的那一行已删，编号不回收（U2 至 U8 原号不动，免得跟旧记录表串号）。
