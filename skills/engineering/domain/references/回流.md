# 回流：把案件图里判为通用的模块与节点写进领域图

方向与对象只有一个：案件图的构成写进领域图。回的只有图的构成，节点、标题、归属、顺序、空白模板属性、时限句；不回条目、不回律师陈述里的裁定、不回「生成」空白模板；保留案件里的原 id；只回本领域的图。

**终点只有一个：活图**（`~/.loo0ng/领域/<领域名>/领域图.json`，路径由 `sketch.py home --name <领域名>` 回显）。领域图的构建两侧同一条路（ADR-0020）：开发者要定制或维护一个领域图，也是办一遍、回流进自己那份活图。包内出厂种子谁都不许在会话里写，引擎无条件拒，没有放行口；种子改由**入库**更新，那是另一个动作，见本篇末尾。

ADR-0019 分出的两条路差别只剩粒度与时点：

| | 律师侧逐节点（默认路） | 开发侧批量 |
| --- | --- | --- |
| 在哪个会话 | 办案会话，当前目录是案件工作区 | 开发会话，开发者一句话给出案件工作区路径 |
| 粒度 | 一次一个节点 | 一批，`from-case` 从一份案件图算出来 |
| 时点 | 节点确认那一刻 | 没有时点，开发者补历史或定制领域图时做 |
| 写的是 | 本机的**活图** `~/.loo0ng/领域/<领域名>/领域图.json` | 同一份**活图**，路径同样用 `home` 取 |
| 做什么用 | 这一个个案子累计出自己的领域图，下一个案子接着用 | 补此前已确认、逐节点那条路漏掉的历史节点；定制一个领域图 |
| 谁拍板 | 律师一句话 | 开发者一句话 |
| 走不走雏形 | 不走，一次一个节点，直接经引擎 | 走，`from-case` 算出一批候选写成雏形文件 |
| 第二双眼 | 没有 | 回流这一刻没有；它守的是**入库**那一次写 |

## 判为通用要两条都满足

1. **用过一次**：该节点在真实案件里至少有一版已确认文书。未生成、只生成未确认、不适用的都不是候选。模块的判据是其下至少一个节点满足这条。
2. **去掉案件事实后标题仍成立**：改写成通用标题后，第二个同领域案件读得懂、用得上。

律师侧第一条在确认那一刻天然成立（那一刻正是"至少有一版已确认"的时刻），第二条降为可用性要求，由 agent 提默认标题、律师拍板；开发侧第一条由 `from-case` 机械算，第二条由开发者改写标题时判。

## 律师侧：逐节点，在确认那一刻

在办案会话里做，由 skill "doit" 在确认之后驱动（那一问挂在它的收尾）。缺失判定、回显什么、写入的命令都在它的正文里；本篇只记这条路的规矩：

- **只对领域图里没有的节点问。** 判定是按 id 的反向减法，引擎已经算好了：`图视图.md` 里这个节点那一行的「来源」是「领域图」就一个字不问，是「案件」才问。写死成每次都问，就是把 2.0 的反复确认搬回来。
- **一次只问一个问题，两个默认值**：模块继承它在案件图里所在的那个，标题取去掉当事人、案号、金额、日期之后仍成立的写法（与本篇开发侧那套改写是同一个口径）。
- **不问时限**（ADR-0019）。律师侧新增的节点没有时限属性，缺省；有通用规则的由开发者补。
- **未拍板不写**，与雏形机制同一条规矩：律师那一句之前活图一个字不动。
- **写入只经引擎**，`--kind domain` 指着活图那份 `领域图.json`；改模块、改标题、跨模块移动、新建或改名模块用的都是引擎现成的子命令，不新增 CLI。
- **没有第二双眼。** 活图在 skill 包与本仓库之外，硬边界 1 与隐私钩子都管不到它；去案件化在这条路上是可用性问题（别让 A 案当事人的名字出现在 B 案的图里），不是隐私门禁。进仓库的那一份仍要第二双眼，见本篇末尾的入库。

## 开发侧：批量，只在开发会话

只在开发会话做（ADR-0012）：当前目录是本仓库（下面每条命令里的路径都从这里算起），开发者一句话给出案件工作区路径，agent 只读那份 `图.json`，写的是开发者本机的活图。它做两件事：补此前已确认、逐节点那条路漏掉的历史节点，以及定制一个领域图。写出去的那份文件在仓库之外，所以这条路上没有分支、没有 changeset、没有 PR，那些是入库的事。

1. **取活图路径**。

   ```
   python skills/engineering/domain/scripts/sketch.py home --name <领域名>
   ```

   回显第一行就是绝对路径（`活图：<路径>`）。下面每一条命令里的 `<活图>` 都是它；开发者那句话里直接给了一份领域图的路径时，用他给的那个，这一步跳过。活图不在就从出厂种子整份拷一份，已经在就一个字不动。

   造的是一个**全新领域**（活图与出厂种子都没有）时，这一条加 `--empty`：它在活图位置建目录、经引擎起一份空领域图，回显同一行绝对路径（ADR-0020）。包里已经有种子时它拒，那种情形本来就不带 `--empty`。
2. **算候选**。只读案件图，按 id 做「案件图有、领域图没有」的减法，再筛至少一版已确认的：

   ```
   python skills/engineering/domain/scripts/sketch.py from-case --case <案件工作区>/图.json --domain <活图> --out %TEMP%/回流.json
   ```

   产出是一份雏形文件：模块与节点保留原 id；已在领域图里的模块按领域图的标题指认（案件里改过名也不带）；官方空白模板原样带，生成空白模板改为「无」；没有时限。没有候选就什么都不写。
3. **去案件化改写**。逐条读候选标题，去掉案号、当事人、具体日期与本案特有的说法，改成通用标题；本案专有、第二个案件用不上的整条删掉。有通用规则的节点补上一句时限（取舍见 `时限句.md`）。改的只是那份雏形文件。
4. **判重回显**。对着活图 `check --kind domain`，同名的不再提，相似的列为待定，由开发者定：

   ```
   python skills/engineering/domain/scripts/sketch.py check --proposal %TEMP%/回流.json --graph <活图>/领域图.json --kind domain
   ```

5. **一句话拍板后写入**。

   ```
   python skills/engineering/domain/scripts/sketch.py apply --proposal %TEMP%/回流.json --graph <活图>/领域图.json --kind domain [--as-new <标题>]...
   ```

   顺序要调用引擎的 `move-node` / `move-module`（`--kind domain`）；领域图节点改标题用 `rename-node`。
6. **验证**。`python skills/engineering/graph/scripts/graph.py --graph <活图>/领域图.json --kind domain validate`；在测试工作区整份起手看视图。

`--graph` 指到包内 `assets/<领域名>/领域图.json` 上时引擎无条件拒，一字不写（ADR-0020），拒绝消息里写着活图怎么取。

### 换完指针那一行之后补历史

律师（或开发者）把工作区 `AGENTS.md` 里「领域目录」那一行从包内出厂种子换成活图之后，**这个案子里此前已确认的节点不会自动补上**：逐节点那条路的时点只有确认那一刻，那一刻已经过去，#91 定的是「不写、不再问第二次」，不设补问。

补它就走上面这条路，`--domain` 指活图：

```
python skills/engineering/domain/scripts/sketch.py from-case --case <案件工作区>/图.json --domain <活图> --out %TEMP%/回流.json
```

它算的是「案件图有、活图没有」的减法，所以已经逐节点回流进去的那些不会再提一遍，只剩换指针之前攒下的那批。补历史不是另一套机制，与开发侧批量是同一条路、同一组命令。

## 入库：活图那份进仓库成为出厂种子

回流从不写出厂种子。种子要更新，是另一个动作（ADR-0020）：开发者活图那份 `领域图.json` 进仓库、成为 `skills/engineering/domain/assets/<领域名>/领域图.json`，一次 git 提交，在仓库里做。它只拿 `领域图.json`，不拿整个领域目录（官方模板原件与指引手册原文进仓库的路本来就是普通的 git 添加）。

拷那一下是一条命令，在仓库里跑：

```
python skills/engineering/domain/scripts/sketch.py intake --name <领域名>
```

它拷之前先经引擎 `validate` 校验（格式合法、无条目），再把这次比种子多了什么、改了什么分栏回显：新增、改名、改属性、改归属、种子里有而活图里没有，头一行数出「多了几个模块几个节点、改了几个标题」。两侧同一条路带来一个原来没有的风险：活图里混着开发者试办案子回流进去的东西，入库是整份送进去，第二双眼要审的 diff 一下子变大且没有摘要，这几行就是隐私钩子与第二双眼之前的第一道人眼过滤，念给人听再往下走。种子根不在一个 git 工作树里（装好的那份 skill 包）它拒；活图那份里写的领域名与 `--name` 对不上也拒。它是一次拷贝，不经图引擎，所以不受「包内种子谁都不许写」那条拒约束；那条拒管的是会话里的每一次写图，照旧立着，入库没有绕过它。

这一次写由分支 + PR 守：先开分支，隐私钩子在 `main` 上拒绝触及领域图文件的提交（ADR-0014）；跑脚本层测试与三条校验，再跑两侧的用例「回流」（`python scripts/skill-eval.py --harness claude --case 回流`，Codex 侧同）；`npm run changeset` 写一条（minor：领域图的一次发布）；开 PR，另一个会话的 AFK 代理审 diff，专查案件内容（姓名、公司、案号、金额、日期），开发者读报告后合并；隐私钩子只跑正则，不算第二双眼。**第二双眼这一道把关强度不变，只是位置从回流那一刻挪到了入库这一刻**（ADR-0012 的 2026-09-10 附注）。入库与 skill 包的版本发布是两回事（ADR-0009「维护即发布」说的是后者），一次包发布可以带零次或多次入库。

## 两条路都不做的

- 不给回流的节点换新 id：该案的前方会多出一个与自己重复的节点。
- 不动案件图：回流只读它；领域图改版也不改案件图任何字节，前方是按 id 的减法。
- 不回流案件里领域图节点的改名：领域图节点的标题由开发者直接用 `rename-node --kind domain` 改，那是对领域图的普通编辑。
- 不写包内出厂种子：引擎无条件拒，没有放行口。
- 开发侧那条没有时点、不自动触发；律师侧那条的时点只有确认那一刻，不在生成中间问，也不等结案。
