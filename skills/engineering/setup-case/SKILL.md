# 起手

一案一次，在案件工作区里跑：工作区就是会话当前目录，`图.json` 是它的身份标记。**前置只有一条：当前目录没有 `图.json`**。有就拒绝，告诉律师这个目录已经是案件工作区，要改图的构成在对话里说一句就到 skill "graph"，要另起一案换一个目录。脚本自己也守这一条。

**目录非空不拒。** 律师在 Codex 建的项目目录里打这一句，目录里通常已经堆着他手头的文件：这些一律视为待归档，由起手挪进 `待归档/`，判去向是后面那一步的事。别因为目录里有东西就停下来问。

CLI 是本目录的 `scripts/setup.py`（Python 标准库，零依赖，不 import 兄弟 skill；写图经 skill "graph" 的引擎子进程，预设图路径经 skill "domain" 的 `preset.py resolve` 子进程）。退出码 0 完成；1 拒绝（原因在 stderr，工作区不留半截）；2 用法错。`--help` 是参数的权威。

## 顺序是死的

**一问二选 → 一条命令 → 清待归档 → 回显起手清单 → 律师一句话 → 搬、登记、写图 → 收尾**。起手清单是这一路上唯一的确认点，前面不问律师，后面不再问第二遍；没有文件要归时连它也没有。

## 1. 一问二选

只问这一件事：**空图，还是哪份预设图**。列表由 skill "domain" 给：调用 Skill 工具，传 "domain"，照它正文里的写法跑 `preset.py list`。

它分出厂、个人两组回显，照抄给律师，让他选一个名，或者说要空图。两组都空就是「这次只能从空图起手」，照说一句直接进第 2 步。

**不问领域名**：案件图自足，预设图自带名字。**律师那句话里说了的不再问**：他打「起手，用破产那份」就是选好了，直接进第 2 步；两组里同名两份时才回头问一句要哪个归属。

别替他选，也别因为只有一份出厂预设图就默认用它。

## 2. 一条命令

```
python <本目录>/scripts/setup.py init --preset <名> --owner 出厂|个人
python <本目录>/scripts/setup.py init                     # 空图起手
```

一条命令落下：目录形状、图与两份视图、预设图的空白模板、目录里原有的东西挪进待归档、工作区指针块，回显逐条说明。**预设图的路径本脚本自己取**，它子进程调 `preset.py resolve`，跟它调图引擎是同一个形状；这一步没有留给模型的事，别自己先跑一遍 `resolve` 再把路径抄过来。

```
<案件工作区>/
├── 图.json  图视图.md  图视图.json  AGENTS.md  CLAUDE.md
├── 待归档/                   ← 目录里原有的东西都在这里，等归档判去向
├── 材料/
├── 参考/模板/  参考/指南/
└── 文书/                     ← <模块>/<节点>/ 出件时才建
```

工作区根还会多一份 `归档索引.md`，那是归档第一次搬东西时由 skill "filing" 建的，起手不落它。

预设图那条路把它的模块、节点、空白模板文件名与时限句一次拷进案件图，`模板/` 整份拷进 `参考/模板/`；**空图起手不拷模板**，那一格先空着，律师自己的空白模板之后经归档放进来。拷入之后案件图自足：前方只从它自己的条目算，律师加节点走 skill "graph"，想把这一案的构成带走就整份另存（skill "domain"）。

指针块照 [WORKSPACE-AGENTS.md](./WORKSPACE-AGENTS.md) 落成工作区根的 `AGENTS.md`（Codex 读）与一行 `@AGENTS.md` 的 `CLAUDE.md`（Claude Code 读），**只四项**：预设图的名与归属、图与视图的文件名、入口名、「本工作区对 skill 仓库只读」。**一条路径都不记**：记下来包一升级就死；要路径的按名与归属当场解析。目录里原本就有 `AGENTS.md` 的，块追加在末尾，原有内容一字不动。它由那一问机械推出，不加确认点，之后没有任何 skill 往里写。

引擎或 `resolve` 拒了就一格不建、一个字不写：把拒写的原话照读给律师，别自己改 JSON 绕过去，也别换一份预设图替他起手。

## 3. 环境

本版不做。自检、安装、后端版本都不在起手里；填模板脚本的环境由 skill "to-docx" 在出件时自备。这一节留着位置。

## 4. 清待归档

调用 Skill 工具，传 "filing"：`list` 逐件列出 `待归档/`，按它的三格判去向（本案事实原件→`材料`，空白件→`参考/模板`，官方要求文件→`参考/指南`），写成一份归档计划。**这一步只写计划，不 `apply`**：搬要等律师那一句话。

`list` 说「没有文件」就到此为止：不出清单、不问、直接收尾。

这一趟里认出**既有成品**的挑出来，不写进归档计划：起手前律师已经写成、对得上图上某个节点的本案文书就是既有成品，它的去处是那个节点的文书目录，不是三格里的任何一格。对不上任何节点的不算，那只是普通材料，照常归 `材料`。

## 5. 起手清单（唯一的确认点）

三张表合成一张，一次回显、一句话拍板。

```markdown
## 起手清单

**归档去向**

| # | 文件 | 去向 | 一句理由 |
| - | ---- | ---- | -------- |
| 1 | 合同.pdf | 材料 | 本案的事实来源原件 |
| 2 | （格式）登记表.docx | 参考/模板 | 官方发布的空白件 |

**建议登记为已生成的既有成品（来源记律师，不是确认）**

| # | 文件 | 登记到节点 | 登记后状态 |
| - | ---- | ---------- | ---------- |
| 3 | 待归档/旧的下种记录.md | 下种 | 已生成（未确认） |

**同名冲突与拿不准的**

| # | 文件 | 本案已有的那一件 | 为什么停在这里 |
| - | ---- | ---------------- | -------------- |
| 4 | 同名的.txt | 材料/同名的.txt | 同名不同内容，搬不搬、搬到哪由你定 |
| 5 | 未命名.txt | | 三格都没有正向证据，先留在待归档 |

另有 N 件本案已有，不再搬。

一句话拍板整张：可以是「都按建议来」「第 3 条不要」「4 归材料」。说了才搬、才写图。
```

空的那张表整张不出（比如没有既有成品就没有第二张），三张都空就是没有文件要归，直接收尾。清单之外不加自己的判断，也不先搬再问。

## 6. 律师一句话之后才搬、才写图

按他的话改完计划，依次做：

1. **搬**：调用 Skill 工具，传 "filing"，跑它的 `apply`，回显照读。
2. **登记既有成品**：一件一条

   ```
   python <本目录>/scripts/setup.py register --node <节点标题> --file 待归档/<文件>
   ```

   它把那件成品挪进 `文书/<模块>/<节点>/`，写一份只有 `律师自写` 一行的审查报告（格式照 skill "to-docx" 的审查报告格式里「律师自写的」那一节），再经引擎追加一条来源为律师的生成条目。律师拍板那句话不进文件：生成条目不存原话，那句话留在这次对话与收尾里。

**没有任何节点被自动确认。** 确认只能由律师一句话发起；起手登记的这一版本工作台没参与写作，审查报告那一行就写着「律师自写」。律师说「这份就这样了」是确认，那是 skill "doit" 的事，不在起手里做。

## 收尾三段

同别的入口一个形状：

1. **落了什么**：五行，一行一样，**少一行就是没照做**（不是「说得简略」）；每行起头那几个字原样照抄，件数与节点名逐个写实，没有的那一样写「0 件」而不是整行不写：

   > 目录与图：目录形状建齐，`图.json`、`图视图.md`、`图视图.json` 三份都落了盘。
   > 起手图：<空图，或预设图「<名>」（出厂/个人）>，<几> 个模块 <几> 个节点，空白模板拷进 `参考/模板/` <几> 件。
   > 待归档：目录里原有的 <几> 件已挪进 `待归档/`。
   > 归档：材料 <几> 件、参考/模板 <几> 件、参考/指南 <几> 件，留在待归档 <几> 件（逐件说一句为什么留）。
   > 既有成品：登记 <几> 件，逐件点名，都是已生成未确认。

   发出去之前数一遍这五行在不在。只报「归档了几件」不算这一段。

2. **你现在该拍板什么**：起手不产生要拍板的东西；有既有成品登记的，说明它们是已生成未确认，要确认得在办那个节点的对话里说一句。
3. **下一句该打什么**：`doit 出一版 <节点标题>` 开一个新对话办第一个节点；不知道从哪开始就打 `ask-loo0ng`。

## 与邻居的边界

- 待归档的判去向与搬运归 skill "filing"；本 skill 只在第 4、6 步调它，不自己搬文件、不自己写归档索引。既有成品那一件是例外，它不进三格，由 `register` 挪进文书目录。
- 预设图的列表、按名与归属解析路径、另存归 skill "domain"；本 skill 在第 1 步调它的 `list`，第 2 步由 CLI 子进程调它的 `resolve`，不自己算预设图在哪。
- 起手与既有成品登记之外的一切写图归 skill "graph"；本 skill 的两条写入也都经它的引擎子进程。
- 出一版文书与拍板归 skill "doit"；起手不出件、不确认。
- 起手不跑雏形：从一份指南里提节点是 skill "domain" 的事，律师什么时候想要什么时候说。
- 本 skill 不含领域语义：换一个领域只换 `--preset` 给的那个名字。
