# 问路

你不必记住每个入口，问就行。

这是一张只读的地图：你说一句话，它告诉你这个案件走到哪一步、接下来该做什么、下一句该打什么，然后停。它不触发任何 skill、不写图、不替你按下去；用不用它，案件都走得一样。它的回答不成为图里的状态，每次回答都是完整的，不接上一次。

前置只有一条：会话当前目录是案件工作区（有 `图.json`）。没有就说没有，让律师在案件目录里开会话，还没起手就打 `setup-case`；这不影响他直接打任何入口。

## 主线：一个节点怎么走完

1. **起手**：`setup-case`，一案一次，把当前目录长成案件工作区。目录里已经堆着文件不妨，它们一律视为待归档。
2. **开新对话，出一版**：`doit 出一版 <节点>`。一个对话只办一个节点，所以这一步之前先开新对话。它收尾时会说这一版黄色标在哪几处。
3. **黄色处你来填**，两条路任选：在 Word 里直接填（去不去黄都行），或者在对话里把事实给它、让它重出一版（还是 `doit 出一版 <节点>`）。重出只动仍黄的地方与你点名要改的地方，你填过的一个字不碰。
4. **拍板**：一句「确认 <节点>」，节点完成。**哪个对话说都行**：在 Word 里填完、隔几天新开一个对话说这一句，照样落。
5. **回第 2 步做下一个节点。** 哪一个，见[我读什么、怎么答](#我读什么怎么答)。

黄色清零不等于完成：确认永远是你那一句话，工作台不替你推断。

### 上下文卫生

每个节点的出一版在新对话里跑：第 2 步之前先开新对话。第 3 步在 Word 里填不占对话；要它重出的那一句与第 2 步在同一个对话里说。第 4 步的拍板哪个对话说都行。问路不必开新对话，它只读。

## 汇入线

- **法院退回、要求改一版**：对已确认的节点再 `doit 出一版 <节点>`，这叫重出，节点回到已生成、旧的确认留在条目里，然后回主线第 3 步。要改哪几处就点名哪几处，点名的位置它照改、改完不再标黄。
- **这一份你自己写好了**：`doit <节点> 我自己写好了`，它把你那份登记成这个节点的文书，一个字不改，然后回主线第 4 步。
- **本案不走某个节点或整块**：`doit <节点> 不适用`，或 `doit 模块 <模块> 不适用`，然后回主线第 5 步。
- **图里没有你要做的事**：还是 `doit 出一版 <你说的标题>`，它按你说的标题把节点建进图再出件。绝不替你编一个入口出来。
- **要归档、改图的构成、把这一案的图留给下一案**：不必打名字，在对话里说一句就行，见[另外四件](#另外四件说一句话就到)。

打法：Claude Code 里 `/名 …`，Codex 里 `$名 …`，**都是裸名，不带命名空间前缀**（是 `$doit`，不是 `$<插件名>:doit`）。后面那句话两边都是自由文本，整串原样给那个入口，它自己读案件图；不必替它打包上下文，律师只补图里没有的话。要开新对话的，这一串就是新对话的第一句，两个平台都没有「排队给下一会话」的机制。

你给的永远是整串，律师照打或粘贴都成。但**在 Codex 客户端里他不必打全名**：补全按子串匹配，打 `doi` 就切到 `doit`、打 `ask` 就切到 `ask-loo0ng`，再按 tab 选中；插件路线装的带 `loo0ng-skills:` 前缀，子串照样命中，不必打前缀。只打一个 `$` 反而不好找：列表二十几项，这几件不在首屏。这一条只在 Codex 客户端实测过，Claude Code 的 `/` 补全没测过，别照搬。

### 另外四件：说一句话就到

**这张表与上面那张一样是自持的**，也不去读目录：这四件都在，即使它们在你看到的 skill 列表里长得不是这个样子。律师不必打它们的名字，在案件工作区的对话里说一句，模型自己够到它们；上面两个入口在流程里也调它们。**下一句该打什么**指到它们时，给的就是律师那句话，不是一个 `/名`。

| skill | 律师说一句 | 做什么 |
| --- | --- | --- |
| `filing` | 「把那个目录整理进来」「归一下待归档」 | 把文件归进 `材料/`、`参考/模板/`、`参考/指南/` 三格，去重、不改名、不覆盖，维护 `归档索引.md` |
| `graph` | 「加一个节点 X」「把 X 挪到 Y 模块下」「X 的空白模板换成 Z」 | 改图的构成。它是 `图.json` 的唯一写入口，写完整体重算两份视图 |
| `domain` | 「把这个案子的图存成预设图叫 Y」 | 预设图的家：分出厂、个人两组列出、按名与归属解析路径、另存 |
| `to-docx` | 「这份模板有哪些槽要填」 | 把一件 DOCX 打成带编号的清单；出一版时的施加差量也是它 |

表里只放名字、怎么触发、一句用途；**凡是对某件 skill 行为的断言，先读它自己的 `SKILL.md`（本 skill 的兄弟目录）再说，并在回复里注明以它为准：不一致时它对、这张地图错。**

## 我读什么、怎么答

读工作区根的 `图视图.json`：引擎每次写图之后整体重算它，每个节点的状态、`高亮`、`时限`，以及整张 `前方`（案件图里还没生成的节点，按图序装在它们各自的模块里）都已经算好了。**照读，不自己从条目推**：算一次这件事归引擎，路由与可视化插件一样只是读者。律师读的 `图视图.md` 是同一次重算给人看的形态，`图.json` 是事实但状态要自己算；问路读 JSON 那一份。字段与取值的权威是 skill "graph" 的 `references/格式.md`：状态四值（未生成、已生成、已确认、不适用），`高亮` 三值（`无文书`、`未清`、`已清`）。

**图自足**：视图里没有的节点，本案就是没有；不去别处比对，也不提别处有什么。律师要加一个节点是一句话给 skill "graph"，要整批进图只有起手那一条路。

`图视图.json` 不在（被删了，或是更早版本起手的工作区）：说它不在，并请律师随便做一次改图的动作让引擎重算；这一轮照 `图.json` 答，并写明状态是你自己从条目算的。黄色清没清只有引擎算得出，所以待拍板行这一次写「待拍板：无法判断（`图视图.json` 不在）」，后面照常给出「下一句：…」指向重算那一步；那一行仍然在，不省掉，也不打开任何 docx 自己去数黄色。

- **待拍板** = 已生成、未确认、且 `高亮` 是 `已清` 的节点。工作台这一边全做完了，只差律师那一句，所以它是回复的第一行。
- **当前节点** = 已生成、等你确认的节点，`高亮` 已清与未清的都算，逐份写明是哪一种。可以不止一个；一个都没有就答「没有待确认的文书」。
- **上一完成** = 现在仍处于已确认的节点里，`最近确认` 时间最晚的那个。重出过的节点现在是已生成，不算完成。
- **下一任务** = 先列全部待确认，再由下面的树定出一个要生成的。

### 四问有序决策树

按顺序问，第一个 yes 胜出，每次在回复里标出**命中哪一问**。理由在 [references/下一任务.md](references/下一任务.md)。

1. 有已生成、未确认、`高亮` 是 `已清` 的节点吗？有 → 先确认它们，按图序一份一份来。
2. 有已生成、未确认、`高亮` 不是 `已清` 的节点吗？有 → 那份文书里还有黄色等你动手：在 Word 里直接填，或者在对话里把事实给 `doit`、让它重出一版。
3. `前方` 里还有节点吗？有 → 出**第一个模块里的第一个节点**：`前方` 是一个模块数组，每个模块只装它自己还没生成的那几个节点，模块与节点都已经按图序排好。照它给，不自己重排；一个节点都不剩的模块整个不在里面，所以不必跳过空模块。
4. 都没有 → 无事可做：图上每个节点都已确认或不适用了。

命中问 1 或问 2 时仍要照问 3 往下算出一个要生成的节点，列在后面：律师拍板与填黄色都要花时间，他可能先开新对话出下一版。命中的问号记第一个 yes 的那一问。

**时限不进这棵树。** 路由读不到材料，算不出本案真正的基准日与截止日，任何「临近」判断都是猜。带时限的节点，把那句话**原样附在「往下的路」里**，判断留给律师；顺序不因它改变。

**写「往下的路」之前先查一遍时限**：那几步各自的节点，在 `图视图.json` 里看它有没有 `时限`，有就原样附一行「时限：…」，没有就不附。这是死顺序里的一步，不是想起来才做的一件事。视图里没有就是没有，不去别处找：时限句起手时随图拷进案件工作区，图自足。

## 图里对不上的事

律师说的事在视图里对不上时：**不猜、不造入口、不新建节点**。回复仍是第一行加那五段。在「你在哪」里先写一行以「对不上：」起头的话，说清哪一句在图上找不到，并给出 `doit 出一版 <律师说的标题>` 这一串（它按律师说的标题把节点建进图再出件）；**紧接着仍要照常写你在主线第几步与本案的处境**，这一段少不了它。然后照常答三问；往下的路把律师问的那件事排在第一步（他刚问的就是它），下一句该打什么就是它那一串。绝不发明一个表里没有的入口名。

## 回复长什么样

**第一行是待拍板行**，空一行，然后固定五段，段序不变，最后一段之后就停。五个小标题一字不改地照抄，都写成二级标题：`## 你在哪`、`## 三问`、`## 往下的路`、`## 相近入口分界线`、`## 下一句该打什么`；不改写这五个名字、不合并两段、不添别的段。一行加五段一次给全，写在同一条回复里，前面不加铺垫、后面不加收尾。

**这一行加这五个二级标题是回复本身的形状，不是排版建议。** 少一个、写成粗体或裸文字、把两段并成一段、在末段之后再加一句「下一句可直接复制：」这样的收尾，这条回复就算没回，不算「格式略有出入」；内容答得再对也一样。发出去之前数一遍：待拍板行在最上面、五个 `##` 都在、名字一字不差、按上面的顺序、末段之后再无正文，才发。

下面是一份样例（用合成小领域「菜园」，不是本案）：

```markdown
待拍板：施底肥（整地）黄色已清、还没确认。下一句：`/doit 确认 施底肥`

## 你在哪

主线第 4 步「拍板」：「施底肥」这一版的黄色已经清了，在等你那一句确认。

## 三问

- 当前节点：施底肥（整地）已生成待确认，黄色已清
- 上一完成：松土（整地），确认于 2026-09-06T10:12:03+08:00
- 下一任务：1. 确认 施底肥；2. 出一版 选种（播种）。命中问 1

## 往下的路

1. `/doit 确认 施底肥`
   你拍板：这一份要交就确认，本案根本不走它才是不适用。
   不必开新对话：拍板哪个对话说都行。
   时限：自松土完成之日起 3 日内（手册，示例）
2. `/doit 出一版 选种`
   你拍板：出来之后黄色处你填，填完说一句确认。
   开新对话：一个对话只办一个节点，这一串就是新对话的第一句。

## 相近入口分界线

- 自己填还是让它重出：黄色处你在 Word 里直接填最快，去不去黄都行；要它按你给的事实改那几处，就在对话里把事实给它、说一句重出，它只动仍黄的地方与你点名的地方。
- 确认还是不适用：这一份要交就确认；本案根本不走这一份才是不适用，它是终态。

以上关于各入口行为的说法以它们各自的 `SKILL.md` 为准。

## 下一句该打什么

Claude Code：`/doit 确认 施底肥`
Codex：`$doit 确认 施底肥`
```

逐行逐段的规矩：

1. **待拍板行**：`高亮` 已清、还没确认的节点逐个写成「标题（模块）」，多个用顿号隔开，后面接一句「黄色已清、还没确认」与第一个那一串「下一句：`/doit 确认 <标题>`」。一个都没有就写「待拍板：无。没有黄色已清、等你确认的文书。」读不到视图时写「待拍板：无法判断（`图视图.json` 不在）」。这一行永远在，三种情形各有各的写法，不因为没有就省掉。
2. **你在哪**：主线第几步，加一句本案的具体处境（点名节点、状态、黄色清没清），不要写成一般性描述；图是空图就直说空图，一个节点都没有。
3. **三问**：三行，逐行答；下一任务末尾标「命中问 N」，N 是 1 到 4 的阿拉伯数字，与上面那棵树的编号一致。当前节点复数就逐份列出，逐份写明黄色清没清。
4. **往下的路**：接下来至多四步，每步一行整串，下面跟两行，起头几个字原样照抄：「你拍板：」写这一步要律师定什么，「开新对话：」或「不必开新对话：」写上下文卫生。节点在视图上有 `时限` 的，再原样附一行「时限：…」。这一步是说一句话就到的那四件时，那一行写律师要说的话，不写 `/名`。
5. **相近入口分界线**：只列与这一步相邻的那几条，写成「X 还是 Y，取决于 Z」：自己填还是让它重出、确认还是不适用、节点不适用还是模块不适用、让它出一版还是自己写好了登记。说到某件 skill 会怎么做之前先读它的 `SKILL.md`，这一段末尾固定一行「以上关于各入口行为的说法以它们各自的 `SKILL.md` 为准。」
6. **下一句该打什么**：往下的路第一步那一串，两个平台各一行，整串原样可打。无事可做时说没有下一句，并说明要重出仍是打 `doit`，要改图的构成在对话里说一句就行。

## 不做的事

- 不触发任何 skill，不写图，不写任何文件。跑完之后 `图.json`、`图视图.md`、`图视图.json` 一个字节都不变。
- 不替律师按下去：编排入口只有律师能打，路由调不到（Claude Code 硬拦，Codex 同）。说一句话就到的那四件，路由也只是把律师该说的那句话写给他看，不自己说。
- 不替律师判断某个节点该不该走，不因时限改顺序。
- 不读材料、不读文书正文、不打开任何 docx：只读视图。黄色清没清也读视图那一列，不自己去扫文书。
- 说的事在图里对不上就说对不上，不编入口、不新建节点。
- 凡对某件 skill 行为的断言，以它自己的 `SKILL.md` 为准；不一致时它对、这张地图错。
