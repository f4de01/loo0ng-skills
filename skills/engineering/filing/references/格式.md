# 归档计划与归档索引的格式

`SKILL.md` 指到这里；字段有改动时先改这里，再改脚本与测试。

## 归档计划

模型写，`apply --plan` 读。一个 JSON 数组，一条一件（一个文件一条，目录不收；`list` 已经逐件列出来了）。UTF-8，写在临时位置，不进工作区。

| 字段 | 必填 | 取值 |
| --- | --- | --- |
| `路径` | 是 | 来源目录内的相对路径，`/` 与 `\` 都收；绝对路径与 `..` 拒 |
| `去向` | 是 | `材料`、`参考/模板`、`参考/指南` 三者之一 |
| `说明` | 是 | 一句话「这是什么」，一行，不得含竖线（它进索引表） |
| `子目录` | 否 | `材料` 下的主题子目录，可多级；另两格给了即拒 |

只收这四个键，别的键即拒（拼错的字段不会被静默忽略）。

```json
[
  {"路径": "扫描件/买卖合同.pdf", "去向": "材料", "子目录": "合同", "说明": "甲乙双方买卖合同原件，含两页附件"},
  {"路径": "受理通知.pdf", "去向": "参考/指南", "说明": "法院对本类案件的材料清单与格式要求"},
  {"路径": "申请书空白件.docx", "去向": "参考/模板", "说明": "官方发布的申请书空白模板"}
]
```

目标路径由脚本拼：`<去向>/<子目录>/<路径>`，来源里的子目录原样保留。上面第一条落到 `材料/合同/扫描件/买卖合同.pdf`。

## 两种来源

| 来源 | 命令 | 对原件 |
| --- | --- | --- |
| `待归档/`（默认） | `apply --plan <计划.json>` | 移动；搬空的子目录顺手清掉，`待归档/` 本身留着 |
| 工作区外的任意目录 | `apply --plan <计划.json> --from <目录>` | 复制，原件一字不动 |

`--from` 指进工作区（含 `待归档/` 自己）或套着工作区都拒。

## 逐件结果

`apply` 一件一行，末尾一行汇总。三种结果只有第一种会落进索引：

```
已归档：扫描件/买卖合同.pdf → 材料/合同/扫描件/买卖合同.pdf
已归档：受理通知.pdf → 参考/指南/受理通知.pdf（复制，原件不动）
已有：又一份通知.pdf（与 参考/指南/受理通知.pdf 内容相同，未搬）
同名冲突：申请书空白件.docx → 参考/模板/申请书空白件.docx 已存在且内容不同，未搬，留在原处
共 4 件：已归档 2，已有 1，同名冲突 1；归档索引.md 新增 2 行、更新 0 行。
```

`list` 的一行是 `<相对路径>\t<状态>`，状态三种：`新`、`已有 → <已归档路径>`、`重名 → <已归档路径>（内容不同）`。「已有」按 sha256 内容哈希算，「重名」按文件名算，两者都只在 `材料/`、`参考/模板/`、`参考/指南/` 三格里找；来源目录不在（`待归档/` 这一格还没建）时 `list` 答「没有文件」，退 0。

「重名」与「同名冲突」是两件事：前者在 `list` 出、按文件名算、去向还没定，只是提示律师本案已有一件同名的；后者在 `apply` 出、按目标路径算，那一件必不搬。

## 归档索引

工作区根的 `归档索引.md`。脚本头一次写时带上标题与表头；往后把新件插在**索引那张表**的末尾，或原地更新同一相对路径那一行，已有行不重排。认得出的只有表头恰为 `| 相对路径 | 是什么 | 归档日期 | 文本 |` 的那张表，它的表体到第一条不以 `|` 开头的行为止；表外的段落与律师自己写的别的表一字不动，索引在、但那张表不在时先把表头补到末尾。

```markdown
# 归档索引

一行一件，由归档脚本追加与更新，按归档先后排列；出件开场先读它再决定读哪些原件。
「文本」列现在全是「原件」：将来转出的文本放原件旁同名加 `.md`，这一列指向它。

| 相对路径 | 是什么 | 归档日期 | 文本 |
| --- | --- | --- | --- |
| 材料/合同/扫描件/买卖合同.pdf | 甲乙双方买卖合同原件，含两页附件 | 2026-09-14 | 原件 |
| 参考/指南/受理通知.pdf | 法院对本类案件的材料清单与格式要求 | 2026-09-14 | 原件 |
```

归档日期取跑命令那天（`--date` 只给开发侧测试用）。「文本」列本版恒为「原件」：OCR 与 PDF 转文本是后续版本，到时才有别的值。
