# 图引擎

图是案件工作区根的单一 JSON `图.json`，律师不读它，读随图重算的 `图视图.md`。本 skill 持有它的唯一写入口：本目录的 `scripts/graph.py`（Python 标准库，零依赖）。所有写入都经这个 CLI：律师一句话改构成由模型调它落盘并回显，编排 skill 追加条目也调它。

起手之后案件图**自足**：状态、前方、时限、目录名全部只从图自己的内容算，引擎不读图外的任何东西。字段表与两份视图的形状见 [GRAPH-FORMAT.md](./GRAPH-FORMAT.md)。

## 怎么调

```
python <本目录>/scripts/graph.py [--graph 图.json] [--kind case|preset] <子命令> ...
```

- `--graph` 默认当前目录的 `图.json`；工作区就是会话当前目录。
- `--kind` 默认 `case`（案件图，写完重算两份视图）；`preset` 是预设图，可写时限、无条目、不出视图。
- 退出码 0 落盘；1 拒写（原因在 stderr，文件一字不动）；2 用法错。`--help` 与各子命令的 `--help` 是参数的权威。
- 节点与模块都可用 id 或标题指认。空白模板只写文件名（文件住 `参考/模板/` 下），或 `无`。

## 律师一句话到命令

| 律师说 | 子命令 |
| --- | --- |
| 在某模块下加一个节点 | `add-node --module <模块> --title <标题> [--template <文件名>] [--after <兄弟>]` |
| 把某节点标题改成…… | `rename-node --node <节点> --title <新标题>` |
| 某节点挪到某节点前面 / 挪到某模块下 | `move-node --node <节点> [--module <模块>] --before <兄弟>` 或 `--after` / `--first` / `--last` |
| 某节点用某模板 / 不用模板 | `set-template --node <节点> --template <文件名>` 或 `无` |
| 加一个模块 / 模块改名 / 模块挪到最前 | `add-module --title …` / `rename-module --module … --title …` / `move-module --module … --first` |
| 把空模块删了 | `delete-module --module <模块>`（有节点即拒，先 `move-node` 移走） |
| 某节点不适用 / 整个模块不适用 | `not-applicable --node <节点> --words "<原话>"` / `not-applicable --module <模块> --words "<原话>"` |
| 起手（由起手 skill 调） | `init --empty` 或 `init --preset <预设图目录>` |
| 把这个案子的图存成预设图叫 Y（由 skill "domain" 调） | `export-preset --out <个人预设图目录>` |
| 视图要跟上（律师在 Word 里去了黄之后） | `views` |

编排 skill 追加条目：`generate --node … --doc … --review …`（律师自写的兜底件加 `--lawyer-written`，来源记为律师）；`confirm --node … --words "<原话>"`。`--words` 原样存律师那句话，视图显示它。

## 改构成的规矩

- **一句话即落**：改构成没有确认点。律师说了就跑命令，把 CLI 的回显照读给律师，不先出示再问。**完成判据**：命令退出码 0，且回显已读给律师。
- **节点永不删**。律师说「删掉某节点」，答复是把它记不适用（`not-applicable`），误加的也一样。
- 引擎自己守的规则，拒了就照实转告：已确认的节点不能不适用（要改就重出一版）；不适用是终态；条目只追加，没有改和删；标题图内唯一，转义成目录名之后也唯一。
- **图自足**：图里没有的节点就是没有，引擎不去预设图里找。律师点名一个不在图里的节点，答复是先 `add-node`。要整批进图只有起手 `--preset` 整份拷入一条路。
- **时限只在预设图上写**。案件图的时限句由起手整份拷入，律师在案件图上写它会被拒；本案的基准日与具体截止日是案件事实，追加到 `材料/律师说过的.md`，由 skill "doit" 落。
- 拒写说「不合校验」时，`图.json` 被手改过或损坏了。告诉律师这一点，让律师从上一次能用的状态重来；模型自己修改 JSON 是这条规矩的反面。

## 目录名

节点标题与模块标题做目录名时，`/ \ : * ? " < > |` 由引擎换成同形的全角，规则只在引擎里定一次。要拼文书路径就读视图里算好的 `目录名` 列，不要自己转义一遍。

## 高亮是否已清

视图给每个节点算一列：当前文书不存在写 `无文书`，扫得出高亮写 `未清`，扫不出写 `已清`。引擎只用标准库读 docx，只认「有没有高亮」这一件事。

这一列是提示，不是裁定：**高亮已清不等于确认**。确认永远是律师在对话里说一句话，由 `confirm` 落条目。

## 预设图

预设图是一份构建完成、没有条目、带着空白模板的图，起手时整份拷进案件工作区。按归属分两处，能不能写不一样（归属说的是这一份随 skill 包出厂、还是住律师本机）：

- **个人**预设图住律师本机，由律师一句话从案件图另存（`export-preset`）而来，是唯一写得动的一份。开发者导入一份新的预设图也落在这里，再经 PR 进仓库。
- **出厂**预设图随 skill 包分发、住包内，谁都写不动，**开发会话也不行**：引擎无条件拒，没有放行口。包一升级它就被整个换掉，写进去的东西静默消失。

拒的只是写。出厂件的只读用法一条不碎：`validate`，以及起手 `--preset` 指着它整份拷入，全部照旧。

按名与归属解析出这两处的路径归 skill "domain"，引擎只收目录。

**图的唯一写入口这一条对预设图同样成立**：预设图也只经本引擎写。
