# 图引擎

图是案件工作区根的单一 JSON `图.json`，律师不读它，读随图重算的 `图视图.md`。本 skill 持有它的唯一写入口：本目录的 `scripts/graph.py`（Python 标准库，零依赖）。所有写入都经这个 CLI：律师一句话改构成由模型调它落盘并回显，编排 skill 追加条目也调它。图的字段与两份视图的形状见 [references/格式.md](references/格式.md)。

## 怎么调

```
python <本目录>/scripts/graph.py [--graph 图.json] [--domain <领域图或领域目录>] <子命令> ...
```

- `--graph` 默认当前目录的 `图.json`；工作区就是会话当前目录。
- `--domain` 指领域图：读工作区 `AGENTS.md` 里起手落下的领域目录路径，原样传（目录或其中的 `领域图.json` 都收）。有它才有前方与惰性带入；工作区没写领域目录就不带。
- 退出码 0 落盘；1 拒写（原因在 stderr，文件一字不动）；2 用法错。`--help` 与各子命令的 `--help` 是参数的权威。
- 节点与模块都可用 id 或标题指认。空白模板写法：`无`、`官方:<文件名>`、`生成:<文件名>`。

## 律师一句话到命令

| 律师说 | 子命令 |
| --- | --- |
| 在某模块下加一个节点 | `add-node --module <模块> --title <标题> [--template …] [--after <兄弟>]` |
| 把某节点标题改成…… | `rename-node --node <节点> --title <新标题>` |
| 某节点挪到某节点前面 / 挪到某模块下 | `move-node --node <节点> [--module <模块>] --before <兄弟>` 或 `--after` / `--first` / `--last` |
| 某节点用某模板 / 不用模板 | `set-template --node <节点> --template 官方:<文件名>` 或 `无` |
| 加一个模块 / 模块改名 / 模块挪到最前 | `add-module --title …` / `rename-module --module … --title …` / `move-module --module … --first` |
| 把空模块删了 | `delete-module --module <模块>`（有节点即拒，先 `move-node` 移走） |
| 某节点不适用 / 整个模块不适用 | `not-applicable --node <节点> --words "<原话>"` / `not-applicable --module <模块> --words "<原话>"` |
| 起手（由起手 skill 调） | `init --empty` / `init --full` / `init --from <定制图>` |
| 领域图更新后视图要跟上 | `views` |

编排 skill 追加条目：`generate --node … --doc … --source … --review …`（律师自写的兜底件加 `--lawyer-written`，来源记为律师）；`confirm --node … --words "<原话>"`。`--words` 原样存律师那句话，视图显示它。

## 改构成的规矩

- 一句话即落：改构成没有确认点。律师说了就跑命令，把 CLI 的回显照读给律师，不先出示再问。
- 节点永不删。律师说「删掉某节点」，答复是把它记不适用（`not-applicable`），误加的也一样。
- 引擎自己守的规则，拒了就照实转告：已确认的节点不能不适用（要改就重出一版）；不适用是终态；条目只追加，没有改和删；标题图内唯一。
- 严格惰性：律师点名的节点不在图里而领域图里有，引擎按领域图把它（及其模块）带入，不带同模块其他节点。要整批带入只有整份起手一条路。
- 拒写说「不合校验」时，`图.json` 被手改过或损坏了。告诉律师这一点，让律师从上一次能用的状态重来；模型自己修改 JSON 是这条规矩的反面。
- 时限只住领域图。案件图里给节点写时限会被拒；律师给出的本案具体日期是律师陈述，调用 skill "filing"。

## 领域图

维护领域图用同一引擎，加 `--kind domain`：节点可带时限句（`--time-limit`）、可给 `--id`，没有条目，不出视图。领域图住领域目录，由 skill "domain" 管，分两份，能不能写不一样（ADR-0019、ADR-0020）：

- 律师本机 `~/.loo0ng/领域/<领域名>/` 那份**活图**是唯一写得动的一份。办案会话里只有一条路：节点确认之后那一次逐节点回流，由 skill "doit" 驱动，一次一个节点，律师一句话拍板才写。开发者定制领域图走的是同一条路：办一遍、回流进自己的活图。
- 仓库里 `skills/engineering/domain/assets/<领域名>/` 那份**出厂种子**谁都写不动，**开发会话也不行**：`--kind domain` 的写落在包内，本引擎无条件拒，没有放行口。种子随包分发，写进去的东西下一次升级就被整个换掉；它改由**入库**更新（活图那份 `领域图.json` 进仓库，一次 git 提交，经第二双眼）。

拒的只是写。种子的只读用法一条不碎：`validate`、`views`，以及案件图拿它当领域图来源（`--domain` 指着它起手、算前方、惰性带入）全部照旧。这条规则只管 `--kind domain`。

**图的唯一写入口这一条对活图同样成立**：活图也只经本引擎写。
