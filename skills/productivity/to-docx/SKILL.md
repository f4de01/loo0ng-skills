# 填模板

**模型不重写整篇。** 代码把空白模板（或这个节点当前的文书）打成带编号的清单，模型只提交编号处的改动，代码在 docx 原件上原地施加：骨架、表格几何与槽外的格式由构造保住，删句、抹掉法院名、编一段事实在结构上做不到。本 skill 只持一个 CLI：`scripts/fill.py`，打清单（`list`）与施加差量（`apply`），只依赖 python-docx，离线。

**没有门禁。** 代码只做确定性规则里的前两种：字节原样保住（施加只落在槽的字符区间上，收尾无条件清元数据与留黄也是施加的构造）、被检查的一方是模型自己（拒掉模型写坏的差量）。文书合不合格是判断：撑列、页数、空白页这类由填进去的字多长决定的几何，律师出件后本来就在 WPS 里打开看，一句「写短点重出」就修了。

`--help` 是参数的权威。

## 跑得动脚本的环境

**约束的是后端版本，不是哪个解释器**。怎么弄到一个能跑 `fill.py` 的解释器（系统的、uv 管的、现装的）归你，正文不指定；**没配过 python 不得阻断出件**。要守的只有三条：

1. **能 `import docx`，且是钉住的那个版本**：[requirements.txt](requirements.txt) 精确钉 `python-docx==1.2.0`，随本 skill 分发到这台机器，`pip install -r` 与 `uv pip install -r` 都直接吃得下。
2. **装出来的东西只落在临时位置**：不进案件工作区（工作区里只有施加成功的东西），不进本 skill 目录与本仓库，也别装进用户全局环境。
3. **不静默**：`apply` 回显第二行给出这次用的解释器与实测到的 `python-docx` 版本，原样抄进审查报告的「生成依据」段。**版本对不上照常出件**（退出码不因此变成非零），那一行里会明写它不是钉住的那个版本，照抄即可。

一条**走通过**的路（在 Codex 的 full-access 沙箱里走通的，那里系统 `python` 敲不动）：

```
uv python find                                                    # 拿到 uv 管的解释器，记作 <它>
uv pip install --python <它> --target <临时目录> -r <本目录>/requirements.txt
PYTHONPATH=<临时目录> <它> <本目录>/scripts/fill.py ...           # Windows 上是 set PYTHONPATH=...
```

**这只是走通过的一条路，不是唯一路**：手边的解释器已经装着钉住的那版 python-docx 就直接用它，uv 不在就另想办法。**受限沙箱（Codex `workspace-write`）下这条路实测走得通**，两个条件：uv 与至少一个 uv 管的解释器已经在那个模式读得到的地方（沙箱里装不了新解释器）；uv 的缓存要指到能写的地方，默认缓存写不动时上面三条命令都要加 `--cache-dir <临时目录>`，或先设 `UV_CACHE_DIR`，否则第一条就退 2。**律师那台 mac 上能不能，仍未验证**，别把它当成已验。

## 出一版的四步

载体是该节点的**空白模板**（`参考/模板/<文件名>`，图上那个节点的属性指认它）；重出时载体是**这个节点当前的文书**（`文书/<模块>/<节点>/<标题>.docx`）。

1. **打清单**：

   ```
   python <本目录>/scripts/fill.py list <载体.docx>
   ```

   一段一行：`p<编号>`（正文里全部段落按文档顺序，单元格里的段落也在序列里，行前标 `[表1 行2 格1]`）、槽写成 `⟦1 XX年X月X日⟧`（一段里从左到右编号）、已经是高亮的区间写成 `⟪…⟫`、「（注：…）」开头的段前标 `[说明]`。**整读一份指南或一份现成文书**用同一条命令加 `--plain`，出不带任何标记的纯文本。

   **完成判据**：清单读完，知道每个 `p<编号>#<槽号>` 对应的是哪句话里的哪个空。

2. **写差量**：一个 JSON 数组，一条一个改动，只有五种（写法见 [DIFF-FORMAT.md](./DIFF-FORMAT.md)）：

   ```json
   [{"op":"fill","at":"p2#1","text":"某年某月某日"},
    {"op":"fill","at":"p2#8","text":"某某","highlight":true},
    {"op":"replace","at":"p2","old":"XX公司（债权人名称）","new":"某甲公司"},
    {"op":"delete","at":"p14"},
    {"op":"highlight","at":"p3","text":"没把握的那句"},
    {"op":"unhighlight","at":"p7"}]
   ```

   三条规矩：**材料里没有的值一个不编**：没有的槽干脆不写进差量，代码会替你留黄（写 `fill` 空串也按没填处理，一样留黄，不必为此改差量）；**没把握的写了要加 `highlight: true`**，黄色的意思只有一个「这里要律师动手」；**模板自带的高亮（清单里的 `⟪…⟫`）你解决了的要显式 `unhighlight`**，没解决的留着交给律师。不带任何标记的提示文字（`（债务人名称）`、`（如有）`）与整段的条件块只能用 `replace` 按原文指认，原文在那一段里须唯一。

   **完成判据**：差量里的每一条都能在清单上指出它改的是哪一处；没有一条是整段重写。

3. **施加并落盘**：

   ```
   python <本目录>/scripts/fill.py apply <载体.docx> --diff <差量.json> --out 文书/<模块>/<节点>/<标题>.docx
   ```

   `--out` 直接写 `文书/` 下的路径，**已存在就覆盖**：一节点一份文书、不留版本，重出覆盖同一份，载体与产物可以是同一路径。差量 `.json` 先写在临时目录里；**工作区里不建任何暂存目录**（`_staging/`、`tmp/`、`草稿/` 之类都不要）：工作区里只有施加成功的东西。律师只说「这稿子填一下」时那不是一次生成，不给 `--out` 它写到 `%TEMP%/to-docx/` 并打印路径，不进 `文书/`、不写审查报告、不动图。

   施加完后**没被填也没高亮的槽由代码一律加黄**，模型不必逐个写；元数据（作者、最后修改者、上次打印时间）收尾无条件清掉。退出码 1 是拒改：差量不合法（槽号越界、`replace` 的原文不唯一、两处改动区间重叠），或槽所在 run 含脚注引用、图片、域代码（切开会把它们复制、换字会把它们丢掉）。拒改的件**一个字都不写**，`--out` 指的已有文书原样不动，按 stderr 改差量重来。

   **完成判据**：`文书/<模块>/<节点>/` 下有这一版文书，回显在手。

4. **回显抄进审查报告**：`apply` 的回显分两块，都照抄进审查报告（格式见 [REVIEW-FORMAT.md](./REVIEW-FORMAT.md)）：「高亮清单」那一行之前是**施加原话**（第一行写出的路径、第二行出件环境（同时抄进「生成依据」末条）、第三行改动段、其后逐条改动与留黄）；「高亮清单 N 处」那一行起到末尾是**高亮清单**，一处一行：段落号（提示用）、单元格段的表格坐标、高亮处原文、记录时整段文字。前一块是这一版「代码做了什么」的唯一留痕，后一块是下次重出认律师填没填的键。

   **完成判据**：`文书/<模块>/<节点>/` 下有这一版文书与它的审查报告，图上有那条生成条目，**三件缺一不可**，落条目那一步由 skill "doit" 驱动。

拒改就按 stderr 改差量重来**至多 2 次**；**改的是差量，不是模板规定的正文结构**（表、落款、附注）。仍拒即**生成失败**：把拒改原文交给律师，不交出半成品，律师可兜底自写。永远不要为了绕开拒改把临时件手动拷进 `文书/`。

## 律师只问这份模板有哪些槽要填

不出件、不写差量、不动模板原件：只对他指的那件 DOCX 打一次 `list`，把清单**照编号读给他**，一处一行，`p<编号>#<槽号>` 起头，跟上它落在哪句话里、要填的是什么；末尾报一句总共几处。别把编号压成「第几段共几处」这样的概括，律师下一句点名要改哪一处时，用的就是这个编号。

## 重出

律师在 Word 里填了黄色处（去不去黄都行）之后说「重出」：载体是这个节点当前的文书，四步照走，第 1 步之后多一步**判律师填了哪些**。这是判断，归你，不写比对代码：读当前清单，对照上一次审查报告的「高亮清单」，先认出是哪一段：正文段按记录时整段文字认（律师可能在前面插了段，段号会飘，整段文字仍相似），单元格段按表格坐标认（那种段多半整段就是那一个槽，填了就整段都变）；同段里两处原文相同就按顺序对。再对每处高亮逐处判：

| 当前清单里 | 判为 | 差量里写 |
| --- | --- | --- |
| `⟪…⟫` 里的文字与记录的原文相同 | 律师没动，仍待填 | 有材料就 `fill`（填了自然去黄），没有就不写、继续留给律师 |
| `⟪…⟫` 里的文字与记录的原文不同 | 律师填了、没去黄 | 只写一条 `unhighlight`，文字一个不碰 |
| 记录里有、当前清单里已不是高亮 | 律师填了又去了黄 | 不写、不碰 |
| 律师点名的位置 | 照改 | 按点名写，改完不加黄 |

律师改过的位置一律不碰、不查；差量只对仍高亮处与点名处写。上一次报告是「律师自写」（没有高亮清单）时，当前文书里的黄全是律师自己加的，一处不动，只改点名处。

**完成判据**：差量里每一条 `unhighlight` 都对应一处文字变了的 `⟪…⟫`，每一条 `fill` 都对应一处文字没变的槽或一处点名；清单上其余的 `⟪…⟫` 一条差量都没有。

三条已知行为，真出一次事故再按尺子进代码：

- 律师在记过高亮的段落里**自己新加的黄**，原文不在记录里，会被你当成填过的去掉；在没记过的段落里加的黄不会。
- **没把握的句子与不带标记的提示文字**上的黄若被误去，代码兜不住：`unhighlight` 只改格式、律师的字一个不会被改到，但律师少一处「看这里」。
- **占位形状的槽**误去黄不用担心：`apply` 收尾全篇留黄自动纠回。

## 占位的形状

`XX`、`（20XX）`、`XX年X月X日`、`【…】`、下划线串、带量词的单个 `X` 是 `fill.py` 自带的一张表，**形状可加**：律师自己的空白模板换一套占位习惯时改那张表，只对一次调用临时加就用 `--slot-pattern <正则>`（`list` 与 `apply` 同名同写法，加了就两步都要加，否则清单与留黄会看见不同的槽）。不做姓名词表。

## 与邻居的边界

- 本 skill 不决定写什么：材料、指南、空白模板、同模块在前的已确认文书的整读与差量的内容由 skill "doit" 负责；缺的事实照留黄，不停下来问。
- 空白模板住 `参考/模板/`，起手时由预设图整份拷进来（skill "domain"、skill "setup-case"）；本 skill 只读它。
- 本 skill 不对文书下判断：没有门禁、没有阈值、没有「测不准」那一档。律师改过的位置不碰、不查。
- **确定性规则只有三种**：字节原样（施加本身的构造，如收尾无条件清元数据与留黄）、被检查的一方是模型自己（拒掉模型写坏的差量）、对律师文件的写入可重放。事故先来、规则后进：一次事故先问它落不落进这三种之一，落进的才成 `fill.py` 的一条构造，并配一对钉住它的测试；落不进的写进正文或 eval 用例，不预写检查。
