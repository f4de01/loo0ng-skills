# 兜底件审查报告

律师说「X 我自己写好了」时给那一版写的审查报告：段与顺序同 skill "loo0ng-to-docx" 的 `references/审查报告.md`（五段固定），内容照下面填。文件落在 `文书/<节点标题>/<节点标题>-v{n}-审查报告.md`，`{n}` 是这个节点算上这一版的生成条目数。

本工作台没有参与这一版的写作，所以前三段都不编：**不读文书内容替律师作判断，也不猜他用了什么材料**。门禁那一段是这份报告唯一有实质内容的地方，只披露不阻断。

```markdown
# <节点标题> 第 <n> 版审查报告

这一版不是本工作台出的：文书由律师自己写成，经一句话登记为已生成，来源记为律师。登记那句话：「<律师原话>」。文书原件在 `<文书相对路径>`，登记时刻 <ISO 时刻>。

## 生成依据

无。本工作台没有参与这一版的写作，不掌握它用了哪些材料、模板与过往文书。

## 存疑点

无。兜底登记不读文书内容，也不对它作判断。

## 待律师裁定

无。要对这一版提意见，在本对话里说一句重出（新版有它自己的审查报告）。

## 版式门禁

<把 gate.py 的输出原样贴进来：结论（通过 / 需人眼 / 不通过）、不通过项、需人眼项、披露项；结论后加一句
「兜底件，不阻断」。结论是需人眼时，门禁那段须目验清单原样放在报告开头（第一段），格式见 skill
"loo0ng-to-docx" 的 references/审查报告.md；兜底件本来就不阻断，这一档同样不改文书、不重转。
不是 DOCX 的写：未跑。这一版不是 DOCX，门禁只对 DOCX 跑。>

## 时限

<节点有时限句就照 skill "loo0ng-to-docx" 的 references/审查报告.md 写规则、基准日、推算截止日三行；
基准日只认材料与律师陈述，缺就写「基准日缺失」；没有时限句就写一行「无明示时限」。>
```

## 与起手登记的差别

起手清单里既有成品的登记由 skill "loo0ng-setup-case" 的 `setup.py register` 机械落地，那份报告的门禁段固定写「未跑」。本 skill 的兜底登记发生在办节点的对话里，DOCX 要跑一次门禁，两类项照写。两处都只登记为已生成，确认永不自动。
