# 办节点

**一个对话只服务一个节点**（`CONTEXT.md`「回合」，ADR-0008、ADR-0010）：出件、补事实、要求重出、最后一句确认或不适用，都在这个对话里；下一个节点开新对话。隔夜拍板是新对话、同一个名字。

前置：工作区就是会话当前目录，`图.json` 是它的身份标记（ADR-0007）。没有 `图.json` 就拒绝，告诉律师先在案件目录里开会话，还没起手就调用 skill "loo0ng-setup-case"。领域目录的绝对路径在工作区根的 `AGENTS.md` 里，凡要 `--domain` 的命令都从那里读。

本 skill 自己没有脚本，四件事都经别人的 CLI 落盘：图经 skill "loo0ng-graph"，归档与陈述经 skill "loo0ng-filing"，转换与门禁经 skill "loo0ng-to-docx"。

## 律师那句话 = 动作 + 节点 + 补充

| 律师说 | 去哪一节 |
| --- | --- |
| 「出一版 X」「X 重出一版」「按法院的意见改 X」 | [出一版](#出一版) |
| 「X 我自己写好了」「X 用我这份」 | [兜底登记](#兜底登记) |
| 「确认 X」「X 这份就这样，可以了」 | [拍板](#拍板) |
| 「X 不适用」「模块 Y 本案不办」 | [拍板](#拍板) |

补充可带「以第 n 版为底」「用某模板 / 某过往文书」与对内容的要求，照办即可，不改动作的判定。节点用图内唯一标题指认；律师说的名字与图里不完全一致时，找最接近的那个并在回显里写出你按哪个节点办的，别自己新建一个同义节点。

## 三条留痕规则

确认与不适用是律师专权，保护不在入口门上而在留痕与可逆上（ADR-0010）：

1. **原话原样存**。`--words` 里是律师那一句，一个字不改、不润色、不概括；`图视图.md` 显示的就是它。
2. **只在律师明确说出「确认」或「不适用」且指向本节点时落条目**。从「看起来没问题」「律师没提意见」推断出来的确认不落；律师问「这份行吗」不是确认；模型永不代律师拍板（ADR-0002）。拿不准就问一句，别先落再问。
3. **同一对话第二次「出一版」指向另一节点即拒绝**：告诉律师这个对话已经在办哪个节点，办完这个再开新对话办那个，并把下一句该打什么给他。同一节点重出不拒（那还是这一个回合）；拍板不限次数、也不受这条约束。这一条在[出一版](#出一版)的死顺序里有它自己的一步（第 3 步），办「出一版」时照那个顺序走就会走到它。

## 拍板

一句话即落，没有第二次确认，不先出示再问。

```
python <loo0ng-graph 的 scripts/graph.py> --domain <领域目录> confirm --node <节点标题> --words "<律师那句话>"
python <loo0ng-graph 的 scripts/graph.py> --domain <领域目录> not-applicable --node <节点标题> --words "<律师那句话>"
python <loo0ng-graph 的 scripts/graph.py> --domain <领域目录> not-applicable --module <模块标题> --words "<律师那句话>"
```

- **模块不适用**由引擎把该模块在领域图里的全部节点带进案件图、再逐个记一条不适用，模型不必先逐个 `add-node`。
- 引擎自己守的规则，拒了就把它的原话照实转告，别绕：已确认的节点不能不适用（要改就重出一版）；不适用是终态；只有已生成的节点能确认；模块里有已确认的节点时整个模块不适用被拒。
- 确认之后节点就完成了，这个对话到此为止，收尾按下面的三段写；落完确认条目还有一步，见[确认之后问一次归属](#确认之后问一次归属)。
- 律师说「删掉 X」时答复是记不适用，节点永不删（ADR-0003）。

### 确认之后问一次归属

律师侧逐节点回流（ADR-0019）：确认之后，若领域图里没有这个节点，问一次它在领域图里该归哪儿，律师一句话之后写进**活图**。这是律师累计自己那张领域图的唯一机制。只挂在「确认」之后，不适用不做，生成中间不做（ADR-0008 的确认点不变）。

1. **先判缺不缺，缺才问。** 确认落盘时引擎已重算视图，`图视图.md` 里这个节点那一行带着「来源」：**「领域图」就一个字不问**，直接收尾；「案件」才往下走。这是按 id 的反向减法，引擎算好的，别自己比标题。走熟一个领域之后这一问趋近于零，只有真正的新节点才会再问。

2. **一次一个问题，带两个默认值回显：**

   > 「<节点标题>」领域图里还没有。写进你的领域图的话，我按这两样写：模块「<它在案件图里所在的那个模块>」，标题「<去案件化之后的写法>」。要改模块或标题就说一句；说「不用」就不写。

   模块默认继承它在案件图里所在的那个；标题默认是去案件化后的写法，**口径照 skill "loo0ng-domain" 的 `references/回流.md`（去掉案号、当事人、具体日期与本案特有的说法），两条路同一套，别自己另想一套**。改的只是标题，不动案件图里那个节点一个字。**不问时限**：律师侧新增的节点没有时限属性，缺省（ADR-0019）。

3. **未拍板不写。** 律师那一句之前活图一个字不动；他说「不用」「以后再说」或干脆没答，就到此为止，不写、不再问第二次。

4. **拍板后写入，一条命令，经引擎写活图**（图引擎是图的唯一写入口，活图也不例外）：

   ```
   python <loo0ng-graph 的 scripts/graph.py> --graph <领域目录>/领域图.json --kind domain \
       add-node --module <模块标题> --title <标题> --id <案件图里那个节点的 id> --template 无
   ```

   - **id 用案件图里那个**：换新 id，本案的前方立刻多出一个与自己重复的节点。
   - 律师改了默认值就**按他说的写**：换模块就换 `--module`，改标题就换 `--title`。
   - 那个模块领域图里也没有：先 `add-module --title <模块标题> --id <案件图里那个模块的 id>`，再写节点。
   - **空白模板**：官方的原样带（`--template 官方:<文件名>`，那件原件就在领域目录的 `模板/` 下），`模板/生成/` 里那件是本案的、领域图指不到它，与没有模板的一律 `无`。
   - 写完还要改：跨模块移动 `move-node`、改标题 `rename-node`、模块改名 `rename-module`，都带 `--kind domain` 指着活图，不新增 CLI。
   - 引擎拒了就照实转告，别绕。常见的一条是活图里已有同名不同 id 的节点，那说明它其实已经在图里了，不必再写。
   - **另一条是这个工作区的领域目录还指着 skill 包内的出厂种子**（0.1.0 起手、没手改过那一行的工作区就是这个形状）。种子谁都写不动，引擎无条件拒（ADR-0020）：写进去的东西下一次 skill 包升级就被整个换掉。**提案照样回显**，然后把引擎那段话照实转告：它已经写明活图在哪、路径怎么取；换法在 skill "loo0ng-setup-case" 正文里，**那一行由律师自己改，别替他改**。换完之后往下每个节点照常写得进；这个节点这一次没写成，不在这个对话里想别的办法补。

5. **没有第二双眼**（ADR-0019）：活图在 skill 包与本仓库之外，硬边界 1 与隐私钩子都管不到它；去案件化在这条路上是可用性问题（别让 A 案当事人的名字出现在 B 案的图里），不是隐私门禁。所以标题这一样要自己写干净，别把当事人、案号、金额、日期带过去。

机制的主人是 skill "loo0ng-domain"，两条路的规矩在它的 `references/回流.md`；开发侧批量那条不在办案会话里做。

## 兜底登记

律师说「X 我自己写好了」：那份文书是他写的，**永不改动、不重转、不搬**（ADR-0002）。

1. 文件在收件箱里就先归档（调用 skill "loo0ng-filing"，成品文书归 `材料/`）；在工作区外就拷进 `材料/` 下，原件不动；已经在工作区里就原地登记。条目里记的相对路径就是它当前的位置。
2. 是 DOCX 就跑一次门禁（调用 skill "loo0ng-to-docx" 的 `gate.py`，**不带 `--deliver`**）。门禁**只披露不阻断**：三档结论、不通过项与需人眼项照样写进审查报告（结论是需人眼就把那段须目验清单放在报告开头），不因此拒绝登记、不改文书、不重转。**退出码非零不等于登记失败**：兜底件跑门禁只为取结论。不是 DOCX（`.md`、`.doc`、扫描件）就不跑门禁，报告里照实写未跑。
3. 按 [references/兜底件审查报告.md](references/兜底件审查报告.md) 写一份审查报告，落在 `文书/<节点标题>/<标题>-v{n}-审查报告.md`（`<标题>` 就是节点标题，`{n}` 是这个节点算上这一版的生成条目数）。每一版文书必有一份审查报告（`CONTEXT.md`「审查报告」）；律师那份文书留在他放的位置、报告落进这个节点的文书目录，两条相对路径都在条目里，条目才是文书的身份（ADR-0007）。起手时既有成品的登记同一个形状（skill "loo0ng-setup-case"）。
4. 追加生成条目，来源记律师：

   ```
   python <loo0ng-graph 的 scripts/graph.py> --domain <领域目录> generate --node <节点标题> \
       --doc <文书相对路径> --review <审查报告相对路径> --lawyer-written
   ```

登记只是已生成，**不是确认**：律师要确认，还得读过报告后再说一句（本对话里就可以）。

## 什么算一次生成

**一次生成 = 三件加一条条目**：文书、Markdown 源（兜底件可以没有）、审查报告，与图上那一条带着相对路径的生成条目，缺一即生成失败（`CONTEXT.md`「审查报告」）。工作台出的那版三件都落在 `文书/<节点标题>/`；兜底件的文书留在律师放的位置，报告仍落进那个目录。由此两条，本 skill 不在时两个 harness 会各走各的（#28）：

- **单跑转换与门禁不是一次生成**。律师只说「把这稿子转成 word」「这份 docx 检一下」时，产物留在临时位置或律师指的位置，**不落进 `文书/`**、不写审查报告、不动图；门禁本来就可以单独对任意 DOCX 跑。要它成为这个节点的一版，走本 skill 的[出一版](#出一版)或[兜底登记](#兜底登记)。
- **生成条目只有一条来路：本 skill**（ADR-0008「一类写入一条来路」，`draft` 与 `decide` 由 ADR-0010 并成本 skill）。参考 skill 被律师一句话够到之后只做转换、门禁、搬运、落档，不自行追加生成条目，也不自己补写审查报告。

## 出一版

顺序是死的，中间不停下来问：**归档 → 复制律师指的文件 → 换节点检查 → 惰性建节点 → 三样全无则只回缺什么 → 整读 → 写稿 → 转换 → 门禁 → 落盘 → 追加条目 → 回显**。

### 1. 开场归档

调用 skill "loo0ng-filing"：先 `archive.py list`，逐件判去向搬完，拿不准的留在收件箱并说一句为什么。收件箱空就不必回显这一步。

### 2. 复制律师指的文件

律师在对话里指的盘外文件都要落进工作区（ADR-0007），否则下一个对话看不到它：

- 本案的材料：拷进 `材料/`，原文件名不改。
- **别案的成品文书：不整份复制**。剔除案件内容（当事人、案号、日期、金额、地址）后作为空白模板存进 `模板/生成/`，再用它出件。把 A 案的成品带进 B 案是硬错。
- 律师在对话里给出的、盘上没有的事实：见下面的[生成不问缺事实](#生成不问缺事实)。

### 3. 换节点检查

这个对话已经就某个节点走过一次「出一版」，而这一句指向的是**另一个**节点时，到这一步就停：不建节点、不整读、不出件，图一个字不动，那个节点的回显只有这两行：

> 这个对话在办「<本对话正在办的节点>」，办完它再开新对话办「<律师刚说的那个节点>」。
> 新对话的第一句：`loo0ng-doit 出一版 <律师刚说的那个节点>`。

律师一句话里连着点了两个节点（「出一版 A，出完接着出一版 B」）也走这一步：A 照常往下走完，B 在这里被拒，两件事写在同一条回复里。**A 落进第 5 步「三样全无」这一支也不改变 B 被拒这件事**：缺什么与换节点被拒是两个节点各自的结果，不是二选一。被拒的那个节点**不在这个对话里算它缺什么**：要算就得去读它的模板与材料，那已经是在办它了，与拒绝自相矛盾；缺什么留给它自己那个新对话的第 5 步答。

**什么样的回复算没走这一步**：把两个节点并进同一句（「A 和 B 都缺材料、指南与空白模板」）算没走；只答了 A、B 一个字没提也算没走。这不是「格式略有出入」，内容答得再对也一样。发出去之前数一遍：律师这一句里点了几个节点，回复里就得有几段各自的结果，被拒的那个身上原样带着上面那两行。

同一节点重出不拒（那还是这一个回合）；拍板不受这条约束（[三条留痕规则](#三条留痕规则)第 3 条，ADR-0010）。

### 4. 惰性建节点

节点不在图里就由引擎按领域图带入（`add-node --module <模块> --title <标题>`，标题与领域图里某节点相同则连模块一并带入），不带同模块其他节点。领域图里也没有的，按律师说的标题新建，空白模板属性照他说的写。

### 5. 材料、指南、空白模板三样全无

这个节点手上一样能读的都没有（`材料/` 与 `材料/律师陈述/` 空、`指南/` 空、这个节点没有空白模板）时，**只回缺什么，不出件**：这不算一次生成失败，图一个字不动（ADR-0008）。回显里写清缺哪几样、律师可以怎么补（拷进收件箱、在对话里说一句事实、指一份模板），下一句仍是在这个对话里继续办这个节点。**这句「继续办这个节点」只说给本对话正在办的那一个**：同一句话里另有节点在第 3 步被拒时，那个节点写的是第 3 步那两行「开新对话」，两者同时出现在回复里，不因为这个节点缺件就把那个节点的拒绝咽回去。

### 6. 整读

不摘要、不抽样，整份读：`材料/` 全部（含 `材料/律师陈述/` 里现行的那些，未被任何文件指为取代目标的才是现行）、`指南/` 全部、这个节点的空白模板（`模板/官方/` 或 `模板/生成/`）、这个节点已有的过往文书（`文书/<节点标题>/`，「以第 n 版为底」就以那一版为底）。DOCX 读不动就用 skill "loo0ng-domain" 的 `docx-text` 打成纯文本。

一个对话只办一个节点、下一个对话重新读一遍，这是接受的代价（ADR-0008），别为省事跳过。

### 7. 写稿、转换、门禁、落盘

调用 skill "loo0ng-to-docx"，三步照它的正文走：按最小集写 `.md`（写在 `%TEMP%` 里，**工作区里不建任何暂存目录**）、`md2docx.py` 转到临时位置、`gate.py --deliver 文书/<节点标题>/<标题>-v{n}.docx` 通过才落盘。版本号 `{n}` 是这个节点算上这一版的生成条目数。

门禁结论三档（ADR-0017）。**通过与需人眼都落盘**，一次生成照常成立；**重试只数不通过**：按不通过项改稿重转重检**至多 2 次**，仍不通过就是**生成失败**：

**改稿只改字句，不删模板规定的正文结构**（表、落款、附注）。不通过项指着模板带来的几何（行高、表宽）时，改稿改不动它，直接判生成失败；把被点名的那张表改写成正文段落会让门禁转为通过，但交出去的是一份缺了正文结构的件：一份没有账户表的账户备案报告（#107）。门禁的「模板表缺失」现在拦这一条，别靠它兜底。

仍不通过时：不落盘、不追加条目、不写审查报告，把门禁输出原文交给律师，告诉他可以兜底自写。永远不要为了过门禁调阈值、跳过门禁、或把临时件手动拷进 `文书/`。

结论是**需人眼**时不重试、不改稿：把门禁那段**须目验清单原样放进审查报告的第一段**（在「生成依据」之前，一个字不改），收尾回显里把清单上的坐标念给律师听。退出码 3 是需人眼，**非零不等于失败**；只有 1 是不通过。缺渲染器不阻断出件，但 agent 不许把需人眼说成通过。

落盘后把稿子拷成同名 `.md`、按 skill "loo0ng-to-docx" 的 `references/审查报告.md` 写 `-审查报告.md`，三件同目录。

### 8. 追加生成条目

```
python <loo0ng-graph 的 scripts/graph.py> --domain <领域目录> generate --node <节点标题> \
    --doc 文书/<节点标题>/<标题>-v{n}.docx --source 文书/<节点标题>/<标题>-v{n}.md \
    --review 文书/<节点标题>/<标题>-v{n}-审查报告.md
```

三件都落了才追加条目：条目里的相对路径是文书的身份，指着不存在的文件就是坏账。

## 生成不问缺事实

材料里没有的案号、日期、金额照出，缺项列进审查报告的「待律师裁定」，**生成中途不停下来问**（ADR-0008）。律师读了报告在对话里答一句：

1. 先落成陈述（调用 skill "loo0ng-filing" 的 `statement.py`，`--reply` 指向那份审查报告），回显一行。**不在盘上的事实不是材料**（ADR-0013）：审查报告的依据必须可引，下一个对话看不到这一句。
2. 再据此重出一版，仍在同一个回合、同一个对话里；新版有它自己的审查报告。

律师对某个问题作的选择（先办哪个、按哪种口径写）是 `性质: 裁定` 的陈述，不是图里的条目。

## 收尾三段

每次回答都以这三段结束，与别的入口同形（ADR-0008）：

1. **落了什么**：文书与审查报告的相对路径、图里追加了什么条目、归档搬了几件、落了几条陈述；确认之后写进活图的那个节点也算一样，写清落在哪个模块下、标题是什么。
2. **你现在该拍板什么**：审查报告的要点（存疑点、待律师裁定项逐条），请律师读过报告再拍板。确认之后[问了归属](#确认之后问一次归属)的，这一段就是那一问，原样写在这里等律师一句话。
3. **下一句该打什么**：出一版与兜底登记之后固定两行：

   > 本节点在本对话里拍板：说一句「确认 <节点标题>」或「<节点标题> 不适用」。
   > 下一个节点开新对话：`loo0ng-doit 出一版 <下一个节点标题>`。

   拍板之后这个对话就结束了，收尾只说下一个节点开新对话；不知道下一个办什么就打 `ask-loo0ng`。归属那一问还没答时，先说它，再说下一个节点开新对话。

## 与邻居的边界

- 图的唯一写入口是 skill "loo0ng-graph"：本 skill 不直接改 `图.json`，引擎拒写就照实转告，不自己修 JSON。
- 归档搬运与律师陈述落档归 skill "loo0ng-filing"；转换器、门禁与审查报告格式归 skill "loo0ng-to-docx"；官方模板原件、领域目录与回流机制归 skill "loo0ng-domain"（本 skill 只在确认之后驱动律师侧那一问）；起手归 skill "loo0ng-setup-case"，本 skill 不建工作区。
- 律师问「我在哪、下一步做什么」是 skill "ask-loo0ng"，它只读、不写图。
- 本 skill 不含领域语义：换一个领域，这套步骤一字不改。
