# 审查报告格式

每一版文书必有一份审查报告，与文书一起落盘，缺一即生成失败；面向这一版文书、只对文书负责（`CONTEXT.md`「审查报告」）。文书本体以直接可提交为目标，一切标注都在这里。格式归本 skill（ADR-0006、ADR-0013、ADR-0016），由 skill "loo0ng-doit" 出件时照写。文件名与文书同名加 `-审查报告.md`，落在 `文书/<节点标题>/`。

## 五段固定，顺序固定

```markdown
# <文书标题> 第 n 版审查报告

## 生成依据
## 存疑点
## 待律师裁定
## 版式门禁
## 时限
```

门禁结论为**需人眼**时，标题之后、「生成依据」之前另有一段**须目验清单**，见下节。它是唯一会插在五段之前的东西，且只在那一档出现。

### 生成依据

逐条列这一版用到了什么：材料按工作区内相对路径；空白模板写明是官方模板还是生成模板、文件名；过往文书写版本；律师陈述按下节的引用格式。没有用到的类别不列。

末一条是**出件环境**：把 `scripts/md2docx.py` 回显第二行那句原样抄过来（这次用的解释器与实测到的 `python-docx` 版本）。**恒常写**，不只在版本对不上时写；对不上时那句里自带「这不是钉住的那个版本」，照抄、不改一个字、也不因此拦下这一版（ADR-0018）。转换器与它的后端版本正是「这一版用到了什么」，所以进这一段，不新开第六段。

### 存疑点

agent 拿不准但已按某种理解写进文书的地方：写在文书哪一段、按什么理解写的、另一种理解是什么。不含缺的事实（那是待律师裁定）。

### 待律师裁定

材料里没有、文书里照出的案号、日期、金额等，一条一行，写明文书哪一处、缺什么；律师答一句就落成陈述再重出（ADR-0008）。**转述值与书面材料冲突**不停下来问，列进这里：写明哪份陈述（按引用格式）与哪份材料、两个值各是什么。

### 版式门禁

把 `scripts/gate.py` 的输出原样贴进来：结论（通过 / 需人眼 / 不通过）、不通过项、需人眼项、披露项。通过时写「通过」再列披露项；律师兜底自写的文书门禁只披露不阻断，这一段照样写门禁的原话，结论后加一句「兜底件，不阻断」。披露项里的空单元格坐标由律师判断是不是纸质要件（通用裁定台账 #13）。

**agent 对结论没有写权**（ADR-0006、ADR-0017）：不把「需人眼」写成「通过」，不把区间说成点值，不替门禁下判断。这一段只做一件多余的事：把不确定项翻译成人话，写在门禁原话之后。

## 须目验清单（只在结论为需人眼时）

结论为需人眼时，`scripts/gate.py` 另出一段固定格式的清单。它**由门禁生成，不由模型撰写**：原样放在报告的第一段，一个字不改、不重排、不合并进「版式门禁」那一段。

```markdown
须目验清单
- 最大行高：第 1 页第 1 张表第 2 行；推算 196.0～231.5 磅，阈值 200.0 磅；最坏越界 31.5 磅
- 页数：全篇；推算 28～38 页，阈值 30 页；最坏越界 8 页
确认前请在 WPS 或 Word 里打开看这几处。
```

每行一项，四样齐全：**项名、坐标、推算区间与阈值、最坏越界幅度**。项名只可能是页数、空白页、最大行高三个之一（其余七项判据恒为二值，不产生这一档）。

它存在的理由：需人眼件照常落盘，而图里不记这一档，所以「已生成」不再唯一等于「过了门禁」，判断依据只剩这份报告（ADR-0017 后果段）。鸡蛋全在这一个篮子里，篮子就得是结构而不是散文。它把律师本来就要做的那次确认，从「泛泛读一遍报告」变成「去看这几个坐标」。

### 时限

固定一段，写节点时限句的推算（ADR-0016）：

```markdown
## 时限

规则：自收到指定管理人决定书之日起 3 日内（手册，法院要求）
基准日：甲年乙月丙日，[律师陈述·直接陈述] 材料/律师陈述/20260906-102030-收到指定决定书日期.md：收到日 甲年乙月丙日
推算截止日：甲年乙月己日（不顺延节假日）
```

三样并列让律师一眼能复核。基准日只认材料与律师陈述，永不用条目时间；不顺延节假日；节点没有时限就写一行「无明示时限」；基准日缺失写「基准日缺失」并把它列进待律师裁定。时限句从领域图按节点 id 查出，案件图里没有。

## 引用律师陈述

按文件相对路径引用，附性质标签与所引的值，只引现行陈述（未被任何文件指为取代目标的那些）：

```
[律师陈述·直接陈述] 材料/律师陈述/<文件名>：<项目> <值>
[律师陈述·转述] 材料/律师陈述/<文件名>：<项目> <值>
[律师陈述·裁定] 材料/律师陈述/<文件名>：<问题> <裁定>
```

多值陈述再加「之『项目』」指到整理表的行，不引行号。三档来源强度要在报告里看得出：转述低直接陈述一档，裁定是选择不是事实。报告面向那一版文书，引用后来被取代的陈述不算错。

## 最小样例（合成，甲乙丙占位）

```markdown
# 关于管理人印章备案的报告 第 1 版审查报告

## 生成依据

- 官方模板：模板/官方/1-2.关于管理人印章备案的报告.docx
- 材料/刻章回执.pdf
- [律师陈述·直接陈述] 材料/律师陈述/20260906-102030-印章启用日期.md：启用时间 甲年乙月丙日
- 出件环境：解释器 /usr/bin/python3（python 3.9.6）；python-docx 1.2.0（与依赖清单钉的一致）

## 存疑点

- 印章名称一栏按回执写了两枚章；回执上第二枚章的名称有涂改，按涂改后的写。

## 待律师裁定

- 文书第二段的裁定书案号：材料里没有裁定书，照出为空。

## 版式门禁

版式门禁：通过
不通过项：无
披露项：
- 空单元格：第 1 张表 第 2 行第 2 格
- 页数：1
- 请求字体不在嵌入字体里：方正小标宋简体（嵌入：FangSong、MicrosoftYaHei）

## 时限

无明示时限
```

## 需人眼那一档的样例（合成，无渲染通道的机器上）

清单在最前，五段照旧；「版式门禁」那一段照抄门禁原话，模型只在末尾添一句人话。

```markdown
# 关于管理人印章备案的报告 第 1 版审查报告

须目验清单
- 最大行高：第 1 页第 1 张表第 2 行；推算 196.0～231.5 磅，阈值 200.0 磅；最坏越界 31.5 磅
确认前请在 WPS 或 Word 里打开看这几处。

## 生成依据

- 官方模板：模板/官方/1-2.关于管理人印章备案的报告.docx
- 出件环境：解释器 /var/folders/tmp/uv-python/cpython-3.12/bin/python3（python 3.12.7）；python-docx 1.2.0（与依赖清单钉的一致）

## 存疑点

- 无。

## 待律师裁定

- 无。

## 版式门禁

版式门禁：需人眼
不通过项：无
需人眼项：
- 最大行高测不准：推算 196.0～231.5 磅，阈值 200.0 磅
披露项：
- 空单元格：第 1 张表 第 2 行第 2 格
- 无渲染结果：页数、空白页、最大行高按版面推算给出区间（找不到 powershell.exe）
- 页数：推算 1 页

这台机器上没有渲染器，印模那一行的高度只能算出一个区间，而阈值正落在区间里：门禁测不准，不是测出事故。请按上面的清单在 WPS 或 Word 里看一眼那一格。

## 时限

无明示时限
```
