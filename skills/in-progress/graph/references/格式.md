# 图.json 与 图视图.json 的格式（格式版本 1）

引擎 `scripts/graph.py` 是这两份文件的唯一写者。`图.json` 存事实，`图视图.json` 与 `图视图.md` 是每次写图后覆盖重算的派生视图；状态、来源、前方、时限都是算出来的，不存进图（ADR-0003、ADR-0011、ADR-0016）。两份 JSON 共用一个整数 `格式版本`，同步升；引擎遇到不认识的版本明确拒绝。

## 图.json

顶层只有三个键，多一个即不合校验。

| 键 | 类型 | 含义 |
| --- | --- | --- |
| `格式版本` | 整数 | 现为 1 |
| `领域` | 字符串 | 领域图的名字（不是路径），如「破产」；空图无领域时可为空串 |
| `模块` | 数组 | 模块，数组顺序即顺序 |

模块：

| 键 | 类型 | 含义 |
| --- | --- | --- |
| `id` | 字符串 | 不透明 id，图内唯一（与节点 id 同一命名空间）；从领域图带入的沿用领域图 id，律师自加的由引擎生成（案件图上 `--id` 被拒，只有 `--kind domain` 收） |
| `标题` | 字符串 | 模块名，图内模块间唯一 |
| `节点` | 数组 | 节点，数组顺序即顺序 |

节点：

| 键 | 类型 | 含义 |
| --- | --- | --- |
| `id` | 字符串 | 不透明 id，图内唯一 |
| `标题` | 字符串 | 图内节点间唯一；也是 `文书/<节点标题>/` 的目录名 |
| `空白模板` | `"无"` 或对象 | 对象为 `{"来源": "官方" 或 "生成", "文件": "<文件名>"}`；官方件在领域目录或案件 `模板/官方/`，生成件在案件 `模板/生成/` |
| `条目` | 数组 | 只追加，顺序即时间序 |
| `时限` | 字符串 | 只有领域图节点可有；案件图节点带它即不合校验，带入时不拷贝 |

条目按 `动作` 分三种，`来源` 由动作推出：

| 动作 | 键 | 来源 |
| --- | --- | --- |
| `生成` | `动作`、`时间`、`来源`、`文书`、`审查报告`，可选 `源`（Markdown 源） | `agent`；律师自写的兜底件为 `律师` |
| `确认` | `动作`、`时间`、`来源`、`原话` | `律师` |
| `不适用` | `动作`、`时间`、`来源`、`原话` | `律师` |

`时间` 是引擎写入时刻的 ISO 8601 本地时间带时区偏移（如 `2026-09-05T21:03:11+08:00`），是拍板时刻，不是法律事件日。`文书`、`源`、`审查报告` 都是相对工作区根的正斜杠路径，绝对路径、反斜杠、`..` 都拒。

状态只算不存：无条目 = 未生成；末条生成 = 已生成；末条确认 = 已确认；末条不适用 = 不适用（终态）。合法序列：确认只能紧跟生成；不适用之后没有任何条目。模块状态三值：全部节点不适用 = 不适用；全部节点已确认或不适用且至少一个已确认 = 已完成；其余（含空模块）= 进行中。

模块级不适用（`not-applicable --module`）先把该模块在领域图里还没进图的节点全部带入，再给模块下每个节点（含律师自加的、已在图里的）各追加一条不适用；已是不适用的跳过；有一个已确认就整个拒。

  "领域": "菜园",
  "模块": [
    {
      "id": "m-bozhong",
      "标题": "播种",
      "节点": [
        {
          "id": "n-xiazhong",
          "标题": "下种",
          "空白模板": {"来源": "官方", "文件": "播种登记.docx"},
          "条目": [
            {"动作": "生成", "时间": "2026-09-05T21:03:11+08:00", "来源": "agent",

### 领域图

同格式、同引擎（`--kind domain`）：节点可多一个 `时限`，`条目` 恒为空数组，不出视图。一份领域一个目录，文件名 `领域图.json`；引擎 `--domain` 收目录或文件。合成样例在仓库 `evals/领域/菜园/领域图.json`。

```json
{"id": "n-difei", "标题": "施底肥", "空白模板": {"来源": "官方", "文件": "施肥记录.docx"},
 "时限": "自松土完成之日起 3 日内（手册，示例）", "条目": []}
```

## 图视图.json

与 `图视图.md` 同基名、同一条重算规则，放在 `图.json` 旁边。顶层：

| 键 | 含义 |
| --- | --- |
| `格式版本` | 与 `图.json` 同一个整数 |
| `领域` | 同 `图.json` |
| `生成时间` | 重算时刻，ISO 8601 |
| `源图` | `图.json` 的文件名（相对工作区根） |
| `模块` | 图里的模块，形状见下 |
| `前方` | 领域图里有、案件图里还没有的模块与节点；无领域图时为空数组 |

模块：`id`、`标题`、`来源`（`领域图` 或 `案件`，按 id 是否在领域图里算出）、`状态`（`不适用` / `已完成` / `进行中`）、`节点`。

节点：`id`、`标题`、`来源`、`空白模板`、`时限`（只在领域图里该 id 有时限句时出现，原样带出）、`状态`（`未生成` / `已生成` / `已确认` / `不适用`）、`文书版本`、`条目`（原样）。

文书版本由生成条目序列推出：`{"版本": n, "文书", "源"(可选), "审查报告", "时间", "来源"}`，第 n 条生成条目即第 n 版。

前方里的模块：`id`、`标题`、`来源: "领域图"`、`状态`、`节点`。`状态` 只有两个值，与图内模块状态是两套词：模块整个没进图时为 `尚未进图`，其 `节点` 是领域图里它的全部节点；模块已进图但还有节点没进图时为 `已进图`，`节点` 只列没进图的，该模块的真实状态看 `模块` 列表里同 id 的那条。前方节点：`id`、`标题`、`来源: "领域图"`、`空白模板`、`时限`（有则带）、`状态: "尚未进图"`。已进图的节点即使被移到别的模块，也不再出现在前方。

## 图视图.md

律师读的形态，与 JSON 同一次重算：标题行、每个模块一节（状态、来源），每个节点一行（状态、来源、空白模板、时限）加文书版本与条目原文（确认与不适用显示律师原话），末尾「前方」一节。形状随需要改，JSON 才是接口。

## 引擎的拒写

文件不合校验（多键、少键、id 或标题重复、条目序列不合法、案件图带时限、格式版本不认识、不是 JSON）即拒写并说明原因，文件一字不动；引擎不猜、不修。写入是临时文件加原子替换，单写者不设锁。
